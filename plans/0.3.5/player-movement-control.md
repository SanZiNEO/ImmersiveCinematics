# 玩家移动控制（Player Movement Control）：EVENT 关键帧驱动平滑直线移动

**版本**: 0.3.5
**类型**: 新功能（2026-08-13 讨论定稿）
**状态**: 📋 设计定稿，待实施
**关联**: 复用 EVENT 轨道（keyframe 驱动多点触发）；与相机体系平级（客户端模块）；服务端零改动

---

## 一句话定义

脚本播放期间**控制玩家实体从关键帧 A 平滑直线移动到关键帧 B**（多关键帧 = 折线），玩家真的在走（原版移动链路驱动 → 走路动画/脚步声音/服务端同步全自动），播完停在最后关键帧位置。放在 EVENT 轨道：EVENT 关键帧可选携带 position（x/z），有 position 的关键帧驱动玩家移动，无 position 的保持现状（纯命令触发）。

## 决策记录（2026-08-13 用户拍板）

| # | 决策 | 内容 |
|---|------|------|
| 1 | 形态 | **平滑直线移动**（A→B 直线，多关键帧 = 折线）；瞬移式 setPos 不做 |
| 2 | 动画 | 真移动（假输入走原版链路）→ 走路/跑步动画由原版速度驱动自动播放 |
| 3 | 不管怎么移动 | 地形起伏/碰撞/自动跳跃/被挡停住 = 原版物理照旧；**走不过去 = 作者改脚本** |
| 4 | 高度 | y 交给原版物理（重力贴地/台阶）——关键帧 position 只取 x/z，不控制 y |
| 5 | 速度 | = 段距离 ÷ 段时间（作者写多快走多快；过快动画自动变跑步）；**不做速度上限**（待确认） |
| 6 | 轨道 | 放 EVENT 轨道（复用，不新增轨道类型） |
| 7 | 不做 | 路线计算（A*）、曲线路径、障碍预检、跑步/跳跃动作指令（反馈多了再定） |

## 设计

### 脚本格式（EVENT 关键帧扩展）

```json
{
  "id": "walk_to_gate",
  "type": "EVENT",
  "clips": [
    {
      "start_time": 0, "duration": 3,
      "keyframes": [
        { "time": 0,   "position": { "x": 100, "z": 200 } },   // 移动起点
        { "time": 1.5, "command": "say 到中间了" },             // 纯命令（不移动）
        { "time": 3,   "position": { "x": 112, "z": 200 } }     // 移动终点
      ]
    }
  ]
}
```

- `position` 可选字段（x/z；y 忽略——贴地走）
- **有 position 的关键帧** = 玩家目标位置；**相邻两个有 position 的关键帧之间** = 玩家平滑直线移动
- **无 position 的关键帧** = 现状（命令触发），不受影响
- 纯命令关键帧夹在移动段之间 → 不打断移动（只触发命令）
- 脚本播完/停止 → 玩家停在最后关键帧位置（如果停止时正在移动中 → 停在当前位置）

### 移动语义

- 速度 = 段距离 ÷ 段时间（m/s）；加速/摩擦由原版物理处理（起步/停下自然）
- 玩家朝向 = 移动方向（转身走路）；转身由原版 yBodyRot 平滑
- 目标点不可达（墙/悬崖）→ 玩家停在被挡处，脚本照播（作者改脚本，文档标注）

### 实现要点

- **假输入驱动**：Mixin `LocalPlayer.serverAiStep`（@HEAD）——移动段激活时把"目标方向"换算为 `xxa/zza`（相对朝向的输入分量），走原版 `travel()` 完整链路：碰撞/动画/脚步声音/自动跳跃全自动
- 朝向：每 tick 设 `yRot/yRotO` = 移动方向（鼠标已被过场屏蔽，无冲突）
- 位置上报：原版 `sendPosition()` 自动（移动即上报）→ 服务端 `handleMovePlayer` 正常校验接收 → **服务端零改动**；其他玩家经 TrackedEntity 广播看到玩家走动
- 客户端控制器：从 EVENT 轨道提取"有 position 的关键帧序列"，按 globalTime 求当前移动段（与 CameraTrackPlayer 同模式）

## 已知限制

- 路径不可达（撞墙/悬崖走不过去）→ 停在被挡处，**作者改脚本**（文档/AI 指南标注）
- 路径含悬崖 → 玩家会掉下去（原版物理），可能摔落伤害——作者避开（暂不做摔落保护，待反馈）
- 水流/岩浆等危险地形 → 原版物理照旧，作者避开
- 移动会累计原版走路统计（副作用，无影响）

## 实施顺序

1. Schema：EVENT 关键帧加 `position`（x/z）字段 + 编辑器属性面板
2. 客户端 PlayerMoveController：关键帧段提取 + 移动段求值（与 CameraTrackPlayer 同模式）

4. 停止/暂停/打断的移动状态处理
5. 冒烟测试：A→B 直线移动（动画/速度/停点）、折线多段、纯命令关键帧兼容、被挡停住、脚本中断时玩家位置
