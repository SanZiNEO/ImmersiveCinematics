# 实体相对坐标系（Entity-Relative Frame）：动态 yaw 基准 + 实体中心位置

## 一句话定义

把相机的位置与朝向都放进**以实体为中心的相对坐标系**：位置相对实体（`follow=entity` 已有），朝向的"零值方向"相对实体视线（新增 `yaw_base`）——组合起来就是完整的前/后/左/右语义：想拍生物前面就 yaw=0，后面就 yaw=180，侧面就 ±90，位置用 dx/dy/dz 相对实体表达。

## 概念层次（从简到全）

| 层次 | 内容 | 现状 |
|---|---|---|
| L1 位置相对实体 | `follow=entity` + position dx/dy/dz（相对实体脚底） | ✅ 已有 |
| L2 朝向相对实体视线 | `yaw_base=entity`：yaw 0 = 实体视线方向 | 🆕 本方案 |
| L3 组合 | follow + yaw_base = 完整"实体空间"（第三人称跟拍/背后拍摄/视线同步） | 🆕 本方案 |
| L4 连线相对（可选/待定） | 以 A→B 连线为基准的位置 + 朝向（相对连线偏移） | ❓ 用户不确定，记录待定 |

**关键洞察**：L1 已经存在，L2 只是给 yaw 加基准，L3 是组合——**基于现有底子增量不大**（用户评估：都不是很难）。

## 痛点场景（用户例子）

1. **通过 A 的相对位置看 B**：相机放在 A 的旁边（position relative 已有），但朝向要"对着 B"——现在要么用 look_at（精确注视 B，但没法表达"从 A 的位置朝 B 的方向看"的偏移视角），要么手算世界角度（A/B 动一下就废）
2. **拍生物的前面 / 后面**：相机要始终在生物视线正前方（或正后方）。生物转头/移动时，世界 yaw 是不断变的——手算不可行；需要"以生物视线为 0 值，yaw=0 就是它面前，yaw=180 就是它背后"
3. **跟随拍摄时的相对视角**：生物沿路走，相机保持在它侧面 30°——基准随它的朝向实时更新，yaw 值恒定（30）就能保持相对关系

本质：**把"与世界坐标系的固定关系"变成"与场景对象的动态关系"**。

## 术语界定

- **yaw 基准（yaw reference / baseline）**：yaw=0 时相机朝向的方向。现状固定为世界正南
- 不是"相对坐标"（position 的相对是位置，这里是**朝向**的基准）
- 不是 look_at：look_at 是"精确指向一个点"；yaw 基准是"围绕一条动态方向线做偏移"（可以理解成 look_at 的"方向版"，保留自由偏移量）

## 现有相关机制

| 机制 | 现状 |
|---|---|
| `yaw` | 绝对世界角，0 = 南（KeyframeInterpolator 角度环绕插值） |
| `position_mode` relative | 位置相对玩家激活点（与朝向无关） |
| `follow` / `look_at` | 位置跟随/精确注视（实体每帧求值，动态） |
| pitch/roll | 用户明确"pitch 不管"——只动 yaw |

## 设计草案

### 关键帧新增字段

```json
{
  "time": 0,
  "position": { "dx": 5, "dy": 2, "dz": 0 },
  "position_mode": "relative",
  "yaw_base": "entity",              // 基准类型
  "yaw_base_selector": "@e[type=minecraft:sheep,limit=1]",  // 实体基准：其视线方向 = 0
  "yaw": 0,                          // 相对基准的偏移：0 = 正对实体视线，180 = 正背后
  "pitch": -5
}
```

基准类型候选：
- `"world"`（默认，0 = 南，现状）
- `"entity"` + selector：0 = 该实体视线水平方向（`getYRot()`）
- `"line"` + from/to selector：0 = 从 A 到 B 的连线水平方向（A/B 可以是实体或坐标）

### 求值

```
每帧：
  baseYaw = 按 yaw_base 求动态基准方向（实体视线 / 两点连线 / 0=世界南）
  finalYaw = baseYaw + 关键帧插值的 yaw（偏移量）
  pitch/roll 照旧
```

关键帧 yaw 值成为**相对基准的偏移量**，插值语义不变（偏移量之间的插值）。

## 复杂度与难点（诚实标注）

1. **基准动态变化**：实体转头/移动 → baseYaw 每帧变 → 相机自动跟随保持相对关系（这是目标）；但**基准突变**（实体瞬移/换目标）会导致镜头猛转——需要过渡处理
2. **插值与过渡**：两端关键帧 yaw_base 不同（world → entity）时，偏移量插值没问题，但基准本身是"跳变"还是"插值"要定义（倾向：基准按实体动态求值，偏移量插值；基准切换=镜头自然跟随，无额外插值）
3. **与 look_at 的关系**：look_at 会覆盖 yaw/pitch——yaw_base 只在非 look_at（none）时生效，两者互斥（写了 look_at 时 yaw_base 忽略，或校验提示）
4. **视线方向定义**：实体 `getYRot()` 即水平视线角（MC 朝向约定），"生物前面" = yaw_base=entity + yaw=0，无需额外视线检查——视线检查只是"判断前后"的辅助，基准本身已覆盖
5. **端点动态**：line 基准的 A/B 每帧移动 → 连线方向每帧变 → 相机保持"A 侧看 B"的相对关系（自动）

## 组合场景（L3 直接覆盖）

1. **第三人称跟拍**：`follow=@p` + `yaw_base=entity(@p)` + yaw=180（玩家背后）→ 玩家走哪镜头跟哪，朝向永远同步玩家视线
2. **生物背后拍摄**：`follow=sheep` + yaw_base=sheep 视线 + yaw=180 → 生物转身镜头自动绕到它背后
3. **固定朝向的背景跟拍**：位置相对实体、朝向相对实体——镜头保持相对关系移动（"固定朝向"是相对实体的，不是相对世界）
4. **拍生物前面**：yaw=0（正对视线）——无需额外视线检查，getYRot() 就是视线水平角

## 基准范围（用户拍板）

- **yaw**：可相对（实体视线 / 连线）——水平方向有"前/后/左/右"语义，相对化有意义
- **pitch**：**保持世界基准不变**——俯仰是垂直方向，没有"前/后"相对语义，相对化无意义
- **roll**：**不引入相对**——roll 是本模组自加的属性，语义固定为**屏幕顺时针环绕**（绕相机视线轴旋转，与 yaw/pitch 朝向完全解耦：任何朝向下 roll>0 都是画面向右倒）。未来 yaw 引入相对体系也不影响 roll——它只负责"屏幕旋转"这一件事，不参与 yaw 基准体系；后续若有特殊变化（如与朝向联动的特殊 roll）单独设计

## 边界与待定

1. line 基准（L4）的 from/to 是否支持坐标（look_at_target 式）+ 实体混用；位置是否也相对连线（用户不确定，先记录）
2. roll 是否也需要类似基准（roll 现状绕视线轴，暂不涉及）
3. 与 morph 转场的交互（两端基准不同的 morph 混合）
4. 基准实体不存在 → 该端无基准 → 按空片段处理（沿用现有原则）
5. 基准突变过渡：实体转头瞬间镜头跟转的平滑度（是否要插值缓冲）
