## 0. E0 口径重审（2026-10-10）：模板机制归编辑器（已确认）

> **裁决依据（只读引用）**：`implementation-progress.md`「通用原则」——「**运行时只读只执行**（2026-10-08 用户裁决）」：三层分工 = **定义**（运行时只写机制 / 模型）→ **调配**（编辑器做创作与运算）→ **应用**（运行时解释器读脚本数据、执行调配结果）；「**修改 / 生成 / 调配运算一律在编辑器侧**」；运行时职责固定五项（**解析 / 播放 / 触发 / 调度 / 网络交换**），实时动态例外仅呼吸扰动 / look_at·follow 跟踪 / 选择器切换平滑。同节「越界处置」段已点名：**`script/template/ClipTemplate`（片段模板展开）与 `script/ScriptTemplate`（脚本骨架生成）→ 归编辑器（随 E 批次重审）**；「创作机制口径」行同款（E 批次任务书开工前按此口径重审，模板展开归编辑器）。
>
> **结论一句话**：模板 = **编辑器侧的创作工具**（参数 → 标准脚本 JSON 的生成器）；运行时**零模板语义**——只解析 / 校验 / 播放模板的**产物**（标准脚本）。§1 落地记录中的运行时实现（`script/template/` 10 文件 + `/icinematics template` 命令 + `ScriptTemplate` 骨架）属越界实现，随 E 批执行类任务删除；模板能力与 E1–E4 整体移入**编辑器阶段**（§6）。
>
> 本文引用的代码行号取自 2026-10-10 工作区（会漂移，定位以类名 / 方法名为准）。

### 0.1 五题结论

**① 运行时保留什么 —— 模板语义保留零。**

- 运行时播放消费的是**脚本**：把 `script/template/` 整包删除后，任何脚本的解析 / 校验 / 播放行为不变（模板不是播放期依赖）。
- 「模板数据解析 / 校验」不属运行时「解析」职责——该职责的宾语是**脚本 / schema / 关键帧**（`implementation-progress.md` 运行时职责段原文列举：`ScriptParser`、`ScriptValidator`、`schema/`）。模板定义是创作资产，不是播放数据。
- 「纯数据应用」若指「参数 → 片段 / 轨道 / 脚本 JSON」= **展开 / 生成** → 编辑器「调配」；运行时的「应用」= 解释器执行调配**结果**（`ScriptPlayer` 读脚本）。
- 运行时侧保留的只是两条既有能力（与模板无关）：① 对**产物**的解析 / 校验 / 播放；② 文件搬运（`webui/` 网络交换——编辑器经 `script.save` 落盘、经 `script.validate` 校验）。两者都不含模板语义。

**② `/icinematics template` 命令去留 —— 删（运行时侧不保留）。**

- 依据：命令语义 = `TemplateArgs.parse` → `TemplateScriptAssembler.assembleJson` → 写 `scripts/generated/<name>.json` → 当场校验（`CinematicCommand.java:310-405`），即被点名的「运行时生成脚本」越界形态；「运行时只读只执行」的唯一例外是实时动态（呼吸 / look_at·follow / 选择器平滑），不含生成。
- 删除面：`CinematicCommand` 的 template 子树（注册 `:107-115`、handler `:275-405`、import `:11-15`、补全 `:70-71`）+ `script/template/` 整包（10 文件）。
- **产物不失效**：已生成的 `scripts/generated/*.json` 是标准脚本，照常 `validate` / `play`（`generated:` 命令 ID 映射保留）。
- 过渡期保留属**越界豁免**，需用户拍板（§0.3-1）；倾向仍为删。
- 第三选项「改为编辑器产物导入」**不成立**：编辑器产物 = 标准脚本，运行时侧已有既有通道（`script.save` / 脚本目录加载 + `/icinematics play`），不需要专门入口；再加一个"导入"命令 = 又一个运行时生成 / 改写路径（`util/ScriptStructureResolver` 已因同类原因被判改）。

**③ `ClipTemplate` / `ScriptTemplate` 迁移路径 —— 都迁编辑器，运行时零保留。**

- `script/template/*`（`ClipTemplate` / `TemplateParam` / `TemplateArgs` / `TemplateRegistry` / `TemplateScriptAssembler` / `TemplateJson` + 4 实现）→ 编辑器侧模板引擎的**参考实现**；4 个模板（`fade` / `static_breath` / `dolly` / `orbit_arc`）逐个平移，参数表与算法口径以本文件 §1 落地记录为准（**文档即规格**，不依赖 Java 代码存活）。
- `script/ScriptTemplate`（骨架生成）→ 编辑器侧「新建脚本」：编辑器用 `schema.get` 自行构造——`SchemaExporter.exportAll()` 已导出 meta / clip / keyframe / trigger 字段的 `type` / `default` / `enumValues` / `section`（`SchemaExporter.exportField`），编辑器已缓存 `state.schema`（`editor/src/store.ts` 的 `getSchema()`）且已有 `fillMetaDefaults` / `fillDefaults`（`editor/src/schema.ts`）；`script.new` 消息与 `ScriptFileService.newScriptJson()` 随之去掉（编辑器构造 → `script.save`）。轨道 id 沿用 `docs/SCRIPT_FORMAT.md` §3 约定（`{type小写}_{n}`）、`total_duration` 缺省 10（原 `ScriptTemplate.DEFAULT_TOTAL_DURATION`，编辑器侧定死）。
- 运行时留什么：`script/schema/`（字段权威）、`ScriptParser` / `ScriptValidator`、`script.list/load/save/delete/validate` 协议——零生成。

## 1. 定位（已确认）

**模板 = 参数化生成器**：用户填目标需求（"围绕 X 转一圈看向它"），模板内部展开成标准脚本 JSON——用户不需要懂曲线 / 关键帧 / 轨道的具体写法。

**现状（0.3.5 的预设系统已随编辑器退役删除）**：

| 现状 | 说明 |
|---|---|
| 代码 | ~~`editor/preset/`：`Preset`（接口）、`PresetParam`（参数声明 record）、`PresetRegistry`（注册表）、`OrbitCirclePreset`（环绕轨道）~~ ——**已删除**（0.3.6 游戏内编辑器退役，见[编辑器 WebUI 迁移](./editor-webui-migration.md) §4）；模板体系**从零新建** |
| 内置库 | 0 个（原唯一预设"环绕轨道"随之删除：三段三阶贝塞尔拼圆，控制点距离 = `R × 4/3 × tan(θ/4)` ≈ 0.7698R——算法留档在 `plans/complete/0.3.5/presets.md` 与 git 历史） |
| 形态 | 原形态：**扁平、一次性**（生成函数直接产出整份脚本 / 整个 clip，参数 schema 与 `script/schema` 的 `FieldDef` 是两套）；新体系按 §2 三层模型重建 |
| 原则（0.3.5 已定，沿用） | 生成结果 = 标准脚本 JSON，走 `ScriptParser` / `ScriptValidator` 校验，与手写脚本完全等价、可继续编辑（不是黑盒）；初版只做内置模板（生成逻辑在 Java 代码，非纯数据）——**E0 后：生成逻辑落编辑器侧（TS），运行时不再有模板生成**（§0） |

**目标（已确认·2026-10-07）**：从"一个贝塞尔预设"发展为**脚本-轨道-片段 三层模板体系**——复杂效果 = 分层模板的组合，用户只需要填几个目标参数。

**归属（E0 重审·2026-10-10）**：三层模板全部归**编辑器侧**（"参数 → JSON"的展开 = 创作运算）；运行时只解析 / 校验 / 播放产物，零模板语义。见 §0。

### 落地记录（2026-10-07 · 第一版 = 步骤 1-2）

代码：`common/src/main/java/.../script/template/`。

- **参数声明与 schema 合并（步骤 1）**：模板参数 = `TemplateParam`（key + 显示名 + **复用 `script/schema` 的 `FieldDef`**），不是第二套 `PresetParam`——类型 / 默认值 / 枚举候选 / `section` 分组全部走 FieldDef，将来直接吃 `schema.get` 驱动的表单。
- **展开器（步骤 1）**：`ClipTemplate.expand(TemplateArgs) → clip JSON`（Java 函数）；`TemplateArgs` 按声明归一实参并兜默认值（展开器不用自己判空）；`TemplateRegistry` = 注册表（当前即内置库，id 空间为片段级）。
- **嵌套引用**：本版**未实现**——片段级是三层的最底层，没有可引用的下层；`id` 引用留给步骤 3（轨道级引用片段级）落地时定（倾向：轨道模板按 id 引用片段模板并逐层传参）。
- **产物与校验**：`TemplateScriptAssembler` 把展开出的 clip 装进 `ScriptTemplate` 骨架 → 标准脚本 JSON，走 `ScriptValidator`。冒烟：4 个模板 × 默认 / 非默认参数共 13 组展开 → 装配 → 校验，问题数 0；环绕弧线另做几何核对（贝塞尔采样点相对圆的半径误差 < 0.2%，θ=120°）。
- **接入点**：`/icinematics template list` 与 `/icinematics template <id> [key=value ...]`——后者展开 → 写 `scripts/generated/<name>.json` → 当场 `ScriptValidator` 校验（不过则不落盘）。**选命令而非 WebUI**：纯 common 侧、与既有 `/icinematics validate` 同一条"生成→自查→播放"闭环、无需改 TS 前端。（**E0 后作废**：该接入点本身即"运行时生成脚本"，属越界，见本节末重审标注与 §0。）

**第一批片段模板（4 个）**：`fade`（黑场/白场，OVERLAY 轨）、`static_breath`（固定 + 呼吸）、`dolly`（推近/拉远）、`orbit_arc`（环绕弧线，单段 ≤120°）。
取舍：**希区柯克不单列模板**（= `dolly` 的两个 fov 两端不同，同一条位置路径）；**"环绕整圈"不做片段模板**（三段 120° 拼圆 = 轨道级，属步骤 3）——`orbit_arc` 只负责其中一段，超限直接拒绝并提示。

> **E0 重审（2026-10-10）**：以上是**运行时越界实现**（`implementation-progress.md` 越界处置点名 `script/template/ClipTemplate` 与 `script/ScriptTemplate`）。本记录从此只作两用：① 编辑器侧模板引擎的**规格**（4 个模板的参数表 / 展开口径 / 数学；「文档即规格」）；② **删除范围清单**。代码、`/icinematics template` 命令与 `ScriptTemplate` 骨架随 E 批执行类任务删除，见 §0 / §6。

## 2. 三层模板模型（已确认方向）

**归属（E0 重审·2026-10-10）**：三层模型 = **编辑器侧的创作分层**（生成整份脚本 / 一条轨道 / 一段镜头）；运行时不分层、不认模板——只认最终的标准脚本。见 §0。

```text
脚本级模板（Script Template）
  ├─ 生成整份脚本骨架：meta（含循环 / 可跳过 / 听者等默认值）+ 触发器 + requires
  ├─ 引用 轨道级模板 × N（每条轨道一个）
  └─ 可带默认转场（黑场 / 叠化 …，引用 scene-transition.md）
       ↓
轨道级模板（Track Template）
  ├─ 生成一条轨道的 clips 编排（如"环绕整圈 = 三个 120° 片段"、"A→B 双机位切轨"）
  └─ 引用 片段级模板 × N
       ↓
片段级模板（Clip Template）
```

## 3. 模板的模型（先定义工具，再谈调用）

与用户原则一致（先定义工具 → 再考虑调用 / 整合）：本文先定义"模板是什么"，编辑器面板 / 命令 / 插入点都是后续调用方。

**归属（E0 重审·2026-10-10）**：本节定义的工具（参数声明 / 展开规则 / 嵌套引用 / 产物）全部落在**编辑器侧**；运行时不实现、不消费模板定义——「调用方」只剩编辑器面板（运行时命令已删，见 §0.1-②）。

**模板 = 参数声明 + 展开规则 + 可嵌套引用（方向）**：

1. **参数声明**：与 `script/schema` 同源（`FieldDef` **同形声明**，编辑器侧）——沿用同一形状后，模板参数天然吃 schema 驱动的表单（`editor-webui-migration.md` 的 `schema.get` 链路；运行时 schema 不涉及模板参数）。参数类型覆盖位置 / 选择器 / 数值 / 枚举等（脚本模型 §4 的"参数声明"是同一条底层线）。
2. **展开规则**：编辑器注册的生成函数（TS；输入参数对象 → 输出对应层的 JSON 片段）；生成用的数学（贝塞尔拼圆、轨迹采样）在**编辑器侧实现**——运行时的 `BezierCurve` / `MathUtil` / `BezierPathStrategy` / `ArcLengthLUT` 只服务播放期求值，编辑器不跨语言复用；两侧口径以本文 + 产物过 `script.validate` 对拍为准。
3. **可嵌套引用**：脚本模板引用轨道模板、轨道模板引用片段模板（`id` 引用）；引用时逐层传参。
4. **产物**：标准脚本 JSON，走 `ScriptParser` / `ScriptValidator`——与手写等价、可编辑（沿用 0.3.5 原则）。

**模板是"调用方"，不是底层**：它调用的底层是轨迹数学、关键帧体系、schema 参数声明、坐标源 / 选择器（基准）、转场（脚本级模板默认转场）。这些底层成熟后，模板只是"组合"。**新增一个底层能力（如新曲线类型、新坐标源），模板自动受益。**

## 4. 可能的问题

> **E0 后（2026-10-10）**：本节问题的归属侧统一为**编辑器**（模板不再进运行时）；其中「依赖 math-models」的一条已解除，见 §0.1-④。

- 模板参数与运行时基准（相对坐标 / 选择器 / 触发点）的关系：模板生成的脚本引用实体 / 触发点，运行时解析——与坐标源、选择器的现状差距（selector-model / coordinate-frame 的已确认方向）联动。
- 三层之间传参的形态（参数继承 / 覆盖 / 命名空间）。
- 自定义模板：初版内置（生成逻辑是代码）；"纯数据模板"= 编辑器资产 JSON + 编辑器解释器（E4，§0.1-④）——**不再以 math-models 的 JSON 模型化为前置**（编辑器侧运算自足；仅当模板要产出运行期动态模型引用时，才单向依赖 B16 的脚本字段形态）。
- 生成结果的可编辑性：沿用"生成普通脚本"（作者改完不再与模板关联，或保留模板来源标记用于再生成——待定；落盘口径见 §0.3-2）。
- 模板版本化：模板升级后，已生成的脚本是否受牵连（倾向：生成即脱离，模板升级只影响新生成）。
- 编辑器呈现：模板面板 = schema 表单 + 实时预览（帧推流已有）+ 插入位置（当前时间点 / 新脚本）——归编辑器阶段（§6 步骤 6）。

## 7. G5 归置：叠化 hold 自动补帧 = 编辑器工具（已确认·2026-10-10）

**结论**：G5 归**编辑器侧工具**（叠化向导 / 转场面板），**不属三层模板、不属运行时**。

- **判据**：模板 = 参数 → JSON 生成器（§1）；叠化 hold 补帧的操作对象是**已选中的两个 clip**（clip A 末尾帧复制延长 + clip B 首帧复制延长，交叉窗口内 opacity 关键帧 1→0 / 0→1）——这是对既有时间轴内容的**编辑操作**（与 razor / 剪切同类），不是"填参生成新片段"。
- **生成规则**（编辑器侧共享实现，转场面板与模板引擎共用）：复制延长 = **插等值关键帧 + 窗口调整**——延长区取末 / 首关键帧值（画面冻结），透明度只改在延长区里；不新增字段、不新增机制（`script-model.md` §1.1、§4-7；`scene-transition.md` §3.2）。
- **运行时零改动**：等值关键帧之间线性插值天然成立（冻结），重叠区双 lane 由多相机渲染既有能力支持（`scene-transition.md` §3.2「唯一机制性支持 = 多相机渲染本身」）；不新增转场轨 / 转场字段 / 转场代码，validator 不新增规则。
- **落点**：编辑器阶段「转场面板」（`implementation-progress.md` 末段清单已列），与 §6 步骤 7 对应。
