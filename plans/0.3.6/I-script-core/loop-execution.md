# 片段循环：按次数执行

> 状态：未实现
> 范围：片段循环的执行次数、每次执行身份/局部时间、展开窗口、自然完成、pingpong、状态策略、宏观循环边界
> 关联：`object-model.md`、`runtime-evaluation.md`、`track-camera.md`、`track-overlay-letterbox.md`、`track-audio-adjust.md`、`track-event.md`、`rule-system.md`（本轮规则方向）、`../C-trigger/condition-system.md`（C 轮 v1 旧实现参考）

## 一、摘要

片段循环是片段级的执行次数，不是把全局时间取模折回。片段以自身起点为局部原点，以持续时间展开局部轴；每次执行有独立身份和局部采样位置，关键帧保持明确顺序。是否进入下一次执行由本次内容执行完成、相关等待／依赖解除和剩余次数决定。可推导的 `start + duration × N` 只作显示／定位参考，不是结束判据；普通非阻塞观察不计作剩余内容，随实例自然结束回收。规则时间门、实例级挂起、事实接力与延迟动作由 `rule-system.md` 定义；循环只提供执行身份与局部位置。

## 二、为什么做

### 2.1 问题

- 当前 `KeyframeInterpolator.computeInterpolation` 仍用 `%`/镜像折叠片段局部时间；这是实现层的旧口径，不是“按次数执行”的语义。
- 周期 = 末关键帧时间 − 首关键帧时间（`getAnimPeriod`），不是 `duration`；有限窗口 = `start + animPeriod × loop_count`。如果关键帧没有铺满 `duration`，窗口和视觉都对不上。
- `ScriptPlayer` 的 `lapsBefore`/`clipConsumedAt` 也基于 `animPeriod`；执行事实和窗口可能不一致。
- `Validator` 强制 `duration` 与关键帧周期匹配，掩盖了周期/时长混淆。
- 当前 `Clip.getWindowEnd()` 对无限片段返回 `Float.MAX_VALUE`，`ScriptPlayer.contentEnd()` 对无限内容返回 `NaN`；文档又把 `contentEnd` 写成“有限值/有限部分末端”，同一概念有多套值，容易被当成完成判据。
- `ScriptValidator` 仍把“无限片段后仍有片段”判为禁播，把作者编排的可达性变成框架禁播规则。
- 用时钟除法推导圈数会混淆采样位置与控制事实，无法正确处理等待、分支、跳转及按每次执行激活的规则。

### 2.2 目标

- `loop_count` 是执行次数，不是时间周期；播放控制按次数调度，每次执行有独立身份。
- 每次执行只暴露 `executionId` + `executionIndex` + `executionLocalTime`；对象采样器只认这次执行的局部时间。
- 只有声明了 `loop` 的片段重复；非循环片段仍按自己的定义执行一次，不被别的片段循环改变。
- 内容自然完成由实际执行路径上的剩余执行、明确持有执行的等待及在跑分支判定；普通非阻塞观察不计入剩余内容，窗口与时长估计不参与判完成。
- 无限执行只表示没有自然完成点：不禁止同轨后续片段、不把全局时钟停住、不自动截断，也不因“无限片段后仍有片段”报 validator 错误；后续可达性按作者编排的顺序依赖/并行/退出决定。
- 规则在脚本级集合声明，绑定通过片段引用定位片段与某次执行的局部时间；时间条件是必选外层执行资格门，局部位置 `>=` 指定时间后开始／继续判定，之后成立也执行；每次执行独立判定；门前有效事件事实可采集、动作门后提交；激活后的观察／等待不截在片段活跃窗。
- 规则到门后可挂起整个实例等待判定，成功事实可接力，动作可延迟；已承诺但未释放的动作参与自然完成，但不冻结内容推进。
- 删除 `getAnimPeriod()`、`%` 折叠、`LaneMask.effectiveTime`、有限循环末端钳到末两帧的逻辑。
- 状态策略：执行边界不重置 motion/breath/selector/音频实例；玩家移动目标索引是既有复位点；服务端 EVENT 去重不变。
- 宏观循环保持现有语义：`macro_loop_count` 是圈数，`[a,b]` 是区间；宏观循环只作用于客户端表现层。

### 2.3 非目标

- 不改变宏观循环的 `macro_loop_count`/`macro_loop_mode` 语义；`pingpong` 宏观循环仍未实现（按 repeat 播放，validator 告警）。
- 不改变暂停/挂起/退出模型；`pause` 仍保持内容位置，EVENT 随实例冻结。
- 不改变 `hold_at_end` 的驻留行为本身；驻留点由自然完成给出（有限内容）；无限内容没有自然完成点，不驻留、也不 clamp 到某个数。
- 不做编辑器循环展开/折叠；预览按真实时间线播放。
- 不新增“每 lap 全状态重置”的通用机制；状态策略见 §3.5，改动需单独设计。
- 不改变 EVENT 既有去重；不把规则观察生命周期截在片段活跃窗；不把规则时间条件并入循环次数或全局时长。
- 过渡两侧的状态所有权与装配顺序由 `track-camera.md` 定义；循环控制只提供执行上下文与局部位置。

## 三、方案

### 3.1 字段与执行次数

| 字段 | 位置 | 类型 | 默认 | 语义 |
|---|---|---|---|---|
| `loop` | clip | bool | false | 是否按次数重复执行这个片段 |
| `loop_count` | clip | int | -1 | 执行次数：`-1` = 无限次；正整数 N = 执行 N 次；`0` 非法 |
| `loop_mode` | clip | enum | repeat | 每次执行内的遍历方式：`repeat` = 正向 0→duration；`pingpong` = 正向/反向交替 |

- `loop=false`：只执行 1 次；`loop_count` 写了也忽略（validator 可警告“写了但无效”）。
- `loop=true`、`loop_count=N>0`：执行 N 次；第 N 次结束后片段执行完。
- `loop=true`、`loop_count=-1`：无限次；该片段没有自然完成点，也不产生有限的展开末端（用派生标志表达，不是数值哨兵）。
- `loop_count=0`：非法；validator 报错（运行时按 1 处理只作为防御）。
- `loop`/`loop_count`/`loop_mode` 从「仅 CAMERA 声明」提升为**所有轨道共用的 clip 字段**；AUDIO 的文件循环改名 `file_loop`，不再与执行 `loop` 冲突。这是 schema/格式变更，旧脚本由迁移器处理。

### 3.2 执行状态

播放控制层对每个循环片段维护**执行记录**：

```text
executionId          // 本次执行的身份；播放实例内唯一，不因局部时间回退/seek 复用
executionIndex       // 当前是第几次执行，0 起
executionLocalTime   // 当前这次执行的局部时间，0..duration
executionsRemaining  // 剩余执行次数；无限 = 无上限
done                 // 当前片段是否已执行完
```

- 开始本次执行时确定遍历方向和起点，分配执行身份：正向从局部 0 开始，反向从局部 duration 开始。
- 本次内容报告执行完成、关联的明确等待／执行依赖解除后，产生执行边界事件；仍有次数则建立下一次执行，否则标记该片段已消费完。
- 局部采样到达路径末端是内容求值事件之一，不意味着可跳过等待／分支直接判完成；暂停和分支期间按实际运行态保持或重建位置。
- **执行次数、执行边界事件、完成状态是控制事实，来自执行记录**；`executionLocalTime` 是采样与作者定位坐标，不反过来定义执行了几次。执行身份由执行记录分配；不能用局部时间回退来推断执行边界或复用身份。
- `windowEnd = start + duration × N`（N 有限）是展开后的活跃跨度，仅用于显示、定位和活跃候选；它不驱动执行，也不作为完成判据。无限次 → 没有有限展开末端（用派生标志表达，不用 `∞`/`MAX`/`NaN` 数值哨兵）。
- 非循环片段只有 `executionIndex=0` 一次执行；它的 `start_time`/`duration`/`loop` 定义不被其他片段的循环改变。
- 时间轴上的片段顺序/重叠仍按 lane 模型处理；循环只扩展该片段自己的执行跨度，不是把整个时间轴取模。
- 纯采样轨道只消费执行记录给出的局部位置；可在该次执行内部算术换算进度／方向，但不能从全局时钟另算一套圈数或局部位置，绕过等待、分支与执行记录。

### 3.3 每次执行的局部时间

- 每次执行有独立身份，规则绑定的运行态与客户端执行状态据此区分“哪一次”；服务端 EVENT 的去重不因此加入执行序号，仍保持自身契约。
- `executionLocalTime` 始终在 `[0, duration]`；对象关键帧在这条轴上采样。
- `repeat`：每次执行 0→duration。
- `pingpong`：第 0 次正向 0→duration，第 1 次反向 duration→0，第 2 次正向……；`executionLocalTime` 仍在该次执行的 `[0,duration]` 内，方向由执行序号决定。
- `loop_count=N` 是总执行次数（正向/反向各算一次）；`N=1` 时 pingpong 没有反向，validator 警告。
- `pingpong` 只允许视觉轨道（CAMERA/OVERLAY/ADJUST/LETTERBOX）；AUDIO/EVENT/MOD_EVENT 拒绝（音频/事件没有反向语义）。
- `duration=0`：瞬间片段；只允许 EVENT/瞬时动作；视觉/音频片段 validator 警告或拒绝。
- `duration<0`：旧无限时长哨兵，不是循环；它只表示没有有限展开末端（用标志表达，不用 `∞`/`MAX`），片段只执行一次且时间持续增长；`loop`/`loop_count` 与负 duration 同时出现时 validator 报错。该哨兵没有 fixture 使用，后续可单独清理。

### 3.4 展开窗口、内容末端与自然完成

```text
windowEnd = isEffectivelyInfinite()
  ? 无有限值（用 infinite 标志表达）
  : start + duration * (loop ? loopCount : 1)
```

- `Clip.getWindowEnd()` 只在有限时返回值，不再用 `getAnimPeriod()`，也不返回 `Float.MAX_VALUE`。
- `Clip.isEffectivelyInfinite()` = `duration < 0 || (loop && loop_count < 0)`；它只表示“没有自然完成点”，不表示“后续片段不可播放”。
- `contentEnd` 仅在编排能静态给出有限末端时提供估计；片段或宏观无限重复均不能伪造有限自然末端。有限部分显示范围单独派生；两者都不作为实际路径完成判据。
- `finiteDisplayEnd`：有限片段窗口末端的最大值，单独派生，只服务编辑器缩放/seek/图显示的“有限部分范围”；它不声称内容会在此结束，也不用于 hold/goto 上界。具体数值口径待定，不把显示范围塞进完成语义。
- **自然完成**由实际执行路径无剩余内容、明确持有执行的等待、在跑分支及已承诺未释放的规则动作调度给出；普通非阻塞观察不阻止自然完成，随实例回收；待执行动作参与完成但不冻结内容推进。不由任何窗口数值比较决定，也不因静态声明含无限内容就忽略作者分支／退出路径。
- **无限执行没有自然完成点**：这不代表全局时间停住，也不代表同轨后续片段被禁止或不可达。后续片段是否执行、何时执行，由作者安排的顺序依赖/并行/退出决定；框架不智能补偿、不自动截断、不因无限片段报 validator 错误。
- 展开窗口可索引候选片段，但运行态中仍活跃的内容必须继续被调度；预测窗口结束不能从候选集合中抹掉尚未完成的执行。
- 最后一轮结束由执行完成事件确认，实际最终状态供 hold／transition 使用；派生窗口不负责触发它。
- 非循环片段的窗口仍是 `start + duration`；循环片段只改变自己的窗口。

### 3.5 状态策略

循环边界（一次执行结束、下一次执行开始）是**执行事件**，不是时间回绕；它不自动重置所有状态。既有实现口径与 I 轮补充如下：

| 状态 | 执行边界行为 | 说明 |
|---|---|---|
| 关键帧值/对象采样 | 每次执行用新的 `executionLocalTime` 重新求值 | 纯函数，天然重复 |
| 相机 motion（`motion_*`） | 同片段的连续执行不一律重置 | 状态按自己的执行推进；不同片段各侧状态归属见相机专篇，过渡不得重复推进 |
| 相机 breath（`cam_breath_*`） | **继续**，不重置 | 它是 `globalTime` 的确定性函数，没有“执行圈”概念 |
| 选择器锁/点源冻结 | **继续**；seek 会清点源冻结 | 没有统一的执行边界重置路径 |
| 相机 transition | 执行边界不隐式创建片段间过渡；两侧效果归各自执行状态 | 循环提供上下文和局部位置，状态装配按 `track-camera.md`，过渡只消费快照 |
| OVERLAY / LETTERBOX | 每次执行按局部位置求值；图层存续由实际调度状态和显式控制决定 | 派生窗口不能替代结束事件，不额外重置仍活跃资源 |
| AUDIO 实例 | 跨执行边界**仍然活跃的实例不重启**；不再活跃的，下次执行重新起实例 | 与现有实现一致 |
| EVENT | 服务端不参与客户端循环；事件按自己的时间线触发一次，不按执行次数重复；既有去重不变 | 与现有设计一致 |
| 规则时间入口 | 脚本级规则集合的绑定引用本片段及局部时间；每次执行独立判定时间门，运行态按绑定与执行隔离 | 绑定归脚本级集合，激活归播放实例；时间条件是必选执行资格门，局部位置 `>=` 指定时间后开始／继续判定；到门可挂起整个实例等待判定；关键帧只提供时间点；门前事实可采集、动作门后提交；普通观察不阻止自然完成，待执行动作参与完成但不冻结内容推进 |
| 玩家移动目标索引 | 执行边界**复位** | 现有 `PlayerMoveController.onScriptLoop`；这是执行边界上的既有复位点，不是规则激活机制 |
| 宏观循环 | 区间内容再次执行，播放实例身份不变；片段的新执行获得新身份 | 不因区间重复自动重建实例；玩家移动复位，服务端 EVENT 去重不变 |

- 规则时间入口不是玩家移动复位的替代：玩家移动复位是既有实现细节；规则需要的是绑定在每次执行中的独立时间门与运行态、门前采集与门后动作提交的分离，以及激活后实例内的等待／观察状态。
- 判定成功后已承诺但未释放的规则动作是明确执行依赖：参与自然完成，不因主线采样结束被静默丢弃，也不要求冻结内容推进；显式退出／停播按实例终止回收。
- 规则成功事实与延迟动作属于规则运行态，不改变循环执行身份，也不把规则成功当片段完成。
- 执行重复、资源重建与副作用重放是不同契约：AUDIO 参数可逐次采样，仍活跃的音源不因此重建；服务端 EVENT 不重放。需要按执行重复命令时可由规则绑定的动作表达，不改变 EVENT 去重身份。
- 如果作者希望 motion/breath 每次执行重置，当前不支持；它们会连续。需要确定性的每执行一致运动时，用多个片段/显式关键帧。

### 3.6 宏观循环

- `meta.macro_loop`、`macro_loop_count`、`macro_loop_mode`、`timeline.loop_start`/`loop_end` 保持现有语义；宏观循环是脚本级“整段/子区间重复执行 N 次”。
- 宏观圈边界同样是**执行事件**（区间重复执行），不是全局时间取模；局部时间只用于采样与作者定位。
- 宏观循环只作用于客户端表现层；服务端 EVENT 不重复。
- 玩家移动目标索引按圈复位（现有口径）。
- 无限宏观循环没有自然完成点，但不把全局时钟停住；结束仍走跳过/打断/规则退出。
- `macro_loop_mode=pingpong` 仍未实现，按 repeat 播放并告警。
- 编辑器预览不做循环展开；按真实时间线播放。

### 3.7 校验

- `loop_count >= -1`；`0` 报错。
- `loop=true` 时 `loop_count` 缺省 = -1；`loop=false` 时 `loop_count` 写了告警。
- `loop_mode=pingpong`：仅视觉轨道；`loop=false` 或 `loop_count=1` 告警“无效果”。
- 删除“duration 与关键帧周期不匹配”的校验；关键帧超出 duration 按对象模型忽略。
- 片段重叠仍允许（lane 模型）；不因循环改变重叠规则。
- 非循环片段不因其他片段循环改变自己的 `start_time`/`duration`；validator 不要求所有片段一起展开。
- **不新增“无限片段后仍有片段”的禁播校验/告警**：无限只表示没有自然完成点；后续片段是否可达由作者编排的顺序依赖/并行/退出决定，validator 不替作者截断，也不把“无限之后继续编排”判为错误。

## 四、技术细节

### 4.1 核心模型

```text
ClipExecution
  start
  duration
  loop
  loopCount
  loopMode
  executionId
  executionIndex
  executionLocalTime
  executionsRemaining
  done
  infinite
```

- `ClipExecution` 是播放控制状态，不是对象采样器状态；每个播放实例每个片段一份。
- 运行事件推进当前执行；局部轴负责内容采样。轨道内容完成并解除相关等待／依赖后产生执行边界，按剩余次数调度下一次或消费完；不能把 `advance(dt)` 到 duration 直接等同所有内容已经完成。
- `sampleTime()`：返回当前 `executionLocalTime`；`direction` 由 `loopMode` + `executionIndex` 决定。
- `windowEnd`/`infinite` 在加载时预计算；它们只是派生显示/定位信息，不驱动执行，也不作为完成判据。
- `ScriptPlayer` 用 `ClipExecution` 做活跃/消费/内容事实；不再用 `getAnimPeriod`。`contentEnd`/`finiteDisplayEnd` 只用于显示/定位。

### 4.2 契约

- **创建**：clip 加载时计算 `infinite`/`windowEnd`/有限显示范围；实例创建时初始化 `executionIndex=0`、新的 `executionId`、`executionsRemaining=loopCount`。
- **销毁**：随实例/clip 销毁；无跨实例共享执行状态。
- **状态归谁**：执行次数/执行身份/局部时间归播放控制；每帧派生状态归各轨道（见 §3.5）；规则绑定与激活的运行态归播放实例，按（实例、绑定、执行）隔离；宏观循环归 `ScriptPlayer`。
- **边界**：`ClipExecution` 不知道对象/轨道语义；只给“哪一次执行 + 局部时间 + 方向”。对象采样器不知道 `loop_mode`；只认 `executionLocalTime`。
- **实现边界**：局部进度的算术映射只发生在已确认的本次执行内部；不得从全局 elapsed 用 floor/mod 推导另一套执行事实，也不得用窗口数值代替完成事件。

### 4.3 数据形态

- `executionId`：实例内执行身份，供规则绑定／激活和客户端执行状态引用；不序列化，不替换服务端 EVENT 的既有去重键。
- `executionIndex` int；无限执行可增长到 int 上限（实际播放不会到）。
- `executionLocalTime` float；`[0,duration]`；pingpong 反向也在这个范围。
- `direction` enum `forward`/`backward`；非 pingpong 恒 forward。
- `infinite` bool；`windowEnd` 只在 `infinite=false` 时是 float；不用 `+∞`/`NaN`/`MAX` 数值哨兵。
- `loopCount` int；`-1` 无限；`0` 非法；`N>0` 次数。
- `contentEnd`/`finiteDisplayEnd` 是派生只读值，不序列化；`contentEnd` 只在全部内容静态有限时有值。

### 4.4 边界

- 保留过渡混合公式；两侧状态装配按 `track-camera.md`，循环不选择某一侧的 motion／breath 代替两侧各自求值。
- 不改变全局 cover/modifier 的独立层与数学公式；循环只影响执行位置/局部时间。
- 不改变 motion/breath 的数学模型；只定义执行边界不重置。
- 不改变选择器/点源解析；只定义执行边界不重置。
- 不改变宏观循环的服务端 EVENT 排除规则。
- 不改变 `hold_at_end` 的驻留语义：有限内容在自然完成点驻留；无限内容没有自然完成点、不驻留。
- 不改变非循环片段的 `start_time`/`duration` 定义；循环只扩展自己的执行跨度。
- 规则的时间条件以片段执行局部时间为坐标；循环只提供执行身份与局部位置，不替规则判定时间门，也不把执行次数当规则触发条件。时间门是局部时间阈值：`>=` 指定时间后开始／继续判定，不要求精确时刻或跨越事件；门前有效事实按绑定与执行独立保存，动作在门后确认提交。
- 分支片段与主线片段共用同一片段执行与循环模型；正常完成去向与失败 fallback 属于分支出口策略，不由循环层解释。
- 不把无限片段当 terminal：不自动截断后续片段、不因无限片段报禁播错误；后续可达性由作者编排决定。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 时间驱动 lap（`floor(elapsed/duration)`） | 把循环当成全局时钟的模 | 把“执行次数”变成“重新计时”；其他片段被时间轴绑死；与现有循环设计冲突 | 按次数执行 |
| 保留 `%`/镜像折叠 | 采样前把时间折回周期 | 关键帧轴不是执行轴；窗口用周期不是 duration；LaneMask 重复实现 | 执行次数 + 每次局部时间 |
| 所有片段一起循环 | 时间轴整体取模 | 非循环片段也被重复；不符合“只影响有 loop 的片段” | 只循环声明 loop 的片段 |
| 执行边界全状态重置 | motion/breath/selector/audio/event 全部归零 | 手持/噪声跳变；音频尾巴被切；事件重复；与现有设计冲突 | 执行边界不重置这些状态；玩家移动是既有复位点，规则绑定按执行身份独立判定时间门 |
| 把规则时间门当监听起点 | 门之前不采集事实，门后才开始监听 | 提前有效事件丢失；规则条件语义被改写 | 门控制执行资格；采集与提交分离，提前事实按原语义保留 |
| 把规则时间门当精确时刻或跨越事件 | 只在恰好 t 或观测到 cross 时触发 | 迟到条件漏判；seek／跳帧／低帧率下不一致 | 局部位置 `>=` t 后继续判定，不要求跨越事件 |
| 把待执行动作当普通观察 | 主线采样结束即丢弃未释放动作 | 已承诺动作静默丢失；自然完成判断不完整 | 待执行动作作为执行依赖参与完成，但不冻结内容推进 |
| 删除 pingpong | 只支持 repeat | 少一个已测试 fixture/作者能力；反向需求无法表达 | 保留为每次执行内的遍历模式，限制轨道 |
| 负 duration 继续作为无限 | 保留旧哨兵 | 对象轴 `[0,duration]` 失效；每个轨道特判 | 保留但隔离，建议用 loop_count=-1 |
| 用 `windowEnd`/`contentEnd` 数值判完成 | 时间到窗口末端即完成 | 等待/分支/无限没有有限窗口；数值哨兵会被误用；完成与执行事实脱节 | 完成由执行记录给出，窗口只做显示/定位 |
| 无限片段作为 terminal 截断后续 | 无限片段后内容不播、validator 报错 | 把作者编排结果变成框架禁播规则；全局时钟/后续可达性被错误截断 | 无限只表示无自然完成；可达性按作者编排 |
| 用 floor/mod 直接给控制事实 | 时钟除法/取模当执行次数/完成状态 | 等待/分支/暂停/seek 下与执行记录不一致；无法表达每次执行身份 | 只允许纯采样映射，控制事实走执行记录 |

**本方案的缺点**：

- 执行次数与音源重建、命令重放并非一一对应；编辑器须区分参数重复、文件循环和副作用去重，避免将 AUDIO 的参数循环误写成“不循环”。
- 玩家移动是既有复位点；motion/breath/selector 连续，规则时间入口按执行身份独立判定时间门，循环不是“每一遍完全一样”。
- 循环仅影响本片段及显式依赖它的编排，不自动平移独立片段的起点；重叠、顺序依赖与后续调度由声明决定。
- `pingpong` 只允许视觉轨道；音频/事件不能反向。
- 负 `duration` 哨兵保留，对象轴有例外；后续清理会再动一次格式。
- 采样和控制容易被混在一起；实现须保持执行记录单一真源，不能以“纯采样优化”为名重新从全局时钟折叠执行位置。
- `contentEnd` 在含无限片段时没有有限值，外部工具/显示必须接受“无有限末端”，不能拿一个数代替。
- 规则时间入口的等待／观察生命周期归播放实例；seek／暂停／退出要显式处理，不能靠全局时间推断，也不能以缺少跨越事件拒绝已满足的时间条件。
