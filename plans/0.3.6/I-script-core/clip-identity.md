# 片段身份与引用（Clip Identity / Reference）

> 状态：已实现（I4-1 / I4-6）；序列化口径见 §七
> 范围：片段作为可寻址内容实体的身份、跨结构引用、使用关系索引、内容承载（内联/独立）、轨道放置与执行入口的边界、重排/插入/删除后的绑定、迁移
> 关联：`object-model.md`、`runtime-evaluation.md`、`loop-execution.md`、`rule-system.md`、`rule-exits.md`、`path-collection.md`、`migration.md`、`../Z-editor/object-model.md`

## 一、摘要

片段首先是**内容实体**：持有对象组（`objects`）、自身时长与播放控制。它必须有**稳定身份**，让轨道放置、规则绑定、路径条目、分支/跳转目标、启动/编排入口都能明确指向它；同时要能反查**谁引用了它、在哪个结构里被使用**。这里说片段「在哪里」，指它在**引用图中的位置**（被哪个轨道放置、被哪些规则/路径/分支引用），不是世界坐标，也不是时间坐标；时间坐标属于执行入口，由引用边或编排给出。

**内容归脚本，轨道是编排视图。** 片段内容有两种存储形式：**内联**（直接写在轨道 `clips[]`）与**独立**（脚本级 `clips` 表，不属于任何轨道）。两种形式都是脚本级内容声明；内联形式由轨道给一个默认放置，独立形式没有默认放置，只能被引用启动。轨道只持 `ClipRef` 与默认放置，不拥有片段身份；片段可以没有任何轨道放置，只被规则/路径/分支引用。片段身份不由轨道下标、数组顺序或 `start_time` 推导；重排/插入/删除后必须显式重映射或报错，不得静默改指。执行身份在片段身份之上叠加（播放实例 + 片段身份 + 执行序），分支/规则可以在不同执行入口启动同一片段。

## 二、为什么做

- 现行片段是 `track.clips[]` 的匿名元素：没有稳定 id；`goto_clip` 按轨道 + 索引；规则是 `clip.rules`；路径没有集合。插入/重排后，索引会指向另一段内容，引用语义静默改变。
- 规则与路径提升为脚本级集合后，必须能跨轨道/跨结构引用片段；没有稳定身份就只能退回下标或名称匹配，重排/重名即改指。
- 分支/跳转要求目标片段可稳定寻址，且同一片段可能被多条规则、多条路径、多个入口引用；需要区分「同一个片段的多次使用」与「另一段内容」。
- 编辑器/诊断需要反查「这个片段被谁用了」；没有使用关系索引只能全脚本扫描，也无法在删除/重排时给出准确影响面。
- 把身份绑在 `start_time`/轨道槽位上，等于把内容身份和执行调度混在一起；移动片段会改变引用语义。新模型把片段作为一等可引用对象，这是必然概念，不是可选优化。

## 三、方案

### 3.1 三层职责

| 概念（工作名） | 归属 | 职责 |
|---|---|---|
| ClipIdentity（片段身份） | 脚本 | 脚本内稳定、唯一的片段标识；不随轨道顺序/默认放置变化 |
| ClipRef（片段引用） | 脚本级结构/编排 | 指向 ClipIdentity 的引用；可带该引用自己的局部锚点（端点对、时间门、入口局部时间） |
| UsageEdge（使用边） | 脚本级索引 | 谁引用了片段：轨道放置、规则绑定、路径条目、分支目标、启动/入口覆盖；带引用种类与宿主 |
| ExecutionIdentity（执行身份） | 播放实例 | （播放实例、片段身份、执行序）；运行态隔离 |

工作名只是职责标签，不是定稿 JSON 字段名；序列化/引用语法待结构评审。

### 3.2 身份规则

- 脚本内唯一；重复身份是加载期错误。
- 不由轨道下标、数组顺序、`start_time`、对象身份哈希推导。
- 重排/移动不改变身份；重命名是显式操作，必须同步所有引用或报错。
- 删除被引用的片段是加载期错误（或走显式迁移），不得静默丢弃引用。
- 未被任何规则/路径/分支引用的片段合法；轨道放置本身就是一条使用边，不因「没被规则引用」报错。
- 片段也可以没有任何轨道放置，只被规则/路径/分支引用；这种独立形式合法，不要求先放进轨道。
- 复制片段生成新身份；不得两个片段共享同一身份；复制使用边必须显式。

### 3.3 引用与使用关系

- 所有跨结构引用统一用 ClipRef：轨道放置、规则绑定、路径条目、分支/跳转目标、启动/编排入口。
- 加载期编译 `片段身份 → 使用边[]` 反向索引；运行期按身份查，不扫全集合、不按字符串匹配。
- 使用边至少带：引用种类、宿主（轨道/规则定义/绑定/路径条目/入口）、可选局部锚点（端点对/时间门/入口局部时间）。
- 引用必须可解析；悬空引用是加载期错误，带片段身份与宿主路径。
- 同一片段可被多条规则/路径/入口引用；不同使用边各自独立，不共享运行态。

### 3.4 轨道与放置

- 轨道是编排容器：持有有序 ClipRef + 默认放置（`start_time`/顺序）；放置是使用边的一种，不是片段身份。
- 片段内容有两种存储形式：内联（轨道 `clips[]`，该轨道给一个默认放置）与独立（脚本级 `clips` 表，不属于任何轨道，没有默认放置）。轨道只持 ClipRef；独立片段只能被规则/路径/分支/入口引用启动。
- 片段可以没有轨道放置；只被规则/路径/分支引用时，执行入口由该使用边给出。
- 同一片段可以被多个编排条目引用（包含多轨道放置）；是否存在多放置、运行态如何按放置/入口区分，待结构评审；本轮不禁止也不实现。
- 片段被分支/规则启动时，不改写它的轨道放置；执行入口由该使用边给出。
- 轨道顺序只影响默认编排/显示，不定义片段身份；`start_time` 是该轨道内的默认放置位置。

### 3.5 分支、规则、路径

- 分支/`goto_clip`：目标是 ClipRef + 可选入口局部时间；失败 fallback 仍回原主线；不按轨道索引定位。
- 规则绑定：ClipRef + 执行局部时间门；激活身份 =（播放实例、绑定、执行），片段身份是目标的一部分。
- 路径条目：ClipRef + 目标位置序列的两个相邻端点；端点重排/插入必须显式重映射或报错。
- 启动/编排入口：ClipRef + 入口策略（默认/覆盖）；正常完成去向与失败 fallback 分离。
- 独立片段可以直接被规则/路径/分支引用，无需先放进轨道；目标片段可以没有轨道放置。
- 所有引用不复制片段内容；片段内容仍只有一份。

### 3.6 重排、插入、删除

- 重排/移动：身份不变，引用不失效；默认放置随编排更新。
- 插入/删除位置关键帧：路径端点绑定必须显式重映射或报错；不得静默指向另一对端点。
- 删除片段：所有使用边必须显式处理（删除/改指/迁移），否则加载期错误。
- 复制片段：新身份；使用边复制需显式；不得隐式共享运行态。

### 3.7 序列化与迁移（待评审）

- 现行格式：片段嵌在轨道 `clips[]` 里，没有稳定身份；`goto_clip` 用轨道 + 索引。
- 目标：片段带稳定标识；引用用标识而不是下标；具体字段名/语法待结构评审。
- 承载：内联（轨道 `clips[]`）与独立（脚本级 `clips` 表）两种形式；独立形式是**脚本内**存储，不是跨脚本全局库。两种形式都使用稳定身份。
- 迁移：旧下标引用 → 新稳定引用；报告重排/复制/删除差异；不得静默改指；旧 `start_time` 保留为默认放置锚点，执行入口另算。
- 不引入跨脚本全局片段库：内联与独立两种形式都是脚本内存储；身份/引用不等于全局库。

## 四、技术细节

```text
ClipIdentity        // 脚本内稳定标识（工作名）
ClipRef             // identity + 可选局部锚点
UsageEdge           // kind + host + clipRef + anchor?
UsageIndex          // clipIdentity -> UsageEdge[]；加载期编译
ExecutionIdentity   // instance + clipIdentity + executionIndex
```

- **创建**：解析期给每个片段分配身份；重复/非法身份报错；编译使用边索引。
- **销毁**：随脚本销毁；运行态随实例销毁。
- **所有权**：内容归片段；身份归脚本；使用边归宿主结构；执行身份归播放实例。
- **校验**：身份唯一、引用可解析、端点/时间门锚点合法、删除/重排后的绑定显式；错误带宿主路径。
- **运行期**：按身份查使用边/执行身份；不按数组下标或字符串扫描。
- **边界**：身份/引用不定义轨道语义、不定义分支算法、不定义规则判定；只提供稳定寻址与使用关系。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 轨道下标/数组顺序当身份 | 引用写 trackIndex/clipIndex | 重排/插入即改指；跨轨道引用脆弱 | 身份必须稳定 |
| `start_time` 当身份 | 用放置时间定位片段 | 移动片段改变身份；同一片段多入口无法表达 | 时间坐标与内容身份分离 |
| 片段只能内联在轨道 | 每个片段必须属于一个轨道 | 规则/路径/分支要引用就必须先造轨道槽位；内容身份被编排绑架 | 内联/独立两种存储形式，轨道只持引用 |
| 跨脚本全局片段库/新 sequence 库 | 所有片段迁到全局表 | 强制迁移、两套编排；普通片段也被迫改承载 | 身份/引用不等于全局库；独立形式仍是脚本内 |
| 规则/路径复制片段内容 | 每条引用复制一份内容 | 内容多份、编辑分叉 | 引用只指向一份内容 |
| 隐式名称模糊匹配 | 按显示名/路径猜目标 | 重名/改名静默改指 | 显式身份 + 加载期错误 |
| 每个片段只允许一个使用者 | 片段只能被一个结构引用 | 规则/路径/分支多入口无法表达 | 多使用边、各自独立 |

## 六、实现结果

状态：已实现（I4-1 / I4-6）

| 设计目标 | 实现 | 说明 |
|---|---|---|
| 片段稳定身份、跨结构引用、使用关系索引 | `Clip` 带可选 `clipId`（`scriptClipId()` / `identity()`）；`CinematicScript.findClip` 统一解析内联 + 独立片段；`UsageIndex` 编译五类使用边（放置 / 规则绑定 / 路径 / 分支 / 出口） | 见 §七定稿口径 |

## 七、序列化口径（结构评审定稿：I4-1 / I4-6；I2-B3 / I2-B9 关闭）

以下口径已定稿并落地（解析 / 校验 / 使用边索引同一套）：

| 项 | 定稿口径 |
|---|---|
| 片段 `id` | 可选字段，`^[A-Za-z0-9_]{1,64}$`；脚本内唯一，内联片段与独立片段共用同一命名空间（重复 → 加载期错误）。不按下标 / 顺序 / `start_time` / 对象哈希推导 |
| 被引用必填 | 被规则绑定、路径条目、分支目标（`goto_clip`）、出口目标（`exit.target`）引用的片段必须写 `id`；缺 id → 加载期错误「片段被 <宿主> 引用但没有 id」。未被任何结构引用的片段可匿名（231 支既有夹具零改动） |
| 内联片段 | `timeline.tracks[].clips[]`：`start_time` + `duration` + `objects`（新格式），轨道给默认放置；`id` / `exit` 可选 |
| 独立片段 | 顶层 `clips[]`：`track` 必填（决定 `objects` schema）、`duration` 必填非 0、禁止 `start_time`、`objects` 必须非空；`id` / `exit` 与内联同 schema。独立片段没有默认放置，只能被引用启动 |
| 出口 `exit` | `{"on_complete":"continue"\|"goto"\|"return"\|"end_execution"\|"end_script"}`；`goto` 必须带 `target`（片段 id）与可选 `entry_time`（有限 `>= 0`，缺省 0），其余类型禁止 `target` / `entry_time`；未知键报错。片段 `exit` = 默认策略，绑定 `exit` = 入口覆盖，优先级 = 入口覆盖 > 片段默认 > `CONTINUE`；只在分支入口启动的执行完成时解析 |
| 使用边 | 五类：`TRACK_PLACEMENT`（轨道放置）/ `RULE_BINDING`（规则绑定）/ `PATH_ENTRY`（路径条目）/ `BRANCH_TARGET`（`goto_clip` 分支目标）/ `EXIT_TARGET`（出口 goto 目标）；每条带引用种类 + 宿主 JSON 路径 + `ClipRef`（片段 + 可选入口局部时间），解析期编译成 `UsageIndex` 反向索引 |
| 运行期寻址 | 按 id 查 `CinematicScript.findClip` / `UsageIndex.resolve`，不扫全集合、不按字符串模糊匹配；引用不可解析 = 加载期错误 |

剩余待评审（不属于本轮实现范围）：

- 重排 / 插入 / 删除后的显式重映射操作与错误 / 警告边界。
- 同一片段多放置时的运行态区分（本轮不禁止也不实现）。
- 迁移器：旧「轨道 + 下标」引用如何稳定映射到新 id；重复 / 删除片段报告。
