# 脚本对象模型（Object Model）

> 状态：未实现
> 范围：脚本数据形态、对象路径、关键帧组、取值/插值/边界、schema 对象声明、脚本级路径与规则集合的引用关系、普通与分支片段的内容模型
> 关联：`I-script-core/README.md`、`schema-and-types.md`、`runtime-evaluation.md`、`loop-execution.md`、`migration.md`、`I-script-core/rule-system.md`（规则新方向专篇，未完成轮次；旧 `C-trigger/condition-system.md` 仅作既有实现参照）；吸收 `G-script-model/script-model.md` 的 G1/G2；循环目标统一以 `I-script-core/loop-execution.md` 为准

## 一、摘要

脚本以 **Clip 为执行/编排单元**，内部只承载普通数据：统一为 **SampledProperty（采样属性）**，每个属性有独立的 `value` 和 `keyframes[]`，关键帧只属于一个属性，不再有一帧携带全字段的快照。路径与规则不再塞进片段元数据，而是**脚本级独立集合**：路径集合的每条条目先引用一个目标片段，再引用该片段目标位置节点序列中的两个相邻关键帧，并持有该段的 `geometry`（形状）与 `timing`（时间映射）；规则集合持有不可变的 **RuleDefinition（规则定义）**，并由 **RuleBinding（规则绑定）** 引用目标片段与执行局部时间门。**RuleActivation（规则激活）** 是播放实例的运行态，不属于脚本定义。规则控制区分阶段：门前采集事实、门后进入判定；判定成功记录成功事实，动作可延迟到指定片段/局部时间/事实再提交；需要时可建立**本播放实例级**的内容持有（暂停全部内容推进），普通非阻塞观察仍可用。规则成功、片段开始/完成、动作完成是不同事实，可被后续规则引用以接力触发后续片段；时间参照片段与动作目标片段可以不同。普通片段与分支片段使用同一内容模型：片段持对象集合，每个对象持自身关键帧；轨道或分支用途不改变对象 schema。SampledProperty 是叶子：`position.x`、`yaw`、`opacity` 各是一个属性；能独立调的量就是一个属性。运行时按 schema 逐属性求值，轨道播放器只读自己需要的路径并组装语义值；路径集合与规则集合由脚本级索引按片段引用解析，编辑器负责分组、缓动烘焙和呈现。

## 二、为什么做

### 2.1 问题

- **加一个字段要动所有关键帧。** 当前一个 `Keyframe` 是所有字段的稀疏快照；新增一个可调项，旧关键帧都要补默认值或依赖运行时逐字段回落，作者和工具都容易被“这一帧到底有没有写这个字段”绊住。
- **复合值只能整体调。** `position`、`dest`、`source` 是 map，只能整体插值；想只动 x 轴、只改矩形宽度，做不到。`script-model.md` 已把这条列为 G1 的未实现项。
- **稀疏字段的回落口径分裂。** 运行时对缺失字段取字段默认值（`KeyframeInterpolator`），编辑器只插值两端都存在的字段（`operations.ts`），迁移时同一份脚本会出现两套运动。
- **循环在折叠时间。** 片段循环用 `%`/镜像把 clip 内时间折回去，`LaneMask` 又复制了一份；关键帧轴不是真实执行轴。
- **路径只有片段级一份。** 当前 `Clip.curve` 是一个片段一份控制点，隐式套到每个位置段；一个片段想给不同段不同形状、或给同一段并列多条候选路径时，没有承载位置。`objects.curve` 的前稿把路径当 value-only 属性，同样表达不了“目标片段 + 相邻关键帧对 + 形状 + 运动”。
- **规则与片段元数据耦合。** 现行 `clip.rules` 把定义、激活位置和运行态放在同一层，规则只能随片段活跃窗存在；同一规则的多条独立入口、复用定义但不共享计时/once/边沿等运行态，都没有清晰的结构位置。
- **分支片段容易被误当成另一种内容格式。** 如果分支需要独立的内容 schema、全局片段库或新的 sequence 库，普通片段与分支片段就会出现两套对象模型，迁移、编辑器和运行时都要分叉。
- **两个字段没有信息量。** `meta.version` 只有一个值 3；`timeline.total_duration` 只在内容静态有限时能从片段窗口/内容推导有限末端，含无限内容时没有有限真值，却被 parser/validator/编辑器/模板反复写入和校验。

### 2.2 目标

- 新增/删除一个可调项，只动该对象的 schema 和消费代码，不改关键帧容器，也不改其他对象的 keyframes。
- 每个叶子对象可以独立加、删、移动关键帧；同一时间在不同对象上出现关键帧是合法的。
- 运行时只认「路径 + 值 + 关键帧」，不认编辑器分组；轨道播放器只读自己需要的路径。
- 同一片段内所有对象在同一 `t` 求值，然后组装；没有“先算 A 再算 B、B 读到 A 的临时状态”的隐藏顺序。
- 片段循环是执行层重复：关键帧永远在 `[0, duration]` 内采样，不做时间折叠。
- schema 是 parser、validator、编辑器、模板的唯一字段来源；不再维护硬编码通道表。
- 路径与规则在脚本级声明，按片段引用定位：一个片段可以被多条路径条目引用，也可以被多条规则绑定引用；不要求片段自己持有唯一路径或规则数组。
- 普通片段与分支片段共享同一对象 schema、关键帧形态和采样规则；分支只改变执行来源/编排用途，不改变内容模型。
- 结构定义与运行态分离：路径条目的 `geometry` 与 `timing` 只读；RuleDefinition 不可变；RuleBinding 只关联定义、目标片段、时间门与阶段/调度声明；RuleActivation 按（播放实例，绑定身份，执行身份）持有运行态。
- 规则控制可分阶段：时间门满足后可选择建立本实例级内容持有等待判定，或保持非阻塞观察；判定成功、动作提交、动作完成是不同事实，动作可延迟到指定片段开始/完成、局部时间、延迟或事实再执行。
- 规则事实可接力：本实例内某绑定/执行的成功事实、片段开始/完成事实，可作为后续规则的条件，触发后续片段；时间参照片段与动作目标片段可以不同，不要求尚未进入的目标片段先推进自身时间。
- 实例级持有按来源记账，多个来源解除最后一个才恢复内容推进；判定等待可按声明形成实例持有，动作延后是待执行调度，不默认冻结内容推进。不可达的持有依赖给诊断，不自动解除或硬跳主线。

### 2.3 非目标

- 编辑器 UI、对象分组、路径编辑、组合呈现：Z 轮。
- `meta` 静态字段关键帧化（G3）：本轮不做；对象模型只预留扩展点。
- 时间精度（float → double / 有理数）：本轮不动，关键帧时间仍是 float 秒。
- 旧格式兼容层、双语法、解析期分桶：不做。
- 不新增强制全局片段库、强制段落/sequence 库、独立分支内容格式或独立分支引擎；不把嵌套调用栈、并行流程变成前置要求。
- 不规定“只有跨点事件才能满足时间门”；时间门是条件，关键帧只是时间点的选取/引用方式。
- 不把规则接力扩大为通用变量语言、跨脚本任意控制或外部注册总线；规则事实只定位本实例及相关绑定/执行，不做脚本定义上的共享布尔或无界永久历史。
- 不强制所有规则暂停；暂停/等待是显式控制方式，普通非阻塞观察仍可用。动作延后是待执行调度，不默认形成内容持有；只有判定等待可按声明建立实例持有。

## 三、方案

### 3.1 作者看到的形态

一个片段除播放控制字段外，普通数据只有 `objects`；键是稳定路径，值是对象：

```json
{
  "start_time": 0,
  "duration": 5,
  "objects": {
    "position.x": {
      "value": 0,
      "keyframes": [
        {"time": 0, "value": 0},
        {"time": 5, "value": 10}
      ]
    },
    "position.y": {
      "value": 2
    },
    "yaw": {
      "keyframes": [
        {"time": 0, "value": 0},
        {"time": 5, "value": 90}
      ]
    },
    "opacity": {
      "value": 1
    }
  }
}
```

- `objects` 是 JSON object，键是点分路径；键顺序无意义。示例只显示 SampledProperty；路径条目与规则绑定属于脚本级集合，不出现在片段里。
- 对象只放叶子；`position`、`dest`、`source`、`color`、`look_at_part`、`look_at_offset` 这类 JSON map 会展开成叶子路径（`position.x`、`dest.w`、`color.r`……）。
- 已有的标量字段名保持不变（`yaw`、`mask_x`、`mix_rr`、`lut_strength`……）；只有 JSON object/map 才展开。这样迁移是机械的，编辑器可以按 `section` 分组显示。
- `value` 是对象静态值；`keyframes` 非空时覆盖 `value`；`keyframes` 为空/省略时用 `value`；对象缺省时用 schema 默认值。
- 对象没有 `value` 也没有 `keyframes` 等价于缺省；parser 可以丢弃，不报错。
- 关键帧 `time` 相对片段起点；有限片段的采样轴是 `[0, duration]`，无限执行按 §3.5 只要求 `time >= 0`。`time` 落在轴外的关键帧不报错、不参与求值，范围内最后一帧就是末帧，hold 到片段结束。
- 同一对象内 `time` 严格递增；重复时间报错。不同对象之间同一时间合法。
- 非有限值（NaN/Infinity）解析期拒绝；字符串、枚举、布尔、引用按 step；数值按 schema 声明的插值方式。

### 3.2 对象路径

- 路径是 track-scoped 的：`CAMERA` 的 `opacity` 和 `OVERLAY` 的 `opacity` 由各自 track schema 解析，互不影响。
- 路径段用 `.` 分隔；段名与现有字段名一致，使用 `[a-z][a-z0-9_]*`。不引入数组下标；事件记录是离散对象值，不靠路径下标区分。
- 复合 map 的展开规则：
  - `position` → `position.x` / `position.y` / `position.z`；
  - `dest` / `source` → `.x` / `.y` / `.w` / `.h`；
  - `color`（OVERLAY 关键帧颜色）→ `color.r` / `color.g` / `color.b`；
  - `look_at_part` → `look_at_part.x` / `.y` / `.z`；
  - `look_at_offset`、`facing_target_offset`、`yaw_base_from_offset`、`yaw_base_to_offset` → `.x` / `.y` / `.z` + 显式的 `*.space` step 对象（`world` / `base`）；
  - 其余已是标量的字段不展开。
- 路径是稳定标识：schema、脚本、迁移器、编辑器选择状态都用同一字符串；运行时编译成整数槽位，不在每帧做字符串查表。
- 路径拼写错误是解析/校验错误，不做模糊匹配、不做别名。
- **组级参数与组成员平级**：作用于一组叶子的参数（`position_mode`、`position_space`、`position_origin`、`position_origin_freeze` 等）本身也是 `objects` 的路径，与组成员（`position.x/y/z`）平级；不使用容器节点，也不把参数重复写进每个成员的关键帧。组关系由 schema 的 `group` 声明，路径字符串不编码组结构；编辑器分组用 `section`，与运行时组无关。组级参数按自身 `mode` 决定是否可关键帧：点源/参考系切换是 step 属性，必须与组成员的关键帧时间对齐，切换点缺少成员关键帧是校验错误。不引入“组容器”：容器节点会带来“命名空间还是对象”的解析歧义，并让组级参数与成员的关键帧各自需要一套时间语义。

### 3.3 字段形态与脚本级结构集合

`objects` 是 **SampledProperty（采样属性）** 容器，不是结构集合的容器。普通数据统一称 SampledProperty；一个 SampledProperty 有三种形态：

- **value-only**：只有 `value`，没有 keyframes。用于作用于片段/段、但不需要逐帧变化的定义：`orient`、`dimension`、`mask_shape`、`layer_type`、`sound`……它们不需要单独的 clip meta，直接放在字段容器里，脚本不会多一层。
- **animated**：`value` + 可选 `keyframes`。用于可独立调的量：`position.x`、`yaw`、`opacity`、`yaw_offset`、`pitch_offset`……
- **event**：`keyframes` 的值是离散记录，不插值：`event`/`mod_event`。

路径与规则是**脚本级独立集合**，与轨道的片段列表、片段的对象容器并列；它们通过引用定位片段，不占用 `objects` 的路径键空间，也不是新的轨道类型：

- **路径条目**：脚本级路径集合的一个元素。每条先引用一个目标片段，再引用该片段**目标位置节点序列**中的两个相邻关键帧作为端点，并持有该段的 `geometry`（形状）与 `timing`（时间映射）。目标位置节点序列只由该路径所选的位置对象/位置组构成；判断相邻性时只在这个序列内看相邻，不把 FOV、调色、覆盖层等其它对象的帧拼成全片段总序列。一个片段可以有多条路径条目；不同条目各自选择自己的端点对，不隐式复用同一控制点。端点缺失时必须显式补齐或重建并保持绑定可见，不得静默改指另一对端点，具体引用与补齐方式待结构评审。不规定某一种插入细分算法；显式重建可改变形状，但必须与静默改绑区分。
- **形状与运动分离**：`geometry` 决定路径形状与总弧长（`line` 直线 / `bezier` 三次贝塞尔，控制点 XYZ 可分别编辑；参考空间显式，保留相对段起点/绝对世界轴语义；轴集合/2D/3D 弧长沿用既有数学）；`timing` 决定沿路径的推进（局部时间 → 归一化进度，缺省线性、显式时单调），两者互不修改，直线路径同样可以带 `timing`。求值顺序固定：`s = timing(t) · L`，`P = geometry(s)`。路径条目只负责所选轴；未选轴继续按自身 SampledProperty 的局部时间/关键帧求值，仍可独立打帧，不要求整片段三轴全局成组。段外关键帧仍按 SampledProperty 插值。
- **RuleDefinition（规则定义）**：脚本级不可变行为定义，描述内层条件组合树、行为策略（观察/等待、once、边沿/驻留、超时等，按 `rule-system.md`）与动作；不持有播放状态，也不绑定某个片段。一个定义可被多条绑定复用。
- **RuleBinding（规则绑定）**：脚本级关联条目，引用一个 RuleDefinition、一个目标片段和一个**执行局部时间门**，并可声明判定阶段控制（实例级持有/非阻塞观察）与动作调度目标（片段开始/完成、局部时间、延迟、事实）；这些是绑定声明，不是运行态。时间门是必选条件：它定位到目标片段的某次执行及其局部时间，关键帧只提供一个已经确定的时间点，作为时间门的选取/引用方式；不要求规则依赖关键帧，也不要求创建空关键帧。默认时间门为本次执行片段局部时间 **>= 指定值**：到达该值后开始/继续判定其它条件，后面成立可以执行；不是“只在精确时刻判一次”，也不是一次性 cross 事件。时间门控制**执行资格**：在指定局部时间到达前，其它事件条件可能已经触发，但动作不得提前执行；门前有效事件/事实可采集，到达时间后才组合判定并执行。不能把时间门写成“条件监听只从到达时才启动”。一条规则可以有多个独立绑定；每个绑定有自己的时间门、激活身份与运行态，不能把多个“时间 >= t”简单 OR 后让最早时间吞掉后续入口。绑定本身不持有计时/等待状态。
- **事件事实与状态谓词**：时间门前的条件判定必须区分两类。状态谓词按自身实时语义判定，不能把任意一度为真的状态永久锁存；事件事实可按该条件原有的有效期/匹配/消费语义保留到时间门，供到达后确认。事件/事实采集与动作提交分离：有效的提前事件不因时间门尚未满足而丢失。每个绑定/执行上下文各自持有独立状态，不设计无界历史记录或跨实例事件总线；若原条件没有定义记录起点、有效期或消费方式，列为精确待评审项，不假设所有历史事件永久有效。
- **RuleActivation（规则激活）**：运行期实例，身份 =（播放实例，绑定身份，执行身份）；持有该次激活的观察、计时、等待、事实记录、判定成功与动作调度状态。激活记录是运行态实现，不是额外语义前提；有效判定仍由“时间门 AND 内层条件树”决定。共用定义不共用计时、once、边沿等运行态。
- **规则控制阶段**：时间门满足前按源语义采集有效事件事实，不提前提交动作；时间门满足后进入控制阶段，可按声明建立**本播放实例级内容持有**等待判定，或保持非阻塞观察。判定阶段仍要求时间门与 all/any 条件树共同满足；判定成功记录成功事实，动作可延迟到指定片段开始/完成、执行局部时间、显式延迟或事实再提交。判定成功 ≠ 动作完成；成功事实不因原状态条件之后变假而被隐式抹掉，如需再次确认应作为显式执行条件。判定等待可按声明形成实例持有；动作延后是待执行调度，不默认冻结内容推进。
- **实例级持有**：挂起本播放实例的全部内容推进，不影响其它独立脚本实例；多个持有来源按来源记账，最后一个解除才恢复。若判定成功后要等待本实例未来片段/内容位置，必须先释放依赖该进度的判定持有，或由声明的恢复/启动控制保证目标可达；不能假装冻结的内容位置仍会推进。实时时长/外部事实与内容局部位置等待分开计时，超时不被同一挂起冻结；明确不可达的持有依赖给诊断，不自动解除、吞规则或硬跳主线。
- **规则事实接力**：规则判定成功、片段开始/完成等事实可作为后续规则的条件，触发下一片段执行；事实定位到本实例及相关绑定/执行，不使用脚本定义上的共享布尔，不做无界永久历史。时间参照片段与动作目标片段可以不同：例如以 A 的局部时间/成功事实启动 B，不要求尚未进入的 B 先推进自身时间。只覆盖本实例内的规则接力，不扩大为通用变量语言、跨脚本任意控制或外部注册总线。
- **待执行动作与自然完成**：判定成功后已承诺但尚未释放的后续动作不是普通非阻塞观察；主线采样结束不得静默丢弃。它作为明确执行依赖参与自然完成，但不冻结内容推进（否则等待未来片段会互锁）。等待片段开始与等待片段完成是不同语义；显式退出/停播按实例终止回收。
- **规则的必要逻辑**：必选的片段时间门 **AND** 其余条件组合树。内层 `all_of`/`any` 等组合器可以嵌套，但 `any`/`or` 不得绕过最外层时间门；时间门未满足时，规则不得仅凭一次“到达事件”就进入有效判定。默认时间门 = 本次执行片段局部时间 >= 指定值；门后持续判定其它条件，条件后续成立仍可执行。若门后条件一直不成立，规则保持未成立，不因“已经过点”而补执行或丢弃。
- **普通片段与分支片段**：二者只有执行来源/编排用途不同，内容模型相同：同一 `objects` schema、同一关键帧形态、同一采样规则。分支片段仍留在自己的轨道/位置，不强制迁移到全局片段库，也不要求新建段落/sequence 库或另一种分支内容格式。正常完成后的去向（继续、指定目标、返回、结束本执行或本脚本）与执行失败的 fallback 严格分开：**正常完成策略由片段定义提供默认，启动/编排入口可以显式覆盖，优先级为入口显式策略 > 片段默认策略**；失败后沿原主线继续是单独的 fallback，不混入正常后继策略。不得据此把嵌套调用栈、并行流程、全局 sequence 或独立分支引擎变成前置要求。

设计原则：**组合优先、通道级覆盖、定义与运行态分离、创作策略与执行机制分离、按片段引用定位脚本级结构**。

字段可以声明**前置条件**（`requires`）：例如 `yaw_offset`/`pitch_offset` 要求 `orient=tangent`；`look_at` 的目标/偏移要求 `look_at != none`。前置条件不满足时字段不读取/不校验（编辑器置灰/隐藏），满足时才参与求值。前置条件可以递归（A 开才读 B，B 开才读 C），但 schema 构建期必须拒绝环。

**只有播放控制字段留在 clip 外层**：`start_time`、`duration`、`loop`/`loop_count`/`loop_mode` 等；不把 `rules` 固定为 clip 外层目标字段，规则定义/绑定归脚本级规则集合，RuleActivation 归播放实例。除路径条目/规则定义/规则绑定这类脚本级结构外，其余“作用于这个片段/这一段”的普通数据都进 `objects`；是否带 keyframes 由字段形态决定，而不是由“是不是 clip 级”决定。结构条目不进 SampledProperty 容器；`orient` 不需要进 meta，也不会把脚本撑成两层结构。

### 3.4 取值

对字段 `O` 和片段局部时间 `t`：

- `O.mode=value`：直接返回 `O.value`/schema 默认值，不读 keyframes。
- `O.mode=event`：不走本函数；由事件 runtime 按时间触发。
- `O.mode=animated`：按下面步骤采样。

1. 取 `O` 在范围内的关键帧，按 `time` 升序：有限片段为 `[0, duration]`；无限执行为 `time >= 0`（见 §3.5）。
2. 没有范围内关键帧 → `O.value`；`O.value` 也没有 → schema 默认值；schema 没有默认值且对象 `required` → 解析期错误。
3. 只有一个范围内关键帧 → 该值，整段恒值。
4. `t` 小于第一个范围内关键帧 → 第一个值；`t` 大于最后一个范围内关键帧 → 最后一个值。
5. 否则找相邻两帧 `a`、`b`，按 `O.interp` 插值：
   - `linear`：`a + (b - a) * s`；
   - `angle`：最短路径角度插值；
   - `geometric`：`exp(log(a) + (log(b) - log(a)) * s)`（仅 `zoom`，见 `schema-and-types.md`）；
   - `step`：`s < 1 ? a : b`；枚举/字符串/布尔/引用/可空数值默认 step。
6. `s = (t - a.time) / (b.time - a.time)`；两帧时间相同是非法数据，parser/validator 拒绝。

不引入缓动曲线；需要缓动由编辑器在写入前烘焙成显式关键帧。运行时只做上述插值。规则时间门不改变属性采样：属性仍在 `executionLocalTime` 上采样，时间门只决定规则激活/判定。

### 3.5 边界与防护

- 超界关键帧：有限片段 `time < 0` 或 `time > duration` 忽略；无限执行只忽略 `time < 0`。这是正常语义，不是错误，迁移不清理、不报错。
- 范围内最后一帧就是末帧，hold 到片段结束；不会因为“最后一帧不在 duration 上”而回落到对象值。
- 空组回落到对象值；单帧恒值；非有限值解析期拒绝。
- 同一对象重复时间报错；不同对象同一时间合法。
- 未知路径报错；已知路径但类型不匹配报错；`required` 对象没有值/关键帧/默认值报错。
- `mode=value` 的字段不允许 keyframes；`mode=animated` 的字段允许空/非空 keyframes；`mode=event` 的字段只允许 event_record 值。
- `requires` 不满足时，字段存在也不读取；validator 可以警告“写了但前置条件不满足”。前置条件环在 schema 构建期拒绝。
- 可空数值（`yaw_lock`/`pitch_lock`）用 `null` 表示“不锁”；`null` 与数值之间按 step，两个数值之间按声明的角度插值。
- 片段没有任何关键帧也可以有静态相机/静态覆盖层：所有对象用 `value`/默认值；parser 不再要求 CAMERA 至少一个关键帧。
- 无限执行是执行状态语义（当前格式以负 `duration` 表示，属于格式表示，不是完成判据）：对象轴没有有限上界，只忽略 `time < 0`；`time >= 0` 全部在范围内，最后一帧之后 hold。不得用 ∞/NaN/MAX 作为完成判据或有限末端估计；有限部分显示范围单独派生。
- 运行时求值假设数据已通过 parser/validator；不在每帧做类型检查、不抛异常、不分配临时 map。
- 过渡/morph 状态不写入对象：对象只存 `transition*` 声明字段；每侧完整状态由轨道/执行求值，过渡只混合快照，窗口 = 交界 ± maxDuration/2（3 秒窗口 = 前后各 1.5 秒）。某侧在交界附近没有显式关键帧时，按该侧执行位置的所在段/value 求值，不直接取末帧/首帧。
- 路径条目引用不存在/已删除的片段、端点不在目标位置序列、端点不相邻、同一对象内端点时间重复，都是加载期错误；重排关键帧后，绑定必须显式重映射或由作者显式重建，不得静默指向另一对端点。

### 3.6 与循环的关系

- SampledProperty 的采样有效范围是 `[0, duration]`；超界关键帧保留但忽略（见 §3.5）。循环按次数执行，不改变属性轴。
- 循环片段的第 n 次执行由播放控制给出 `executionIndex` 和 `executionLocalTime`；属性采样只用 `executionLocalTime`。`pingpong` 的反向是执行内的遍历方向，不是全局时间取模。
- 规则绑定的时间门以目标片段的执行局部时间为坐标；目标片段执行结束后，时间坐标固定在终止局部时间，不随之后片段继续增长。每次执行进入时建立独立 RuleActivation，时间门满足后推进判定；旧激活不因新执行出现而被重置。
- 实例级内容持有期间，内容局部时间与依赖内容位置的判定不推进；实时时长/外部事实/超时按实例计时继续。持有不改变关键帧轴，也不把冻结位置当成仍在推进。
- 运行位置 = clip + execution + local；当前网络 `(start, offset)` 只是该位置的投影参照，不要求改协议，也不把网络时间当成执行完成事实。
- 循环只作用于声明了 `loop` 的片段；非循环片段仍按自己的 `start_time`/`duration` 执行一次，不因为别的片段循环而改变定义。
- 不再有 `getAnimPeriod()`、`%` 折叠、`LaneMask.effectiveTime` 的重复实现。详见 `loop-execution.md`。

### 3.7 与迁移的关系

- 旧脚本的共享关键帧数组由一次性转换器拆成 SampledProperty；转换器负责复合 map 展开、稀疏字段补齐、`orient`/offset 原样保留、`meta.version`/`timeline.total_duration` 删除。
- 旧曲线按旧全局关键帧段迁移为**脚本级路径条目**：每个旧段一条，引用目标片段，端点对应到该片段的位置节点序列，保留自己的端点/控制点/3D 弧长，`timing` 缺省线性；同一片段的多条旧段各成一条，不限制条数。不能只写一份控制点就声称覆盖所有段。
- 旧 `clip.rules` 迁移为**脚本级规则定义 + 绑定**：旧规则的条件/动作/策略成为定义，旧片段的激活位置成为绑定的目标片段引用与执行局部时间门；RuleActivation 不写入脚本。旧规则按片段活跃窗起算的语义与新的时间门/激活生命周期差异必须单列报告，不能伪称等价。旧数据没有的实例级判定持有、成功事实、动作延迟、事实接力列为“未迁移能力”，不补写。
- 迁移以“旧运行时在同样输入下的可观察结果”为准；能保真的属性用修正关键帧。路径条目的引用/序列化待评审，但不得退回“片段级唯一路径”。
- 不做运行时兼容：新 parser 只认 `objects` 与脚本级集合；出现旧字段按“已移除”处理。

### 3.8 已确认的时间门语义与结构评审项

- **时间门默认语义（已确认）**：本次执行片段局部时间 >= 指定值；到达后开始/继续判定其它条件，后面成立可以执行；不是“只在精确时刻判一次”，也不是一次性 cross 事件。关键帧只用于取该时间值，不是额外激活前提。
- **门前事实（已确认）**：门前有效事件/事实可采集，动作不得提前提交；到达时间门后组合判定并执行。事件/事实采集与动作提交分离，提前事件不丢失。
- **正常完成策略（已确认）**：片段定义提供默认，启动/编排入口可显式覆盖，优先级为入口显式策略 > 片段默认策略；失败沿原主线继续是独立 fallback，不混入正常后继。
- **判定与动作分离（已确认）**：判定成功、动作提交、动作完成是不同事实；成功后可按声明延迟到片段开始/完成、局部时间、延迟或事实再执行，不是重新判定原规则。判定等待可按声明形成实例持有；动作延后是待执行调度，不默认冻结内容推进。
- **结构评审项（非用户待确认）**：
  - 事实记录起点、有效期、消费方式与跨执行匹配；
  - 稳定片段引用（数组下标不足以在重排后保持绑定）；
  - 实例级持有与动作延迟调度的 schema 表达；
  - 脚本级集合的身份/引用/序列化、迁移与编辑器呈现；
  - 若某事件条件原定义没有说明记录起点、有效期或消费方式，其门前事实如何保留。
  以上不假设所有历史事件永久有效，也不引入无界历史或跨实例事件总线。

## 四、技术细节

### 4.1 核心模型

```text
CinematicScript
  meta
  timeline
    tracks[]
      type
      clips[]
        startTime
        duration
        clipData        // 播放控制字段（不固定清单）
        objects         // Map<path, AnimObject>
          value         // 可选静态值
          keyframes[]   // {time, value}
  paths[]               // 脚本级路径集合
    targetClip          // 片段引用
    endpointA/B         // 目标位置序列中两个相邻关键帧
    geometry            // { type: line | bezier, controlPoints? }
    timing              // 时间映射；缺省线性
  rules[]               // 脚本级规则定义
    conditionTree       // 内层组合条件树
    actions
    policy
    bindings[]          // 或脚本级独立绑定集合，待评审
      targetClip        // 片段引用
      timeGate          // 执行局部时间门；关键帧可作为时间点来源
      control?          // 判定阶段：实例级持有等待 / 非阻塞观察
      actionSchedule?   // 动作延迟：片段开始/完成、局部时间、延迟、事实
      actionTarget?     // 动作目标片段，可与时间参照片段不同
```

- `AnimObject` 是 SampledProperty 的统一容器；类型由 schema 的 `ObjectDef.type` 决定，不在对象里重复写类型。
- `Clip` 不再持有 `List<Keyframe>`；`Keyframe` 类被 `ObjectKeyframe`（`time` + `value`）取代。
- `Clip` 不持有路径或规则数组作为目标形态；路径/规则引用由脚本级集合按片段索引解析。旧 `Clip.curve`/`clip.rules` 只作为迁移输入。
- `TimelineTrack` 仍只持有 `type` + `clips[]`；对象路径由 track schema 解释。
- 对象值类型：`float`、`int`、`bool`、`string`、`enum`、`ref`、`nullable_float`、`event_record`。`event_record` 只用于 EVENT/MOD_EVENT。
- `Timeline` 不再持有 `totalDuration`；有限末端估计只在所有内容静态有限时由实际内容/片段窗口推导（不是 `max(windowEnd)` 的别名，也不驱动消费）；含无限内容时表达“无有限自然末端”（状态语义，不用 ∞/NaN/MAX 数值哨兵作完成判据），有限部分显示范围单独派生，不能反过来驱动消费。见 `format-cleanup.md`。

### 4.2 契约

- **创建**：parser 读取 clip 的 `objects`，按 schema 路径建 SampledProperty；未知路径拒绝；缺省属性不创建，采样时回落 schema 默认值。脚本级路径集合由路径解析器编译：校验目标片段引用、目标位置序列、两个相邻端点、`geometry` 与 `timing`；脚本级规则集合由规则解析器编译：RuleDefinition 只读加载，RuleBinding 校验定义引用、目标片段引用、时间门与关键帧时间来源；RuleActivation 只在运行期、绑定所属片段执行进入时按（播放实例，绑定身份，执行身份）创建，承载门前观察/事实。
- **销毁**：对象随 clip 销毁；路径/规则定义随脚本销毁；绑定随脚本/定义销毁；激活随播放实例销毁。没有跨 clip 共享的对象或关键帧数组。
- **所有权**：对象只属于一个 clip；clip 只属于一个 track；脚本级集合只属于脚本。轨道播放器只读对象，不写对象；路径解析器只读 `geometry`/`timing`；规则引擎只读定义/绑定，写激活状态。判定成功、动作待执行/完成/取消、持有来源都归实例/绑定/执行，不写回 RuleDefinition；规则事实按实例与绑定/执行定位，不做脚本级共享布尔。
- **求值**：每个 clip 有一个 `ClipSampler`，对路径提供 `sample(path, t)`；采样是纯函数，不修改对象状态。路径解析按目标片段索引查条目，规则引擎按绑定索引查激活；状态（选择器锁、快照、运动模型、激活）由轨道播放器/规则引擎单独持有，不藏在采样器里。
- **时间**：`t` 是当前执行的片段局部时间，范围 `[0, duration]`；执行层负责第几次执行/反向，采样器只接受已归一化的 `t`。规则时间门使用同一执行局部时间坐标。
- **缓存**：`ClipSampler` 在加载时把每个对象的 keyframes 排序、编译成数组；每帧二分/游标查找；不按路径字符串查 map。脚本级集合在加载时编译成 `clip -> 路径条目[]` 与 `clip -> 绑定[]` 索引，运行期不做集合线性扫描。
- **错误**：加载期错误带脚本路径、轨道、clip 索引、对象路径、关键帧索引；规则/路径错误带集合索引与目标片段引用。运行期不因数据错误崩溃（数据已校验）。

### 4.3 数据形态

- `objects` 的 JSON 键是 SampledProperty 路径；值必须是对象，不能是裸标量。裸标量是旧写法，按“已移除”拒绝。
- 路径条目/规则定义/规则绑定是脚本级集合元素，不占用 `objects` 的路径键空间；RuleActivation 只在运行期存在。结构条目的身份/引用/序列化待评审，但不得伪装成 value-only SampledProperty。
- 路径条目的目标位置序列只包含所选位置对象/位置组的关键帧；端点相邻性在这个序列内判断，不能把其它对象帧并入编号。一个片段可以有多条路径条目，端点对可以重叠，也可以指向同一段的不同 `geometry` 定义。
- 规则绑定必须有时间门；没有时间门的规则不成立。一个 RuleDefinition 可以有多条绑定；每条绑定独立指向片段/时间门，运行态按绑定与执行隔离。时间门的关键帧引用只提供时间点，不把关键帧变成规则激活的额外前提。
- `keyframes` 必须是数组；每项必须是 `{time, value}`；多余字段拒绝。
- `time` 是有限数值；`value` 按 schema 类型校验；`null` 只允许 `nullable_float` 和 `event_record`。
- 同一对象的时间严格递增；parser 不做排序“帮忙”，排序错误直接报错，避免静默改变作者意图。
- 对象 keyframes 不要求覆盖 `0` 或 `duration`；边界值由采样规则补齐。
- `value` 和 `keyframes` 同时存在时，keyframes 覆盖静态值；第一帧之前仍用第一帧，不回落到 `value`（与“范围内第一帧就是起点”一致）。
- 空 `keyframes: []` 等价于没有 keyframes；用 `value`。
- 普通片段与分支片段在数据形态上无差别：同一个 track 的 `clips[]` 使用同一 schema；不存在“普通片段对象表”和“分支片段对象表”两套。
- 规则绑定可声明判定阶段控制（实例级持有/非阻塞观察）与动作延迟目标；这些是绑定数据，不是运行态。判定成功、动作待执行/完成/取消、持有来源只在运行期存在；规则事实引用定位到实例与绑定/执行，不复制脚本定义。

### 4.4 边界

- 对象模型不碰 `meta`；`meta` 仍是静态字段。G3 以后若要关键帧化，按同一 `AnimObject` 容器加在 script 级，不改 clip 对象模型。
- 对象模型不碰轨道语义：CAMERA 怎么把叶子组装成六参数、OVERLAY 怎么画、ADJUST 怎么走着色器栈，分别由轨道文档定义。
- 对象模型不碰循环执行：`executionIndex`/反向由播放控制给出；采样器不知道 `loop_mode`。
- 对象模型不碰编辑器呈现：编辑器可以把 `position.x/y/z` 显示成一组，也可以把 `dest` 显示成一个矩形控件；运行时只认路径。
- 对象模型不碰迁移实现：转换器可以用旧 evaluator 做对照，但运行时没有旧 evaluator。
- 对象模型不定义路径/规则的最终 JSON 字段名与引用语法；只固定“脚本级集合 + 片段引用 + 目标位置序列相邻端点 / 时间门”的责任边界，序列化由结构评审定稿。
- 对象模型不定义分支调度器、调用栈或全局 sequence；普通/分支片段的内容模型相同，编排去向由执行层按已确认的正常/失败区分处理。
- 对象模型不定义规则条件/动作阶段的具体字段与算法；这些归 `rule-system.md`。本文件只固定脚本级集合、片段引用、时间门、判定成功/动作完成分离与实例级持有的结构位置。
- 对象模型不定义通用变量语言、跨脚本任意控制或外部注册总线；规则事实接力只覆盖本实例内的绑定/执行。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 保留共享快照，只加 `keyframable` 标记 | 每个关键帧仍是全字段 map，schema 标记哪些字段可关键帧 | 加字段仍要动所有关键帧；稀疏回落仍分裂；复合值仍不能单轴调 | 没有解决 G1 的核心问题 |
| 每个轨道一个强类型 Keyframe 类 | CAMERA/OVERLAY/ADJUST 各自一个类，字段直接挂 | 新增字段要改类、parser、validator、编辑器、模板五处；跨轨道不能统一处理 | 违背“加对象不改容器”的目标 |
| 复合值保持整体对象 | `position`、`dest` 仍是一个对象，内部再分 | 不能只动一个轴/一个边；对象不是叶子，schema/编辑器要写特例 | 与“每个可独立调的量就是一个对象”冲突 |
| 嵌套 JSON 作为唯一写法 | `objects.position.x` 写成 `objects.position: {x: {...}}` | 路径解析要区分“命名空间”和“对象”；map 与对象歧义；迁移/校验更复杂 | 扁平路径更稳定，嵌套只是编辑器呈现 |
| 所有作用于片段的字段都进 clip meta | `orient`/`motion_*` 等单独一层 clip 字段 | 脚本多一层；字段与关键帧的依赖关系散落；新增字段要改 meta/schema/编辑器 | 字段容器统一，value-only/animated 由字段形态决定 |
| 所有字段都必须有关键帧组 | 连 `orient` 也写成 keyframes | 结构化字段没有时间语义；脚本变复杂；编辑器要伪造关键帧 | value-only 字段只带值 |
| 路径继续挂在 clip 上，一份控制点套所有段 | `clip.curve` 或 `objects.curve` 只有一组 P1/P2，隐式作用到每个位置段 | 不同段不能有不同形状；同片段不能有多条候选路径；插入关键帧会改变其余段 | 脚本级路径集合，每条先引用片段、再引用目标位置序列的相邻端点 |
| 路径做成 value-only SampledProperty | 复用普通字段容器，只放一组值 | 路径需要目标片段、端点对、`geometry`/`timing`；单值容器表达不了，也无法索引 | 路径条目作为脚本级集合，与 SampledProperty 分离 |
| 路径只按全片段关键帧总编号 | 把 FOV/调色等所有对象的帧拼成一条总序列，路径按总序号取相邻帧 | 其它对象增删帧会改变位置路径的端点；语义不可见 | 只在目标位置序列内判断相邻，不拼全片段总序列 |
| 规则继续放在 `clip.rules` | 定义、激活位置与运行态都在片段元数据 | 规则只能随片段活跃窗存在；同规则多入口无法独立；复用定义会串运行态 | 脚本级规则集合：定义 + 绑定 + 运行激活分离 |
| 规则只做一个全局数组，多个时间入口 OR 成最早时间 | 同一规则写多个 `time >= t`，取最早满足的一个 | 后续入口被最早入口吞掉；once/边沿/计时无法按入口独立 | 每条绑定独立时间门与运行身份 |
| 只有全部条件成立后才允许 pause | 规则先判定，成功后才挂起实例 | 到时间门后想先停住等内容、等后续判定的场景无法表达 | 时间门后可进入控制阶段，按声明建立实例级持有等待判定 |
| 判定成功即动作完成 | 成功事实和动作提交/完成合并成一个状态 | 延迟动作、跨规则接力、完成诊断都无法区分 | 成功、动作待执行/完成/取消分开记账 |
| 动作延迟时重新判定原规则 | 到目标片段/时间后从头再判一次 | 原状态条件可能已变假，成功结果被隐式抹掉；语义重复 | 成功后按声明调度，不重新判定；需再确认用显式执行条件 |
| 时间参照片段与动作目标必须同片段 | 只允许在同一片段内等局部时间/完成 | A 的时间/成功事实无法启动 B；跨片段接力不可表达 | 两者可不同，不要求未进入的目标片段先推进时间 |
| 规则事实用脚本级共享布尔 | 在定义上放“已成功”标记供后续规则读 | 循环/多实例串状态；无法定位绑定/执行 | 事实按实例与绑定/执行定位，不做共享布尔或无界历史 |
| 用“到达关键帧事件”替代时间门 | 规则只在跨过某个关键帧时判一次，时间条件不参与有效判定 | 时间条件变成一次性事件；不满足时间门也能触发；与“条件必须满足”冲突 | 时间门是必选条件，关键帧只提供时间点 |
| 分支片段使用独立内容 schema / 全局片段库 / 新 sequence 库 | 分支内容另存一份格式，或把全部片段迁到全局库 | 两套对象模型、两套迁移/编辑器；普通片段也被迫改承载 | 普通/分支同一内容模型，分支只改执行来源/编排用途 |
| 运行时保留旧格式兼容 | parser 同时认 `keyframes` 和 `objects`，同时认 `clip.curve`/`clip.rules` 和脚本级集合 | 两套语义、两套校验、两套编辑器路径；旧口径永远清不掉 | 违反版本原则“不维护自己的过时东西” |

**本方案的缺点**：

- CAMERA 一个片段可能有 160+ 个对象，原始 JSON 比快照冗长；作者入口是编辑器，手写脚本不是推荐路径。
- 扁平路径可读性不如嵌套；编辑器必须做分组和标签，否则 `mix_rg`、`hue_magenta` 这类名字很难扫。
- 稀疏字段迁移是高风险点：旧运行时的“缺失=默认”必须用修正关键帧或明确的语义变更来处理，不能靠机械拆 map。
- 路径拼写错误只能在解析/校验期发现；运行时没有模糊匹配兜底。
- 脚本级路径/规则的序列化、片段引用语法、目标位置端点表达仍待结构评审；parser/validator/编辑器/迁移必须先按同一责任契约实现，不能把结构条目塞回 SampledProperty 或退回片段级唯一路径。
- 同一片段的多条路径可能引用重叠端点；编辑器必须显式显示每条路径的端点对与 `geometry`，否则作者难以分辨。
- 规则多绑定会带来多份激活；未完成的旧激活不会因新执行出现而重置，无限循环 + 永不满足的条件会累积激活（不阻止自然完成，实例结束即回收），需要作者用条件/超时/退出收束。
- 普通/分支片段共享内容模型；正常完成默认由片段定义、入口显式覆盖，编辑器/模板不应擅自生成全局片段库或独立分支格式。失败 fallback 独立，不混入正常后继。
- 2 轴路径只保证该平面内 2D 弧长，不承诺 3D 匀速；未选轴继续按自身 SampledProperty 的局部时间/关键帧求值。
- 结构集合需要独立的 schema/parser/validator/编辑器入口，不能复用 SampledProperty 的表单和关键帧容器；这是一层额外实现成本，但避免把编排语义伪装成普通值。
