本页只做索引与决策记录，不重复各文档正文。一个点一篇文档；组件、协议、步骤以各文档为准。

## 一、定义

编辑器是**固定格式脚本的生成器**。它不是视频剪辑器，也不是构图编辑器：时间轴、预览、参数面板都为产出脚本服务，产物由模组侧解析与播放模块唯一确认。外部编辑器是唯一编辑器。

- 产物是模组可解析的标准脚本；编辑器不定义格式，也不改运行时语义。
- 生成包含优化：编辑器把底层能力整合、优化成效果，细分到每一项效果都能快捷生成——作者想要环绕、黑场、划像这类效果，不必考虑底层怎么组合，编辑器按底层规则把该有的效果拼出来。
- 作者的输入是“要什么效果”，不是“底层字段怎么填”。

## 二、为什么做

### 2.1 问题

- 游戏内编辑器编译在模组里，每个 Minecraft 版本都要重新适配，一份编辑器对接不了多个版本。
- 它占模组 Java 代码三分之一左右，自带文件读写、预览捕获与整套 UI，与播放解析混在一处。
- 作者只能在游戏里改脚本，改完切回游戏看效果，一轮迭代成本接近重开游戏。

### 2.2 目标

- 一份编辑器对接所有版本：字段由模组侧 schema 描述，编辑器按 schema 渲染表单。
- 不启动游戏也能打开界面，用示例数据浏览与编辑。
- 游戏内按键后，编辑器能读写脚本、校验、看实时画面、控制播放、进飞控取景。
- 新增字段只需改 schema 并补一个控件。
- 只有本机编辑器能连上；脚本数据模型与字段元数据不随编辑器存亡。

### 2.3 非目标

- 不做视频剪辑器：媒体导入、成片导出、转码、特效库都不做。
- 不做构图编辑器：时间轴与预览只为产出脚本服务。
- 不把前端打包进模组 jar，不托管成网页，不做远程访问。
- 不保留游戏内 Java 编辑器。

## 三、形态与能力

### 3.1 形态

独立的 Windows 小工具（Vue 3 + TypeScript + Vite + Electron，源码在 `editor/`），不随模组分发，已打出安装包（0.1.0，测试中）。带离线演示模式：没连游戏时也能浏览界面与示例脚本。游戏内按 F9 打开预览屏并启动本地服务，编辑器连上 `ws://127.0.0.1:8765/ws` 即可工作，关屏即断开。mod 是服务端，编辑器是客户端。

### 3.2 能力

脚本管理（新建、打开、保存、删除、校验）、meta 与轨道、片段、关键帧与触发器编辑、播放控制、实时预览、飞控取景、撤销重做、A-B 循环、marker、快捷键与中英双语。时间轴与预览是产出脚本的辅助，不是通用剪辑能力。

### 3.3 权威

权威始终在模组侧：编辑器不直接读文件、不自己解析，字段有哪些、脚本是否合法都经协议回答；加一个字段等于改 schema 加一个控件。字段元数据归 `script/schema/`，独立于任何编辑器存在。

## 五、方案取舍

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 继续保留游戏内 Java 编辑器 | UI 留在模组内 | 每版本重适配、改字段重编译 | 一份编辑器对接所有版本更划算 |
| 以 Olive / lossless-cut 为壳 | 取用开源剪辑器代码 | 两者是 GPL（Olive GPL-3.0、lossless-cut GPL-2.0-only），本项目 MIT，会被迫改许可 | 许可不可行 |
| 以 MIT 剪辑软件为基座 | 用现成剪辑器改 | 素材是媒体、核心是切片段，与脚本生成器不同构 | 结构不采用，只借交互外形 |
| 模组托管网页给浏览器 | 服务端出页面 | 页面读不到凭据、权限受限 | 桌面客户端更合适 |
| 引第三方 WebSocket 库 | 现成库做握手与帧 | 多一份依赖与打包成本 | 需求只有文本帧、二进制帧与单机连接 |
| 引重型图库（d3 / cytoscape / G6）做架构图 | 现成布局与画布 | 依赖体积、样式难贴合分区语义 | 自研布局更可控 |
| 力导向布局 | 物理模拟 | 每次结果不同、文件夹语义丢失 | 拓扑分层可重复 |
| 只画脚本级依赖 | 同一对脚本的多条前置合成一条 | 丢失触发器粒度 | 边保留触发器与条件 |

**本方案的缺点**：预览屏不开就用不了，失去“不切窗口”的便利；服务端仍在模组内，跨版本适配只解决一半；飞控单独镜头依赖多相机画面与预览隔离，链路长；预览用原始像素，带宽与画质固定，单凭据无权限分级；架构图大包规模下的渲染方式未定，前置成环只能提示，布局不能由作者保留，图不随脚本增删改自动更新。

从 Olive 借的是设计思路（不受版权保护）：变换按序列分辨率归一化到 [-1,1]、Fit / Fill / Stretch 适配三档、关键帧自带插值 + 贝塞尔手柄、向量按分量分轨、裁切四边 0~1 归一化。lossless-cut 用的 `electron-vite` 脚手架本身是 MIT，但编辑器已是同一套栈，fork 它是降级。

## 七、边界

- 不改运行时字段与语义；字段问题回运行时轮，不在编辑器里补。
- 模板展开只在编辑器，运行时零模板语义；模板产物 = 标准字段脚本，与手写等价。
- 不保留游戏内 Java 编辑器。
- 架构图只读：不写脚本，不改前置依赖；布局与视图状态不落到脚本文件。
