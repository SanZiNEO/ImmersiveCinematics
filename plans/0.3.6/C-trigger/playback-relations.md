# 播放关系与队列

> 状态：已实现（2026-10-14）
> 范围：多脚本同时播放时的到达裁决、排队接播、按实例退场、跨脚本控制原语
> 关联：`docs/SCRIPT_FORMAT.md` §1b、`plans/complete/0.3.6/B-camera/parallel-playback.md`、`plans/0.3.6/C-trigger/condition-system.md`

## 一、摘要

脚本在元信息里声明自己在播期间与其它脚本的关系：并行、独占或可打断。新请求到达时按当前在播集合裁决——有独占就排队，没有独占但有可打断就先顶掉再开播，其余直接并行加入。排队按脚本 id 占位，优先级降序、同级先来先播，同脚本重复请求替换自己的排队位，队列跨实例存活。退场渐出按播放实例隔离，服务端可按脚本与实例精确停止或取消排队。

## 二、为什么做

### 2.1 问题

- 所有脚本默认跨脚本并行：任何新脚本都直接叠上来，没法表达「这段剧情播放时别插别的」。
- 同脚本不可打断时，第二次请求入队后在实例结束时被清掉，接播永远不发生。
- 退场渐出是全局的：一个实例退场会把其它实例的覆盖层一起淡掉，并行画面互相牵连。
- 停止只对最顶层实例生效：并行时想停下面那个脚本，没有入口。

### 2.2 目标

- 脚本可声明在播期间的关系；新来者按在播集合得到确定去向（直接播 / 排队 / 顶掉）。
- 排队项在阻塞者结束后按优先级与先来后到接播；同脚本重复请求不堆积。
- 一个实例退场只影响自己的层与退场时机。
- 能按脚本（可再按实例）停止任意层级的实例；不在播时能取消它的排队项。
- 不声明关系的旧脚本行为不变。

### 2.3 非目标

- 不做优先级抢占；优先级只决定排队次序。
- 不做插队、组与标签整组进出、无视可打断标记的硬抢。
- 不做被打断后的恢复续播（停即销毁）。
- 不做主相机声明与跨维度运镜。
- 不定义玩家死亡的处置。
- 不做队列容量上限与满容量策略。

## 三、方案

每个脚本在元信息里选一种播放关系：

| 关系 | 在播期间的表现 |
|---|---|
| 并行 | 不挡任何新来者，也不被跨脚本顶掉；缺省值 |
| 独占 | 我播时其它脚本的启动请求一律排队，我播完按序接播 |
| 可打断 | 新来者可以顶掉我（实例销毁）后开播 |

到达裁决先看同脚本：同脚本已在播时按它自己的可打断开关决定「立即替换」还是「排队」。跨脚本时看在播集合：有独占就排队；没有独占但有可打断就先顶掉所有可打断实例再开播；其余情况直接并行加入。新脚本开播后，它自己的关系对后续到达者生效。

排队按脚本 id 占位：同一脚本再次请求替换自己的位置，不排到队尾。顺序是优先级高的先播，同优先级按请求先后。阻塞者全部结束才开始接播；每接一个都重新检查，因为刚接的脚本可能自己是独占。队列不设容量上限，跨实例存活——只有世界退出、断线、强制停止才清空。

退场统一走一条链：被打断、被停止、自然结束都先渐出本实例的层，渐完再真正停用；强退与全停不渐出。打断形态是硬切：顶掉即销毁，没有过渡。

服务端可以按脚本 id 停止实例，可再带实例 id 精确到某一个，不限层级；不在播时退化为取消该脚本的排队项，两者都不匹配就静默忽略。末尾驻留的实例仍算「在播」，会继续挡住独占期间的新来者，直到有人退出它。编辑器预览实例不参与裁决、不挡队列，恒定在最上层。

## 四、技术细节

### 4.1 核心模型

- **播放实例**：一次真正的播放，持有脚本、实例 id、播放模式快照、行为开关、规则引擎与覆盖层归属 token。
- **播放注册表**：活跃实例列表（顺序 = 启动顺序，后写覆盖先写）、同脚本查询、按模式查询、按脚本与实例定位；预览实例恒在末位。
- **播放生命周期**：启动、到达裁决、统一退出、立即停用、队列排空、全局复位；待接播槽与队列都归它。
- **播放队列**：按脚本 id 的优先队列，条目 = 脚本 + 实例 id + 入队序号；提供入队或替换、按脚本取消、取首个可播项。
- **覆盖层管理器**：层带归属 token（值 = 播放实例引用），渐出触发、动画判定、清理都按归属过滤。
- **帧驱动**：每帧遍历实例；退场中的实例在自己的层不再动画时停用；内容播完的实例按末尾驻留策略退出。
- **播放账本与预览通道**：前者上报开始与结束，后者把预览实例与游戏实例隔离。

### 4.2 契约

- 实例由生命周期创建：新请求通过到达裁决后新建并启动；预览实例由预览通道创建，不经过到达裁决。
- 队列归生命周期所有，跨实例存活；只有全停（强制停用 / 紧急停止）清空，普通实例结束不清。
- 出队权在生命周期：判据是「当前没有独占实例在播」；每个接播项启动后重新判定。同脚本已在播的排队项跳过但保留原位。
- 待接播槽优先于队列：同脚本可打断替换时，替换目标退出后先接待接播项，并移除该脚本的旧排队副本。
- 退场渐出的所有权在实例：触发渐出只传本实例 token，完成判定由帧驱动按本实例的层动画状态决定。
- 结束原因五值不扩：跳过、系统停止、被打断、强退、自然结束；声明式退出映射到自然结束。
- 全局复位只在注册表为空时发生；仍有实例在播时只重算行为开关并集。

### 4.3 数据形态

- 播放关系 = 枚举三值：`parallel` / `exclusive` / `interruptible`，缺省 `parallel`；域外值按缺省处理并告警。
- 同脚本再触发开关 = 独立布尔值（缺省开），不进入行为并集。
- 队列条目 =（脚本, 实例 id, 入队序号）；排序键 = 优先级降序、序号升序；同键替换保留原序号。
- 实例的播放模式在启动与脚本替换时从元信息快照，运行期不变。
- 退出请求原因与完成原因是两套枚举：请求原因决定门控（可跳过 / 可打断 / 末尾驻留），完成原因上报给服务端。

### 4.4 边界

- 预览实例不参与同脚本查询与按模式查询，也不挡队列；它恒在列表末位，即最上层。
- 关系裁决只看游戏实例；编辑器预览与游戏播放并行时互不影响。
- 优先级不产生打断，只决定队列内次序。
- 队列不按实例 id 区分：同脚本只有一个排队位，后来的请求覆盖前一个。
- 音频、HUD、输入交接按各自口径（音频每实例各响，行为开关取并集），本篇不改。
- 跨维度运镜、主相机声明、玩家死亡处置都不在这里。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 全局一次只播一个脚本 | 新请求一律顶掉当前 | 并行叠加（画中画、字幕并行）做不了 | 现状需要跨脚本并行 |
| 新来者侧声明 | 请求方声明「我要并行 / 排队 / 打断」 | 语义落在请求方，每个调用点都要重复；与「在播者决定关系」的直觉相反 | 采用在播侧声明 |
| 优先级抢占 | 高优先级请求直接顶掉低优先级实例 | 打断变成隐式副作用，难以预测、难以调试 | 优先级只排序 |
| 有界队列 + 满则拒绝或替换最旧 | 队列设容量，满时丢弃 | 拒绝会丢请求；替换最旧会丢更早的意图 | 队列无界 + 同键替换 |
| 每次请求占一格 | 同脚本重复请求各占一位 | 重复触发堆积，播完连播多次 | 同键替换排队位 |
| 合并同脚本开关与跨脚本关系 | 一个字段同时管两种语义 | 需要迁移同脚本的替换行为，旧脚本语义会变 | 两字段共存分工 |

**本方案的缺点**：

- 独占脚本播完（含末尾驻留）之前挡住所有新来者；一个长驻留脚本能把队列堵很久。
- 队列无界：持续触发会无限堆积，只有同键替换能抑制重复。
- 被打断即销毁，没有恢复续播；作者只能用重新触发来补。
- 打断是硬切，画面会跳，没有过渡可用。
- 关系只看脚本，不看实例：同一脚本的两个实例无法各自声明关系。
- 预览实例是特例而非第四种关系，规则上要多记一条。
- 服务端只能停实例或取消排队，不能查询队列内容。

## 六、实现结果

状态：已实现（2026-10-14）

| 设计目标 | 实现 | 说明 |
|---|---|---|
| 打断形态 = 硬切（顶掉即销毁） | 跨脚本顶掉走渐出退场（约 0.5 秒），同脚本替换仍硬切 | 渐出改为按实例后，跨脚本打断复用同一条退场链 |
| 队列满时拒绝新请求 | 队列不设上限，永不拒绝；请求结果只有拒绝（世界未就绪）、已开播、已排队三态 | 队列是无界优先队列，容量问题不存在 |
| 退场渐出为全局一次 | 按实例归属过滤；渐出层 0.5 秒，图片与字幕层无动画、下一帧硬停 | 修并行时互相牵连的缺陷 |
| 黑边层为全局单例 | 每个实例自建黑边层 | 同上：层归属按实例 |
| 停止只对顶层生效（现状缺陷） | 按（脚本, 实例）精确定位，任意层级都停；不在播则取消排队项 | 控制原语补齐 |
| 队列跨实例存活 | 一致 | — |
| 同脚本开关与跨脚本关系不合并 | 一致 | — |
| 语义轴 = 在播侧 | 一致 | — |

#### 2. 播放模式（定稿：三态枚举 @ 脚本 meta）

`meta.play_mode`，三值，声明**该脚本在播期间与其它脚本的关系**（在播侧语义；到达行为由在播者集合决定，见 §4）：

| 取值 | 中文 | 在播侧语义 | 缺省 |
|---|---|---|---|
| `parallel` | 并行 | 不阻塞任何新来者（直接并行加入）；也不被跨脚本打断 | ✅（缺省 = 0.3.6 现状） |
| `exclusive` | 独占 | 我播时其他脚本的启动请求一律**排队**，我播完按序接播 | — |
| `interruptible` | 可打断 | 我可被新来者**打断**（顶掉，实例销毁） | — |

- 取值域外/缺失 = `parallel`（旧脚本零回归）。
- 在播侧为轴：「只能他在播放、其他的都要排队」= `exclusive`；「其他的会直接把它打断」= `interruptible`；「并行播放多个脚本」= 双方 `parallel`。
- 与既有 `meta.interruptible`（bool）的关系：旧字段管**同脚本**再触发的替换语义 + 退出原因门控（requestExit 按 skippable/interruptible/hold_at_end 门控），保留不动；`play_mode` 管**跨脚本**关系。两者同名值 `interruptible` 语义同向（都是「可被打断」），文档与 schema 注释写明分工；是否合并字段 = §7 待拍板。
- `meta.priority` 保留（队列内排序）；既有口径「优先级不产生打断」不变——优先级只决定排队次序，不产生抢占。

#### 3. 队列语义（定稿；覆盖并扩展 F2）

| 项 | 定稿 | 说明 |
|---|---|---|
| 队列键 | 脚本 id | 同脚本第二次请求**替换**自己的排队位（不再占一格） |
| 跨实例存活 | **队列不随在播实例结束而清空**（修 §1-1 bug） | 接播按队列持续滚动；仅世界退出/forceDeactivate 清空 |
| 出队条件 | 阻塞它的 `exclusive` 实例全部结束 | 无 exclusive 在播 = 不排队（parallel 不阻塞） |
| 排序 | `meta.priority` 降序 + FIFO | `ScriptQueue`（PriorityQueue，不设容量上限） |
| 满容量 | 不设上限（consolidation 决策 8） | 第 9 项起也正常入队 |
| 接播形态 | 硬切起步（现状）；转场起步归 scene-transition | — |

`ScriptQueue` 需补「按脚本匹配」API（F2 原口径）：同键替换排队位、按脚本取消（E3）。

#### 4. 到达组合规则（新来者 B 到达时，按在播集合 S 裁决）

| S 的构成 | B 的去向 |
|---|---|
| 空 | 直接开播 |
| 仅 `parallel` | 直接并行加入（现状） |
| 含 `exclusive`（无论其它） | B **入队**（S 全部结束才接播） |
| 含 `interruptible` 且无 `exclusive` | B **打断**该 interruptible 实例（只顶它，S 里的 parallel 实例继续）后开播 |

- B 开播后，B 自己的 `play_mode` 对后续到达者生效。
- 同脚本再触发（单实例口径不变）：既有 `meta.interruptible` 路径（true→替换 / false→入队）保留；与 §3 队列键规则一致（false 时同键替换排队位）。
- 打断形态：默认**硬切**（现状）；渐出接 = `play_mode` 附加字段 `on_interrupt: "cut" | "fade"`（§7 待拍板）。
- 「等 A 播完再播 B」的串行意图用触发器 `requires`（script_played/started/completed，现状已有）表达，**不**新增队列原语。

#### 6. 冲突裁决与异常（保持现状 + 两处修复）

1. 共享资源裁决维持现状表（§1）；「主相机声明」（F1）不做。
2. **渐出 per-instance**（修 §1-3，C5-c 已落地）：`deactivate` 只淡出本实例的层（层持 owner token = 播放实例引用）；
