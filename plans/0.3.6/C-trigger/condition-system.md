# 判定规则（片段级条件与动作）

> 状态：实现中（判定规则 v1 的数据链、引擎、动作与退出模型已落地；判定源与部分动作参数未覆盖设计）
> 范围：片段级判定规则——条件与动作、两种形态、挂起语义、判定源、动作集、退出模型
> 关联：`docs/SCRIPT_FORMAT.md` §13、`docs/TRIGGER_TYPES.md`、`plans/0.3.6/C-trigger/trigger-conditions.md`、`plans/0.3.6/C-trigger/playback-relations.md`

## 一、摘要

判定规则是挂在片段上的「条件 + 动作」：片段执行期间持续判定，条件成立就执行一组动作——改播放路线、调参数、暂停恢复、退出、发声、发命令。两种形态：持续规则不冻结播放；阻塞规则在条件不成立时把本实例停住，条件成立或超时后继续并执行动作。规则是片段元数据，不新开轨道；等待点与判定点都由阻塞规则表达；暂停表示保持内容位置而不是冻结时钟；脚本播完按实际执行内容判定。

## 二、为什么做

### 2.1 问题

- 脚本是一条时间线播到底。要在播放中按玩家位置、朝向或相机状态改路线，只能把内容拆成多个脚本、用触发器在外部切换；切换点只能是脚本边界，做不到「到这个镜头时如果玩家在左边就换一条」。
- 「到某个时间点停下来，等一件事发生再继续」没有原语。为它新开一条轨道，会让轨道模型多出一类非内容对象，裁剪、循环、时间轴语义都要开特例。
- 暂停若按冻结时钟理解，需要维护挂起累计、恢复换算等一套时间账本；跨片段或时间门的恢复在冻结时钟下不可达，行为不可控。
- 结束若按墙钟与片段窗口末比较，内容比声明长就会被截断；再加一个兜底上限，等于承认判定不可靠。

### 2.2 目标

- 片段上可声明规则：条件成立执行动作；阻塞形态可挂起到条件成立或超时。
- 条件覆盖时间、位置、朝向、群系、维度、相机状态与玩家输入，并可用组合器嵌套。
- 动作只作用触发它的实例：改参数、加临时层、跳转、暂停恢复、退出、发声、发命令。
- 暂停期间内容位置不变，恢复从原位置继续；位置随握手包上报，服务端事件时间线按它推进。
- 播完 = 实际执行路径上没有剩余内容，不读时钟、不需要兜底上限。
- 非法写法在 validate 阶段报错；动作执行失败不中断播放。

### 2.3 非目标

- 不做变量系统与规则间接力（启用 / 禁用规则、设标记）。
- 不做同片段内容变体切换。
- 不做跨脚本动作（起播 / 排队 / 停止其它脚本）。
- 不做等待点轨道。
- 不做嵌套挂起：同一时刻只挂起一次，多条阻塞规则按声明顺序逐条生效。
- 不做外部模组注册自定义判定源与动作。
- 不做编辑器的规则可视化编辑。

## 三、方案

规则写在片段上，与关键帧平级，任意轨道的片段都能挂；片段活跃期内判定，片段结束即不再判定。规则有两种形态。持续规则在条件成立的那一刻执行动作，播放不冻结；触发方式可选边沿（假变真那一刻）或驻留（连续成立满若干秒）。阻塞规则在条件不成立时把本实例停住，条件成立或超时后继续并执行动作，超时走单独的超时动作。公共修饰：默认只触发一次（片段循环折返后重新计），可设冷却，触发后一段时间内不再触发。

条件的时间一项相对片段本地时钟，挂起期间不走；其余条件复用触发器那一套词汇——位置、结构、群系、维度、朝向与注视、实体、背包、经验、世界事件，另加播放侧新增的相机状态与玩家输入。条件可用任一满足 / 全部满足组合器嵌套。变量本期不做。判定在播放同端逐实例进行：多人广播时各看各的本地玩家与相机。

动作分几族：参数调整（相机参数、覆盖层、调色）、分支（跳到某个片段或时间点）、播放控制（暂停、恢复、退出）、媒体（声音、命令）。跨脚本动作与规则自控留给后续版本。动作只作用触发它的那个实例；要作用到别的实例，只能经跨脚本族显式表达。

暂停的边界：暂停期间后续关键帧不推进、片段不切换、时间条件与驻留计时不走。因此释放暂停的规则必须写在触发暂停的同一个片段里；运行期发现同片段已无释放者会自动解除并告警，校验器按同一口径提示。打断、跳过、强退不受挂起影响。

分支失败不传播错误、不中断播放：目标片段缺失、参数非法、中途被打断，都直接回到主支当前状态继续，回退目标恒为主支（分支无栈、不做嵌套恢复）。

退出分三族：人为干预（强退 / 跳过 / 投票跳过）按元信息开关；内容播完按执行事实自然结束，末尾驻留时停在最后一帧；规则里的退出动作是声明式退出，跳过末尾驻留。时间不是退出触发，脚本总时长只作统计与信息位。

## 四、技术细节

### 4.1 核心模型

- **规则**：不可变数据载体，持有形态（持续 / 阻塞）、条件原文、动作列表、超时动作、只触发一次、冷却、触发方式、驻留阈值与超时。条件与动作保留原始 JSON：本层只解析结构，求值归判定源、执行归动作集。
- **规则引擎**：每个播放实例一份；启动时按脚本把所有规则展开成槽位（片段活跃窗 + 规则 + 状态数组），每帧判定；持有挂起请求、动作工件与挂起出口判定。
- **判定源**：播放端的求值层，覆盖时间、区域、结构 / 群系 / 维度、朝向 / 注视、实体 / 背包 / 经验、世界事件、相机状态、玩家输入与组合器；几何与 id 匹配复用与触发器共享的几何核。
- **动作执行**：按动作类型分发；参数调整类产出工件，接入实例的覆盖链、覆盖层或调色层。
- **工件**：参数调整的实例级产物，记录回收时刻（所属片段活跃窗末），同类至多一件——再次触发即覆盖。
- **播放器**：时间轴读数、挂起位置、内容事实（每片段消费状态 + 已展开圈数 + 剩余内容计数）与内容位置查询。
- **服务端播放会话**：按（脚本, 实例）维护观看者、跳过投票与事件时间线基准；暂停期间不处理关键帧，暂停 / 恢复时按上报位置重定基准。

### 4.2 契约

- 规则在解析期建成，播放期只读；脚本替换 = 重建槽位，旧等待与工件一并作废。
- 槽位与状态数组归规则引擎，容量在启动与替换时一次性分配；帧内不新建集合。
- 挂起是实例级状态：阻塞规则与暂停动作共用同一个「停住」状态，但分开记账；解除顺序 = 条件成立、超时、恢复动作、挂起出口、引擎重建、停播。
- 动作工件归引擎：触发帧接入，片段活跃窗末、引擎重建、停播时回收。
- 内容事实归播放器：播放头推进时记录，路径变更时按新路径重导；判定侧只读剩余计数。
- 退出请求归播放生命周期：规则里的退出映射为自然结束并跳过末尾驻留；强退与全停不经渐出。
- 暂停位置由客户端计算并上报；服务端只在收到非空位置时重定基准。

### 4.3 数据形态

- 规则数组：元素 = 形态 + 条件 + 动作数组 + 可选修饰；形态二选一、互斥；动作数组至少一个；超时动作可省。
- 条件：与触发器条件同一份字段词汇；组合器用 `list`，元素 = `{ type, conditions }`。
- 挂起位置：二元组（片段起始秒, 片段内偏移秒）；无片段覆盖时起始秒为空、偏移为绝对秒；未上报时偏移为空。
- 内容事实：每片段一个状态（待进入 / 执行中 / 已消费完）+ 已展开圈数；剩余内容计数 = 尚未消费的片段数。有限循环片段要求圈数计满且窗口末到达；无限片段永不消费完。
- 工件：种类 + 回收时刻，按片段活跃窗末对齐。
- 脚本总时长保留为必填的统计 / 信息位，不参与结束判定。

### 4.4 边界

- 判定端在播放端，逐实例、每渲染帧；触发器仍在服务端。
- 动作只作用本实例，不改脚本定义（关键帧只读）。
- 时间条件相对片段本地时钟，挂起期间不走；冷却与持续规则的驻留计时走播放时钟；阻塞规则的超时与驻留计时走真实时钟。
- 暂停释放者必须在触发暂停的同一片段；跨片段、时间门、驻留门的恢复不可达。
- 无限内容（无限循环片段、负时长、无限宏观循环）永不「内容播完」，只能靠人为干预或声明式退出。
- 预览实例同样跑规则，但不参与服务端会话与账本。
- 与播放关系正交：规则可以暂停或退出本实例，但不起播、不排队、不停止其它脚本。
- 编辑器呈现与外部模组注册不在本期。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 新开等待点轨道 | 用一条轨道表示「在这里等事件」 | 轨道模型多一类非内容轨道；裁剪、循环、时间轴语义都要为它开特例 | 等待 = 阻塞规则，不新开轨道 |
| 冻结播放时钟的暂停 | 暂停时冻结时钟，记录累计挂起时长，恢复时补算 | 需要时间账本；跨片段与时间门的恢复不可达；行为不可控 | 改为保持内容位置，位置即真源 |
| 每帧比较播放时钟与片段窗口末 | 用已播放时间与各片段窗口末做数值比较判播完 | 内容比声明长会被截断；需要兜底上限，等于承认判定不可靠 | 按执行事实判定 |
| 规则在服务端统一判定 | 服务端求值、下发结果 | 多人广播时无法按各自玩家与相机判定；网络往返增加延迟 | 播放端逐实例判定 |
| 条件与触发器合并成同一 JSON 层 | 规则直接复用触发器的条件对象与动作面 | 触发器的动作是起播，规则的动作是实例内操作，合并后语义混乱 | 词汇同源、JSON 不合并 |
| 变量系统进 v1 | 规则里读写变量，互相接力 | 变量作用域、生命周期、持久化都要定义，范围失控 | 留后续版本 |

**本方案的缺点**：

- 规则只在播放端，服务端不知道规则状态（除暂停位置），做不了服务端权威的分支时序。
- 挂起会停掉全部轨（含事件轨），且释放者必须同片段；「等到很远之后的一件事」只能拆片段。
- 逐帧遍历所有规则，成本随规则数线性增长；深层组合器还会放大。
- 世界事件类判定源依赖服务端追踪器，与播放端判定之间存在同步窗口。
- 跳转按片段或时间点寻址，缺少稳定的片段标识时动作指向会随重排漂移。
- 失败静默（限频日志），作者不看日志很难发现动作没生效。
- 内容事实按片段粒度记账，片段内部的「部分执行」不区分。

#### 1. 概念与命名（主代理提案）

**定义**：挂在片段上的**条件判定 + 动作**规则——片段执行期间持续判定，条件成立则执行动作（改播放 / 分支 / 发声 / 控制…）。语义等价代码里的 `if` / `while` / `when`：判定成立 → 做事。

| 概念 | 命名（提案） | JSON | 备选（可否决） |
|---|---|---|---|
| 系统 | **判定规则**（judgment rules） | clip 上的 `rules` | 应变规则 / 条件规则 |
| 单条规则 | 规则（rule） | `rules[]` 一元素 | — |
| 条件部分 | 判定（if / until） | `if` / `until` | `when` / `condition` |
| 动作部分 | 动作（do） | `do: [...]` | `actions` / `then` |

选名理由：承接「判定点」血统（判定一词既有）；「规则」= 条件 + 动作成对，与 if/while 心智一致；JSON `rules[{if|until, do}]` 读作自然语句；与 `meta.triggers[].conditions`（纯谓词、无动作）**零撞名**。

#### 2. 两种规则形态（定稿：一套词汇、两种形态）

| 形态 | 结构 | 语义 | 判定节奏 |
|---|---|---|---|
| **持续规则** | `{ if, do, ... }` | 片段执行期内持续判定；条件**成立瞬间**（边沿）触发 `do` | 每帧（客户端） |
| **阻塞规则** | `{ until, do, timeout?, on_timeout? }` | 触发后**挂起播放时钟**，直到 `until` 成立才执行 `do` 并恢复；超时执行 `on_timeout` | 挂起期间持续判定 |

公共修饰字段（两条形态共用）：`once`（只触发一次，默认 true）、`cooldown`（触发后 N 秒内不再触发）、`mode`（`enter` 瞬时边沿（缺省）/ `dwell` 驻留成立才触发）。

**特例收编**：
- **判定点**（到时间点停下来判定 → 分支/继续）= 阻塞规则的时间条件：`{ until: {type:"time", at: T}, do: [分支/继续] }`；不停表的版本 = 持续规则 `{ if: {type:"time", at: T}, do: [...] }`。
- **等待点**（等到事件再走）= 阻塞规则：`{ until: <事件/状态条件>, do: [...] }`。
- 原 `wait-point-track.md` 的 WAIT_POINT **轨道**方案废弃（用户拍板：不新开轨道），其用例（死亡重生等）全部由阻塞规则表达；该文档标记被本篇吸收。

#### 3. 挂起（suspend）语义（阻塞规则运行期）

1. 挂起 = **本脚本实例的播放时钟冻结**（全部轨一起停，含 EVENT 轨时间线）；游戏世界、触发器、其它脚本实例照常。
2. 挂起期间：本片段的规则**继续判定**（这正是 `until` 的语义）；持续规则照常。
3. 解除顺序：`until` 成立 → 恢复时钟并执行 `do`；`timeout` 先到 → 恢复时钟并执行 `on_timeout`（两者都没有 = 无限等待）。
4. 挂起中的打断/跳过/退出：走既有生命周期（interruptible/skippable/forceDeactivate 门控不变）。
5. 多条阻塞规则同片段 = 顺序声明、逐条生效（同一时刻只挂起一次；嵌套挂起不做）。

**口径补记（2026-10-14 用户口径，`pause` 从「时间暂停」改为「执行状态暂停」）**：原先 `pause` 按「冻结播放时钟」理解，随之而来的是一整套时间账本（挂起累计秒 `suspendAccum`、跨片段 / 时间门的 `resume` 在冻结时钟下不可达等），**不可控**。按新理念（②族已改为「按执行内容判定」）改为**执行状态暂停**：

- **暂停时**：读本实例的**脚本执行状态**（执行到哪个片段、哪个分支、什么内容 / 哪些执行事实）并**上报服务端**（服务端据此知道客户端在 EVENT 时间线的哪一点，取代 `totalPausedTicks` 之类的墙钟推算）；
- **恢复时**：从该状态**接着续**（状态即真源，不需要时间换算）；
- **不再考虑时间**：挂起/恢复不依赖播放时钟冻结与累计时长 → **从不可控变可控**。

落地形态（实现时定）：执行状态 = ②族判定的同一份执行事实（片段 entered/completed、圈数、分支位置、事件游标）；上报 = 既有 C2S 暂停握手通道（`PlaybackLedger` / `ScriptEventManager.handlePause`）载荷改为携带状态；服务端 EVENT 时间线改为按状态推进而非 `elapsed` 推算。与 `state-tracking.md`（P1 事实追踪层）同族。

**状态表示细化（2026-10-14 用户口径）**：上报的状态 = **内容相对位置**，形如 **`(片段标识, 片段内偏移秒)`**——例：相机片段 3 起始 6s、持续 10s → 记「片段 3 的第 x 秒」。依据 = **脚本固定 + 全轨道共用一条时间轴**（A 轨某时刻必然对应 B 轨某时刻，一一对应）⇒ `(片段, 片段内偏移)` 唯一确定整脚本在所有轨道上的状态，**因此准确**；服务端回执（暂停/恢复握手）也据它执行——位置无歧义。取代「绝对播放时钟秒 + 挂起累计秒」那套账本。（**机制形态沿用已定稿**：§2「特例收编」早已把「等待点 / 判定点」内化为阻塞规则 `until→do`；`pause` = 「等待条件为外部 `resume`」的阻塞规则特例——本次改的只是「停住」的**表示**（内容位置）与时钟账本的退场，不新造机制。**前身参照**：`_archive/wait-point-track.md` §5.1/§5.2/§6 的等待点设计已含「冻结脚本时钟 / 各轨停在当前状态 / 后续关键帧不再推进 / 等待态与 `pause_when_game_paused` 是两个独立状态 / 音频托管 `pause_managed`」——本条与之同源，实现可参照。）

**落地（2026-10-14，C-pause）**：本条已实现，机制形态沿用已定稿（不新造机制）：

- **客户端状态表示**：`ScriptPlayer` 的 `suspendStartClock` / `suspendAccum`（时间账本）退场，改为单一 `heldElapsed`——挂起 = 记下挂起瞬间的内容位置，挂起中 `getElapsedSeconds()` 恒返回它，`endSuspend()` 以 `startGameTimeSeconds = clock − heldElapsed` 重定起始读数（挂起时长不累计、不补算）；`seekTo` / `alignTime` 基准随之改为真实时钟读数（挂起中定位改写保持的位置）。新增零分配的**内容位置查询** `contentPosition(float[])` → `(片段起始秒, 片段内偏移秒)`；无片段覆盖（片段间隙 / 空时间轴）= 起始秒 NaN + 偏移为绝对秒。
- **上报（载荷带位置）**：`C2SScriptPausePacket` 加 `positionClipStart` + `positionOffset`。**片段标识选型 = 片段起始时间**（不用「轨道类型 + 片段序」）：位置 = 起始 + 偏移，服务端无需回查脚本即可还原时间线坐标，同类型多轨（OVERLAY 多轨）不产生歧义、无索引 / 版本漂移面，也不引入 clip id 字段。**上报缺失回落 = 保持既有基准不动**（= 原 tick 推算，不卡事件；偏移为 NaN 即未上报）。
- **服务端时间线按状态推进**：`ScriptPlayback` 的 `pauseStartTick` / `totalPausedTicks` 退场，改为基准 `timelineAnchorSeconds` + `timelineAnchorTick`（读数 = 基准 + 其后服务端 tick）；暂停期间不处理关键帧，暂停 / 恢复转换帧按上报位置重定基准（`handlePause` 收位置参数）。
- **挂起出口（防卡死）**：`RuleEngine` 持有 `actionSuspendHeld` 且触发它的片段里（仍在活跃窗内）既无未完成的 `until`、也无仍可触发的 `resume`（`once` 已用完 / 冷却未过的不算）→ 自动解除 + 限频告警；`ScriptValidator` 同口径 issue（clip 声明 `pause` 但同 clip 无释放规则）。②族谓词的 `isSuspended()` 短路出口**保持**——有出口兜底后挂起不会永久存在。

#### 4. 判定源（词汇复用触发器条件 + 播放侧新增）

判定语法与取值**复用** `meta.triggers[].conditions` 一族（含 `all_of` / `any` 组合器与 `requires` 前置锁存思路）；实现上把求值器核下沉为共享库（触发器服务端与规则客户端共用同一 schema/语义）。

| 判定源 | 现状（触发器侧） | 规则侧 | 归属 |
|---|---|---|---|
| 时间点/区间 `time` | 无（仅 EVENT 到点） | **新增**（相对片段时钟；挂起期间不走） | 客户端 |
| 区域 `location`（AABB/球） | ✅ Evaluators | 直接复用 | 客户端取本地玩家 |
| 结构/群系/维度 | ✅ | 复用 | 客户端可判（已加载）/服务端兜底 |
| 朝向/注视 `facing`/`observation` | ✅（只读玩家） | 复用 + 扩相机朝向 | 客户端 |
| 实体/背包/经验 `entity_*`/`inventory`/`xp` | ✅ | 复用 | 客户端 |
| 世界事件（击杀/交互/拾取…8 类 tracker） | ✅（单槽） | 复用 | 服务端 tracker → 报文 |
| 相机状态（位置/朝向/look_at 目标/FOV） | 无 | **新增** | 客户端 |
| 玩家输入（按键/点击） | 无 | **新增**（v1 可缓） | 客户端 |
| 变量 | 无变量系统 | **不做 v1**（§9） | — |
| 其它脚本/实例状态（在播/已完成） | ✅ requires 族 | 复用 | 服务端账本 |

判定归属 = **播放同端**（客户端逐实例求值；多人广播脚本各看各的本地玩家 = 个人化运镜的自然语义）。命令类动作仍走服务端 EVENT 口径。

##### 5.1 分支与回退语义（定稿 2026-10-10 用户口径）

分支条件达成 → 执行分支（`goto_clip` / `switch_variant` 等改变播放路线的动作）。**分支执行不成功或中间出现纰漏 → 自然回退主支**：

- **主支 = 完整基线**：主线路（未被分支改动的播放路线）永远是完整、有效的定义状态；分支 = 有条件偏离。
- **失败即回主支**：分支执行期间的一切异常（目标片段缺失/未定义、动作失败、数据非法、中途被打断/跳过、状态不可恢复）都不传播错误、不中断播放——直接回到主支当前状态继续。
- 与现有「目标不可用 → 片段按空处理」的 fail-safe 基调一致：保完整、不卡死；回退进日志（限频）供作者排查。
- 回退目标恒为**主支**（不是上一层分支）：分支无栈、不做嵌套恢复——与 §3-5「嵌套挂起不做」同口径。

#### 6. 与既有概念的关系（定稿图）

```
判定规则（clip.rules：if→do 持续 / until→do 阻塞）
 ├─ 判定点    = until/if 的 time 条件特例（停表或不停表两版）
 ├─ 等待点    = 阻塞规则（挂起直到条件）——wait-point-track.md 被本篇吸收
 ├─ 触发器    = 脚本「启动」侧的条件（外部事件→起播；词汇同源、动作面不同）
 ├─ 循环体    = 时间条件的周期化（每圈重判；clip.loop 与规则正交）
 └─ 前置条件 requires = 起播前锁存判定（不变）
```

#### 8. 边界与预留

##### 8.1 退出模型（定稿 2026-10-10 用户口径；取代原「脚本退出机制」预留）

退出 = **条件集**，三族（用户口径：跳过/打断/投票跳过是默认条件之一；自动退出不按时间走）：

| 族 | 条件 | 控制字段 |
|---|---|---|
| ① 默认·人为干预 | 强制退出 / 跳过 / 投票跳过 | `skippable` / `skipVoteRatio` / `interruptible`（既有，不动） |
| ② 默认·内容播完 | **全部内容消费完毕**：所有轨片段走到尽头 + 循环次数耗尽（`loop_count` 展开计数）+ 在跑分支完成 | 无（脚本自带） |
| ③ 声明·条件退出 | `exit` 动作 / 分支执行完直接退出 / `until` 等待点内直接退出——全走判定规则词汇（§5「播放控制」族） | `clip.rules`（不新开 meta 字段） |

- **时间不再是退出触发**：`total_duration` 降级为统计/信息位（记录、真同步、补帧参考），兼可选兜底上限（防内容状态算漏卡死，到点限频告警后退出）；分支比「脚本时长」长 → 继续播完（内容驱动，不截断）。
- **内容完成度统计 = 内部状态追踪**（`state-tracking.md` 事实追踪族）：每实例维护各轨 clip 消费窗口 + 循环计数 + 分支/挂起状态；自然结束谓词 = 全部内容终点到达且无挂起/分支在跑。**按内容点判定、不按墙钟**（时间误差不参与）；统计细节归 C 批任务书细化。
- 与既有 `ExitReason`（FORCE_QUIT/SYSTEM_STOP/INTERRUPTED/USER_SKIP/NATURAL_END）：①族映射既有五值不变；②③族归 NATURAL_END，保持五值不扩。
- `hold_at_end` 不变（自然结束后驻留至干预退出）；`macro_loop` 无限圈永不「内容播完」→ 只能 ①/③ 退出——「循环 + 条件退出」即「播到 X 发生为止」的干净组合。

**落地（C6-4 首版 2026-10-14 → 当日修订）**：首版②族谓词 = 每帧拿播放时钟 `elapsed` 与各 clip `getWindowEnd()` 数值比较（+ 圈数 + `!isSuspended()`），`isFinished()` = 内容谓词 ∨ 兜底上限（新 meta `exit_on_duration_overrun`，缺省 false = 只告警）。
**修订（2026-10-14，按用户口径「做成可靠底层判定、不靠兜底」）**：改为**执行事实判定**——`ScriptPlayer` per-clip 消费状态槽（`CLIP_PENDING` 未进入 / `CLIP_ACTIVE` 执行中 / `CLIP_CONSUMED` 无剩余内容，`byte[]` 扁平片段序）+ 剩余内容计数 `remainingContent`；事实在播放头推进时记录（`recordContentFacts`：片段进入 / 消费完 / 圈数计满）、**路径变更时重导**（`rederiveContentFacts`，挂在 `alignTime` 上 → `goto_clip` 跳转 / 编辑器 seek / 首个基准全覆盖）；谓词 `allContentConsumed()` 只读 `remainingContent == 0`（**O(1)、不读时钟、零分配**）。有限片段消费完 = 消费窗口末到达（⇒ 其 EVENT 关键帧事件必已执行）且有限循环展开圈数计满；无限片段恒不消费完；挂起中恒 false。宏观循环路径未动。
**兜底上限删除**：`meta.exit_on_duration_overrun` 整体移除（字段 / `RuntimeBehavior` / 解析 / schema / 判定分支），validator 对出现该字段**报错「已移除」**（负例已验）；`total_duration` 保持必填（统计 / 真同步），validator 口径不变；「内容比声明长」降级为限频**诊断提示**（非机制）。`getRemainingTime()` 语义 = 距内容终点；`hold_at_end` 走 ②族同一路径（`FrameDriver` 的 `requestExit(NATURAL_END)` 仍按 `hold_at_end` 拒绝，声明式 `exit` 才跳过）。
**已落地（2026-10-14，C-pause）**：`pause` 改「执行状态暂停」模型（§3 补记末「落地」小节）；②族的 `isSuspended` 短路出口**保持**——同片段无释放者的 `pause` 由挂起出口自动解除 + 限频告警，挂起不再可能永久存在。

**口径补记（2026-10-14 用户口径，修正②族判定依据）**：**②族「内容播完」要做成可靠的底层判定，不靠兜底上限**。依据 = 脚本的**固定内容结构**——格式固定、内容固定、循环执行次数固定、分支各走各的路径；因此「完成」= **实际执行路径上已无剩余可执行内容**（当前播放位置之后没有片段、没有事件、没有待完成的循环圈数、没有在跑的分支），任一分支路径都有自己的终点（「后面没有东西」那一刻）。**按执行内容判定完毕是相对准确的**。

- 与现实现的差距：`allContentConsumed()` 现在是**每帧拿播放时钟 `elapsed` 与各 clip `getWindowEnd()` 做数值比较**（+ 圈数 + `!isSuspended()`），属「时钟 vs 窗口末」；本条要求的是**执行状态判定**（哪些片段已执行到尽头、圈数已计满、分支已完）——正是本节正文「内容完成度统计 = 内部状态追踪（`state-tracking.md` 事实追踪族）」的落点。修复方向按此定：②族判定改为消费**执行事实/执行状态**，而非时钟阈值比较。
- 兜底上限（`total_duration`）因此**不是机制的一部分**（正文称其「防内容状态算漏卡死」——底层判定可靠后该网不必要；其存在本身即「判定不可靠」的自认）。
- 连带：本条把②族的正确落点指向 `state-tracking.md`（P1 事实追踪层），与 `P1-impl` 同族。

2. 与「运行时只读只执行」原则的边界：规则动作改的是**实例运行时状态**（参数叠加/播放位置），不改脚本定义（keyframes 只读）；`switch_variant` 若引入内容变体，变体集仍是定义数据、只读。
3. 编辑器呈现（规则的可视化编辑/预览）归编辑器阶段，不在 C 批实现范围。
4. 外部模组注册自定义判定源/动作（`modid:name` 式）留 v2（与 PrerequisiteRegistry 同族思路）。
