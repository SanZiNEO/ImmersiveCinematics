## 一、摘要

点源 = 来源 + 偏移 + 表达空间 + 时态。时态两值：实时（逐帧重取，缺省）与快照（首次取到后冻结）。开关只对实体选择器形态生效，静态来源天生恒定、写了无效果。快照按片段与调用点分桶：片段内取一次，编辑器定位重取，循环折返延续，过渡两侧各持各的。它让「跟随某实体、但从这个镜头起参考点冻在当时位置」成为可表达的镜头。

## 二、为什么做

### 2.1 问题

- 同一个点源的行为由写法暗中决定：写坐标就恒定不动，写选择器或玩家就逐帧跟随。动静不是显式选择，而是类型自带的隐含行为。
- 「跟 / 看某个实体，但从这个镜头起参考点冻在当时位置」这类镜头做不出来——只能硬写坐标，实体一动就穿帮。定机位环绕、构图锁定、相对生物的定格取景都属于这一类。
- 动静规则散落在各类型语义里，作者要记住「哪种来源会动」，不统一。

### 2.2 目标

- 点源上有一个显式时态值：实时或快照，缺省实时。
- 快照 = 首次取到的点冻结，之后该片段的每一帧读同一份；实体移动画面不动。
- 实时 = 逐帧重取，与升级前逐位一致。
- 不写时态值的脚本行为零变化。
- 静态来源写时态无效果，校验给出提示。

### 2.3 非目标

- 不扩到运动模型的输入（另一条线）。
- 不迁移、不改名既有字段（跟随与注视字段保持原样）。
- 不新增点源形态。
- 不做整脚本级的全局时态开关。
- 不改变点源取点与偏移的语义。

## 三、方案

在点源字段旁写时态：缺省实时；写快照表示「这个片段第一次取到的位置就是它」。快照的时点是片段开始时取一次；选择器异步解析的，在首次解析成功那一帧取。编辑器拖动播放头（定位）时重新取；片段循环折返不重取（延续）；过渡两侧各用各的快照。

适用范围是点源本身：位置基准、基准朝向目标、连线起止端点、注视点、选择器锚点的原点，都可以写时态。坐标、方块、结构、玩家激活位置这些来源天生恒定，写时态没有效果，校验会提示。

与跟随的关系：跟随实体是「实时」在特定字段上的表现，不再是独立语义；字段不动，理解上统一。玩家形态的语义是激活位置在整场播放中不变（等价快照）；需要逐帧跟随玩家时用选择器。

边界：时态只影响参考点的取法，不影响镜头运动模型、不影响偏移计算、不影响过渡曲线。

## 四、技术细节

### 4.1 核心模型

- **点源规格**：形态（玩家激活位置 / 固定坐标 / 实体选择器 / 方块 / 结构）+ 偏移（世界轴或基准坐标系）+ 时态。
- **快照表**：按片段身份 + 槽位分桶缓存已展开偏移的取点，值 = 世界空间坐标。
- **解析器**：点源求值入口；快照模式下读本片段该槽位的快照点，快照点在片段开始时捕获。
- **轨道播放器**：持有快照表，负责在定位、停止、脚本替换时清表；循环折返不清。
- **关键帧求值器**：求值前注入当前片段；过渡两侧各注入自己的一侧。
- **校验器**：时态取值枚举检查；静态来源写时态的提示。
- **字段表**：五个点源字段各配一个时态字段。

### 4.2 契约

- 快照表由轨道播放器持有，生命周期 = 所属轨道；停止、脚本替换、定位时清空。
- 桶键 = 片段引用 + 槽位；同一片段的所有帧读同一桶；过渡两侧的片段各自成桶。
- 快照在片段开始时捕获；选择器异步解析的，在首次解析成功那一帧捕获。解析为空不写入，继续等待下一次解析。
- 时态只对实体选择器形态生效；静态来源即使写了也按实时路径求值。
- 循环折返不重取（状态延续）；定位（硬定位）重取；脚本替换重取。

### 4.3 数据形态

- 时态字段 = 点源字段名 + `_time`，取值 `live` / `snapshot`，缺省 `live`；未知值运行期按 `live` 处理，校验报错。
- 五个字段：`facing_origin_time` / `facing_target_time` / `yaw_base_from_time` / `yaw_base_to_time` / `look_at_time`。
- 快照值 = 已展开偏移的世界坐标；未捕获 = 无表项（不存空值）。
- 槽位按点源调用点划分：位置基准、基准朝向目标、连线起点、连线终点、注视点、锚点原点。锚点原点单列一槽，因为同一位置点源在锚点调用点固定按相机锚点解析，与位置基准的配置锚点可以不同。

### 4.4 边界

- 只对实体选择器形态生效；坐标、方块、结构、玩家激活位置天生恒定。
- 玩家激活位置整场不变，是快照语义；逐帧跟随用选择器。
- 不扩到运动模型输入；跟随与注视字段不迁移、不改名。
- 快照只冻结参考点，不冻结偏移；偏移在取点时展开后一并冻结。
- 过渡两侧各持各的快照，互不污染。
- 预览实例与正式播放走同一套时态逻辑。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 新增「冻结选择器」点源形态 | 用另一个形态字符串表示冻结 | 形态数量翻倍；每加一种来源都要同时加冻结版；判据与文档膨胀 | 时态是独立一维，不复制形态 |
| 整脚本级全局开关 | 元信息里一个开关，整脚本的点源一起冻结 | 同一镜头里无法一部分跟随、一部分冻结 | 按点源逐字段控制 |
| 每帧保存历史点 | 环形缓冲保存每帧取点，按时间回溯 | 内存与分配随帧数增长；回溯时刻的语义难定义 | 首次捕获，一份值 |
| 把玩家激活位置也改成实时跟随 | 让玩家形态逐帧读玩家位置 | 改变既有脚本的逐位行为，违反「缺省 = 现状」 | 保持激活位置，实时跟随用选择器 |
| 用实体 id + 世界坐标做缓存键 | 按实体与位置缓存取点 | 片段切换与重排要额外失效判断，容易串味 | 按片段引用分桶，失效边界清晰 |

**本方案的缺点**：

- 捕获是惰性的，不是严格的「片段第一帧」；点源写在片段中段时，捕获时刻 = 首次求值。
- 快照表按片段引用线性扫描，片段多时每次求值都要扫；槽位固定，新增点源字段要加槽。
- 快照只覆盖选择器，玩家激活位置无法实时跟随（要用选择器，字段语义不同）。
- 定位会重取快照：编辑器里拖动播放头与正式播放可能取到不同的点。
- 偏移在捕获时展开并冻结，基准坐标系变化不再影响快照点——可能是想要的，也可能是陷阱。
- 同一选择器在两个片段各取一次，可能得到不同点，没有跨片段共享。

#### 1. 问题

同一个「点源」（玩家 / 坐标 / 选择器 / 方块 / 结构 + 偏移 + 表达空间），行为却由写法暗中决定：

- 写坐标 = 恒定不动；
- 写选择器 / 玩家 = 逐帧实时跟随。

于是「**跟/看某实体，但从这个镜头起参考点冻在当时位置**」这类镜头（定机位环绕、构图锁定、相对生物的定格取景）做不出来——只能硬写坐标，实体一动就穿帮。且动静规则散落在类型语义里，不统一。

#### 2. 口径（定稿）

**来源 × 时态 二维**：点源 = 来源 + 偏移 + 表达空间 + **时态**（本篇新增的一维）。

| 来源形态 | 时态 = 实时（缺省） | 时态 = 快照 |
|---|---|---|
| 坐标 / 方块 / 结构 | 天生恒定，写不写无差 | 同左（无意义） |
| 玩家（WORLD 形态） | ~~跟着玩家走~~ **〔2026-10-14 修正：代码现状 = 玩家激活位置、整场不变（等价快照语义）；实时跟随 = 选择器 `@p`，见 §8〕** | 冻在取快照那一刻的玩家位置 |
| 实体选择器（SELECTOR） | 跟着实体走（= 跟随语义） | 冻在首次解析到的位置 |

- **缺省 = 现状**：玩家/选择器类缺省实时，坐标类天然恒定；不写这个值的脚本逐位零变化。
- **统一性**：follow / look_at 跟实体 = 「实时」档在特定字段上的表现，不再是独立语义。**理解上统一、字段不动**——follow/look_at 现有字段不迁移不改名（避免复杂化，见 §4）。
- 用户示例（拍板依据）：相对生物点源——开关关 = 第一次取到相对位置后固定；开 = 一直取、一直更新（即跟随）。

#### 3. 边界规则（定稿，三条）

| 边界 | 规则 | 依据/类比 |
|---|---|---|
| 快照时刻 | **clip 开始取一次**；选择器异步解析的 = 首次解析成功那帧取 | 「clip = 片段」语义 |
| seek（编辑器拖播放头） | **重取快照** | B16 拍板「seek = reset」同口径（seek = 硬定位、状态归零） |
| loop 折返 / morph | loop 折返**不重取**（延续）；morph 两侧**各用各的快照** | 与运动模型 macro loop「状态延续」口径一致；morph = 两个片段各持状态 |

#### 4. 范围限定（防复杂化）

1. 开关只管**点源**（follow 位置 / look_at 系 / yaw_base_from·to 端点 / facing_origin·facing_target / 位置基准 / selector_anchor 的 origin）；
2. **不扩到 motion 模型输入**（那是另一条线，混入即复杂化）；
3. 现有字段**不迁移不改名**——本开关是给点源对象加一维，不是重构既有字段；
4. 坐标/方块/结构类不需要写该值（写了也无效果，validator 可提示）。

#### 5. 字段形态（已落地）

- 点源字段配套 `<字段>_time` 枚举：`facing_origin_time` / `facing_target_time` / `yaw_base_from_time` / `yaw_base_to_time` / `look_at_time`，取值 `"live" | "snapshot"`，缺省 `"live"`（未知值回落 live + validator 报错）；
- 仅对 SELECTOR 形态生效（§2 WORLD 行修正 + §4.4）；静态来源写时态 = 无效果 + validator 提示。

#### 9. 补记：点源形态注册可扩展性（2026-10-14 用户口径）

**点源形态要方便后续注册新增**。未来可能新增点源形态——例如「扫群系、读群系地表、出一套坐标组，根据坐标组自动运镜」这类来源；现在不做，但 PointSource 的形态定义/解析/判据/schema 写法必须让后面新增形态时**注册成本低**（不要每加一个形态就到处改）。

落地口径：

1. 求值分发在 `EntityTargetResolver.resolvePointSource` 的 switch——新增形态难免动这里（求值逻辑所在），但**解析/判据/schema 侧**（`PointSource.parse` / `PositionData.originKindOf` / `PointSource.kindOf` / TrackSchemas 字段）应尽量收敛在少数注册点，加形态 = 加一处 case + schema 行，不动消费方。
2. C7 快照门是显式 `kind() == SELECTOR` 单点判定（v1 裁定范围）；槽位表/快照存储本身形态无关（按 clip+slot 分桶）。未来新形态若是「解析一次恒定」类型天然不需要快照；若是「实时扫描」类型想冻结，放开对应 Kind 即可——扩展点保持开放。

此为**记录口径**，不改已提交代码（当前实现已满足：快照门单点、槽位表形态无关、解析集中在 PointSource.parse 一处）。真正实现「群系地表坐标组」点源时另立任务书。
