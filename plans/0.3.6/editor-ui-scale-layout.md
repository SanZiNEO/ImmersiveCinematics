# 0.3.6 编辑器界面缩放与布局方案

**状态**: 📋 计划，未实现
**目标版本**: 0.3.6
**最后更新**: 2026-08-22

> 本文只记录 0.3.6 编辑器界面缩放/布局的方向，不涉及 0.3.5。
> 参考：LDLib（全局 GUI Scale 菜单）、本地 bbs 模组（临时改 GUI Scale + 关闭恢复）。

---

## 1. 问题

- 编辑器当前界面大小固定，跟随 MC 的 GUI Scale，体感不好
- 用户想要“编辑器内调整界面尺寸”，且不影响关闭编辑器后的游戏 UI
- 之前做过“缩放对冲”，坐标换算太痛苦
- 还想要面板可拖动边缘调整大小 / 停靠布局

---

## 2. 缩放方案（采用 bbs 思路）

bbs 的做法：

- 编辑器打开时：
  - 保存当前 `options.guiScale`
  - 设置为编辑器自己的 `editorGuiScale`
  - 调用 `onResolutionChanged()`
- 编辑器关闭时：
  - 恢复保存的 `options.guiScale`
  - 调用 `onResolutionChanged()`

优点：
- 所有渲染/鼠标/滚动由 MC 统一处理，不需要手动“缩放对冲”
- 关闭后不影响游戏 UI
- 实现成本低

缺点：
- 编辑器打开期间，全局 GUI Scale 会临时变化（编辑器通常是全屏界面，可接受）

### 配置

- 新增 `editorGuiScale` 配置（0=自动，1/2/3…）
- 可在编辑器菜单里调整，类似 LDLib 的 Window Size

---

## 3. 布局方案（单独做）

缩放只解决“整体大小”，不解决“布局可调”。

目标：
- 面板可拖动边缘改变大小（splitter）
- 组件可靠边停靠（类似 IDE）
- 布局不超出屏幕边界
- 布局响应式：窗口变化时自动适配

建议分阶段：
1. 先做简单分割条（左/右/上/下可拖大小）
2. 再做布局预设（几种固定布局切换）
3. 完整 docking 停靠系统放后面

---

## 4. 实施步骤（0.3.6）

1. 新增 `editorGuiScale` 配置
2. 编辑器打开/关闭时临时切换 GUI Scale（bbs 方案）
3. 编辑器菜单加“界面大小”选项
4. 布局：抽离当前固定布局，改为基于实际 `getGuiScaledWidth/Height` 计算
5. 布局：加分割条，支持拖拽调整面板大小
6. 布局：加布局预设
7. 持久化：记住用户上次的布局/缩放

---

## 5. 不做的

- 不做“完全独立缩放”（自己维护一套坐标系）——容易重蹈缩放对冲覆辙
- 不排入 0.3.5
