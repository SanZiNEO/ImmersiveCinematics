# 失败分层与外部依赖

> 状态：J-2 已实现（捕获/解码/视频音轨）；J-3/J-4 的预览编码与导出降级未实现
> 范围：ffmpeg 缺失/不可执行、坏文件、解码失败、seek 超时、资源回收与日志限频
> 关联：`playback.md`、`decode.md`、`preview-stream.md`、`export.md`、`../F-playback/failure-handling-audit.md`

## 一、摘要

媒体链路的所有失败都收敛为“错误纹理 / 最后一帧 + 限频日志 + 资源回收”，不崩客户端、不抛异常到脚本层、不留下僵尸进程或半开管道。

## 二、为什么做

### 2.1 问题

- 视频链路引入外部进程、网络、文件三类失败源，任何一类都可能把客户端拖死。
- 现有失败处理审计里已经有一批空 catch 与资源泄漏；媒体会新增同类风险。
- 错误不可定位时，作者只会看到黑屏或卡死。

### 2.2 目标

- 任何失败都有明确错误态：错误纹理或最后一帧，加一行可定位日志。
- 进程、管道、纹理、缓存句柄在失败路径上也释放。
- 日志限频，避免坏文件刷屏。
- 关闭幂等，重复关闭不报错。

### 2.3 非目标

- 不自动修复坏文件、不自动转码。
- 不做错误重试风暴；超过重试次数即标记不可用。
- 不把错误抛给脚本作者处理。

## 三、方案

### 3.1 错误分类与回退

| 场景 | 行为 |
|---|---|
| ffmpeg 不存在/不可执行 | **不是错误态**：标记「无 FFmpeg」能力位；WebUI 预览退回原始 RGBA；**视频素材什么都不显示**（有什么显示什么；不占位、不报错、不阻塞其余轨道）；导出不可用；限频日志一次；不崩 |
| 文件不存在/扩展名不支持 | 加载期错误纹理；validator 只做扩展名/路径检查，不要求 ffmpeg 在场 |
| 解码中途失败/进程退出 | 停进程、清队列、显示最后一帧或错误纹理；记录退出码与 stderr 尾部 |
| seek 超时 | 强制结束进程，回退最后一帧；下一次 seek 重新启动 |
| 预览客户端慢 | 丢最旧帧、计数、降级；不阻塞其他会话 |
| 远程分片（不做） | 2026-11-08 裁决不做，无此路径 |
| 关闭/退出 | 停进程、关管道、释放纹理/缓存；不留僵尸进程 |

### 3.2 资源回收

- 关闭顺序固定：停解码线程 → 停进程 → 关管道 → 清队列 → 释放纹理/缓存。
- 关闭幂等：重复调用不报错、不重复释放。
- 世界退出/编辑器关闭时统一回收该实例的所有媒体资源。
- 进程管理：记录 PID 与启动时间；异常退出时清理残留。

### 3.3 日志

- 同类错误按固定间隔限频（例如每分钟一条），附媒体路径与错误码。
- stderr 只保留尾部若干行，避免日志爆量。
- 错误日志包含可定位信息：文件、阶段（探测/解码/seek/传输）、退出码。

## 四、技术细节

### 4.1 核心模型

| 对象 | 职责 |
|---|---|
| 媒体错误态 | 错误码、阶段、文件标识、是否可重试 |
| 资源回收器 | 进程/管道/纹理/缓存的统一释放顺序 |
| 日志限频器 | 按错误键与时间窗限频 |

### 4.2 契约

- **创建**：错误态在首次失败时创建，绑定到图层/会话。
- **销毁**：图层/会话关闭时一并释放；错误态不跨实例共享。
- **状态归谁**：错误态归图层/会话；限频器可按进程或全局持有。
- **重试**：解码失败不自动重启（seek 除外）；远程分片不做，无重试链路。

### 4.3 数据形态

- 错误码：枚举（缺依赖/文件错误/解码错误/超时）。
- 错误日志字段：媒体标识、阶段、退出码、stderr 尾部。
- 重试计数：远程分片不做；解码失败计数只进限频日志。

### 4.4 边界

- 不修改脚本语义；错误纹理属于图层表现。
- 不把错误抛给规则/脚本执行层。
- 不把失败当成“媒体不存在”静默跳过：至少一次可定位日志。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| fail-fast 直接崩 | 失败即抛异常/退出 | 一个坏素材毁掉整场播放 | 降级 + 错误纹理 + 日志 |
| 无限重试 | 失败就重试 | CPU/进程风暴，日志刷屏 | 有限重试 + 标记不可用 |
| 静默跳过 | 失败不显示任何东西 | 作者无法定位；黑屏无解释 | 错误纹理 + 一行可定位提示 |

**本方案的缺点**：

- 错误纹理的观感差，但比黑屏/崩溃可诊断。
- 限频日志可能掩盖连续错误的具体次数。
- 进程清理依赖平台进程语义，Windows/Linux 行为需分别验证。

## 六、实现结果

状态：已实现（2026-11-08，J-2）。

- 缺 ffmpeg / ffprobe：`Ffmpeg.available()` 判定；视频图层 `unavailable=true`，`render` 直接返回（不占位、不报错），`ErrorLog.warnRateLimited` 5s 一次；其余轨道不受影响。
- 坏文件 / 解码失败：`VideoProbe` 返回 null 或解码未产出帧 → `markError`，画共享错误纹理，限频日志（5s）带路径与原因。
- 解码进程退出：`VideoDecoder` 的 stderr 线程保留尾部 8 行；EOF / 异常退出置 `ended`；非零退出码与 stderr 尾部进限频日志。
- seek：`seek()` 内部 stop → `join(1000ms)` → `destroyForcibly()` → 清队列 → 重启；重启期间保留当前纹理（不闪黑）。
- 回收：`close()` 幂等（解码器 / 纹理 / 音轨）；50 次启停探针通过，探针退出后无残留 ffmpeg 进程。
- 日志：统一 `ErrorLog`（`logRateLimited` / `warnRateLimited`），视频路径 5s，探测 60s。
