# 媒体验收矩阵

> 状态：未实现
> 范围：播放、解码、音频、预览流、传输、失败降级与真实机器检查
> 关联：`playback.md`、`decode.md`、`audio.md`、`preview-stream.md`、`transport.md`、`degrade.md`

## 一、摘要

本页只列“怎么算过”，不重复各篇语义。每项写方法、通过标准；实现完成后在本页补实测结果。

## 二、为什么做

### 2.1 问题

- 媒体能力依赖外部进程、网络、真实文件，单测覆盖不了播放观感与资源回收。
- 各篇独立验收，容易出现“单篇过、组合崩”。

### 2.2 目标

- 每篇有可执行的验收项，且能在真实客户端上复现。
- 失败路径与正常路径同等验收，不只测成功。
- 组合场景（多视频同屏、seek、循环、morph、远程拉取）有明确通过标准。

### 2.3 非目标

- 不做性能基准的长期跟踪；只记录单次实测。
- 不验收导出/编码能力（不在本能力范围）。

## 三、方案

### 3.1 验收分层

| 层 | 测什么 | 方式 |
|---|---|---|
| 单元/契约 | 路径解析、扩展名分流、分片校验、队列边界 | 无头探针 + 构造数据 |
| 客户端播放 | 首帧、时间跟随、暂停/seek/循环、morph 两侧 | 真实客户端 + fixture 视频 |
| 资源与失败 | 缺 ffmpeg、坏文件、seek 超时、断线、关闭幂等 | 故障注入 + 进程/句柄检查 |
| 预览流 | 编码、PTS、背压、丢帧、关键帧、慢客户端 | 双客户端 + 限速 |
| 传输 | 分片、校验、续传、缓存淘汰、白名单 | 本地服务端 + 断网 |
| 真实机器 | Fabric/Forge、光影、跨维度、多视频同屏 | 实机日志 + 截图 |

### 3.2 验收项

| # | 项 | 方法 | 通过标准 |
|---|---|---|---|
| P1 | 首帧 | 播放 fixture 视频，记录首帧时间 | 首帧可见；错误纹理不出现；日志无异常 |
| P2 | 时间跟随 | 暂停/恢复/seek 到任意点 | 画面帧与 `localTime` 对应；无累计漂移 |
| P3 | 循环 | 片段 `loop` 多圈 | 每圈从头播放；不读墙钟；不累积偏移 |
| P4 | morph 两侧 | 两段视频 morphi | 两侧各按自己的局部时间取帧；过渡只混合 |
| P5 | 图层参数 | 改 `x/y/scale/opacity/z_index` | 与图片图层行为一致 |
| C1 | 捕获一致性 | 同一时刻预览与导出各取一帧 | 像素内容一致；尺寸/格式一致 |
| C2 | 捕获尺寸 | 配置 1280×720、1920×1080、2560×1440 | 输出尺寸固定；窗口缩放不影响 |
| C3 | PTS | 录制/预览各取 10 帧 | PTS 单调；与脚本局部时间对应 |
| E1 | 录制首帧/时长 | 固定脚本录制 | 首帧正确；时长/帧数与目标 fps 一致 |
| E2 | 目标 fps 采样 | 实时帧率高于/低于目标 fps | 高则丢中间帧；低则丢帧不拉长时长 |
| E3 | 音频混音 | 含音频录制 | 音频轨存在；与画面同一时间轴 |
| E4 | 取消/失败收尾 | 中途取消、编码进程被杀 | 标记取消/失败；半成品删除；无残留进程 |
| D1 | 解码链路 | 正常视频连续播放 | 队列有界；内存不随时间增长 |
| D2 | seek 重启 | 长 GOP 视频 seek | 超时后回退最后一帧；不越界读旧帧 |
| D3 | 线程边界 | 解码中拖动/暂停 | 渲染不阻塞；无半帧撕裂 |
| A1 | 音频格式 | WAV/OGG/mp3/aac | 按扩展名解码；时间跟随片段 |
| A2 | 视频音轨 | 带音轨视频播放 | 默认静音；抽取后 AUDIO 轨可播 |
| V1 | 预览编码 | 本地预览 | 编码帧 + PTS；首帧从关键帧开始 |
| V2 | 背压 | 慢客户端 + 正常客户端 | 慢端丢帧/降级；正常端不受影响 |
| V3 | 暂停/恢复 | 预览暂停再恢复 | 暂停停编码；恢复从当前播放头取关键帧 |
| T1 | 分片拉取 | 远程客户端请求媒体 | 分片大小在 16–64 KiB；单包不超限 |
| T2 | 校验 | 篡改分片/整文件 | 坏片重拉；整文件不匹配则丢弃重下 |
| T3 | 续传 | 拉取中断后重连 | 从缺片继续；不重传已完成分片 |
| T4 | 缓存 | 多文件/超上限 | LRU 淘汰；正在播放的不删 |
| T5 | 白名单 | `..`、绝对路径、非白名单扩展名 | 服务端拒绝；客户端显示错误纹理 |
| F1 | 缺 ffmpeg | 改配置指向不存在路径 | 错误纹理 + 限频日志；脚本仍加载 |
| F2 | 坏文件 | 截断/损坏视频 | 解码失败回退；无僵尸进程 |
| F3 | seek 超时 | 构造卡死进程 | 强制结束；下一 seek 可恢复 |
| F4 | 断线 | 传输中断网 | 保留已校验分片；重连续传 |
| F5 | 关闭幂等 | 重复 close/世界退出 | 无异常；进程/纹理/句柄清零 |
| R1 | Fabric | 实机加载/播放/预览 | 无异常；资源回收正常 |
| R2 | Forge | 同上 | 同上 |
| R3 | 光影 | Iris/Oculus 开启 | 视频图层不破坏合成；无花屏/黑屏 |
| R4 | 跨维度 | 目标维度播放视频 | 与 F8 视图组合正常 |

## 四、技术细节

### 4.1 证据留存

- 每项验收保留日志片段、截图或进程列表；一次性脚本用完删除。
- 失败项必须记录复现条件（文件、编码、GOP、平台）。

### 4.2 判定

- 通过标准是“可观察结果”，不是“代码里存在某函数”。
- 资源类验收以进程数、句柄数、纹理数为准，不以“看起来正常”为准。

### 4.3 边界

- 不验收导出/编码；不验收直播流；不验收未列出的容器/编码组合。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只做单元测试 | 不跑客户端 | 播放观感、资源回收、光影组合测不到 | 分层验收 + 实机 |
| 只做手工验收 | 全靠人看 | 不可复现、容易漏失败路径 | 探针 + 故障注入 + 实机 |
| 把验收集中在最后 | 全部做完再测 | 失败路径与资源泄漏拖到最后才暴露 | 每篇完成时补本行 |

**本方案的缺点**：

- 媒体验收成本高：需要真实视频、ffmpeg、双客户端、故障注入。
- 光影/跨维度组合的结果受环境与版本影响，需要固定测试矩阵。
