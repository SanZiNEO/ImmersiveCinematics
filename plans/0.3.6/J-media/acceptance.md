# 媒体验收矩阵

> 状态：J-2 部分已实现；J-3 已实现并验收；J-4 未实现
> 范围：播放、解码、音频、预览流、失败降级与真实机器检查（远程分片不做）
> 关联：`playback.md`、`decode.md`、`audio.md`、`preview-stream.md`、`export.md`、`degrade.md`

## 一、摘要

本页只列“怎么算过”，不重复各篇语义。每项写方法、通过标准；实现完成后在本页补实测结果。

## 二、为什么做

### 2.1 问题

- 媒体能力依赖外部进程、网络、真实文件，单测覆盖不了播放观感与资源回收。
- 各篇独立验收，容易出现“单篇过、组合崩”。

### 2.2 目标

- 每篇有可执行的验收项，且能在真实客户端上复现。
- 失败路径与正常路径同等验收，不只测成功。
- 组合场景（多视频同屏、seek、循环、morph）有明确通过标准。

### 2.3 非目标

- 不做性能基准的长期跟踪；只记录单次实测。
- 不验收导出 UI；导出参数与收尾自动验，画面效果人眼判定。
- **不验收导出音频（不做；导出文件为静音视频）**。
- 不做远程媒体分片（用户 2026-11-08 裁决：编辑通信与播放均本地）。

## 三、方案

### 3.1 验收分层

| 层 | 测什么 | 方式 |
|---|---|---|
| 单元/契约 | 路径解析、扩展名分流、队列边界 | 无头探针 + 构造数据 |
| 客户端播放 | 首帧、时间跟随、暂停/seek/循环、morph 两侧 | 真实客户端 + fixture 视频 |
| 资源与失败 | 缺 ffmpeg、坏文件、seek 超时、关闭幂等 | 故障注入 + 进程/句柄检查 |
| 预览流 | 编码、PTS、背压、丢帧、关键帧、慢客户端 | 双客户端 + 限速 |
| 导出 | 参数、时长/帧数、收尾、无残留 | 自动验参数 + 人眼看画面 |
| 真实机器 | Fabric/Forge、光影、跨维度、多视频同屏 | 实机日志 + 截图 |

### 3.2 验收项

| # | 项 | 方法 | 通过标准 |
|---|---|---|---|
| P1 | 首帧 | 播放 fixture 视频，记录首帧时间 | 首帧可见；错误纹理不出现；日志无异常 |
| P2 | 时间跟随 | 暂停/恢复/seek 到任意点 | 画面帧与 `localTime` 对应；无累计漂移 |
| P3 | 循环 | 片段 `loop` 多圈 | 每圈从头播放；不读墙钟；不累积偏移 |
| P4 | morph 两侧 | 两段视频 morphi | 两侧各按自己的局部时间取帧；过渡只混合 |
| P5 | 图层参数 | 改 `x/y/scale/opacity/z_index` | 与图片图层行为一致 |
| C1 | 捕获一致性 | 同一捕获点（`hud`）、同一时刻预览与导出各取一帧 | 像素内容一致；HUD 内容 = 脚本 `screen_layers` 放行 |
| C2 | 捕获尺寸 | 预览配置 original / 720p / 1080p，导出配置 1080p / 4K | 各尺寸独立生效；窗口缩放只影响 original；无 ffmpeg 时 original 封顶 720p |
| C3 | 捕获点 | 编辑器中预览/导出 | 含 HUD、不含编辑器 UI（人眼）；不新增 `include_hud` 字段 |
| C4 | PTS | 录制/预览各取 10 帧 | 捕获 PTS 单调；导出按脚本局部时间采样，无累计漂移 |
| E1 | 导出参数 | 编辑器发导出信号（分辨率/帧率/容器/码率/路径） | 参数原样生效；无导出 UI；入口只在编辑器模式 |
| E2 | 录制时长/帧数 | 固定脚本录制 | 时长/帧数与目标 fps 一致；脚本结束自动收尾 |
| E3 | 目标 fps 采样 | 实时帧率高于/低于目标 fps | 高则丢中间帧；低则丢帧不拉长时长 |
| E4 | 导出音频（不做） | — | **不做**（2026-11-08 裁决；导出文件静音） |
| E5 | 暂停继续 | 录制中触发单机 ESC 暂停 | 脚本时间继续、画面继续录，直到脚本结束；不出现时长冻结 |
| E6 | 导出画面 | 编辑器中录制 | 含脚本放行的 HUD；不含编辑器 UI（人眼）；参数项由自动验 |
| E7 | 取消/失败收尾 | 中途取消、编码进程被杀 | 标记取消/失败；半成品删除；无残留进程 |
| D1 | 解码链路 | 正常视频连续播放 | 队列有界；内存不随时间增长 |
| D2 | seek 重启 | 长 GOP 视频 seek | 超时后回退最后一帧；不越界读旧帧 |
| D3 | 线程边界 | 解码中拖动/暂停 | 渲染不阻塞；无半帧撕裂 |
| A1 | 音频格式 | WAV/OGG/mp3/aac | 按扩展名解码；时间跟随片段 |
| A2 | 视频音轨 | 带音轨视频播放 | 视频自带声音随视频播放；不拆成 AUDIO 轨；暂停/seek/循环跟随 |
| V1 | 预览编码 | 本地预览 | 编码帧 + PTS；首帧从关键帧开始 |
| V2 | 背压 | 慢客户端 + 正常客户端 | 慢端丢帧计数增长；正常端帧率不受影响（不自动降档） |
| V3 | 暂停/恢复 | 预览暂停再恢复 | 暂停停编码；恢复从当前播放头取关键帧 |
| — | 远程分片 | — | **不做**（2026-11-08 裁决：编辑通信与播放均本地） |
| F1 | 缺 ffmpeg | 移除 `<gameDir>/ffmpeg/ffmpeg.exe` 后重启 | 视频不显示、不占位、不报错；编辑器传原始画面（original 封顶 720p）；导出不可用；限频日志一次 |
| F2 | 坏文件 | 截断/损坏视频 | 解码失败回退；无僵尸进程 |
| F3 | seek 超时 | 构造卡死进程 | 强制结束；下一 seek 可恢复 |
| F4 | 远程断线 | — | **不做**（远程分片不做） |
| F5 | 关闭幂等 | 重复 close/世界退出 | 无异常；进程/纹理/句柄清零 |
| R1 | Fabric | 实机加载/播放/预览 | 无异常；资源回收正常 |
| R2 | Forge | 同上 | 同上 |
| R3 | 光影 | Iris/Oculus 开启 | 视频图层不破坏合成；无花屏/黑屏 |
| R4 | 跨维度 | 目标维度播放视频 | 与 F8 视图组合正常 |

## 四、技术细节

### 4.1 证据留存

- 每项验收保留日志片段、截图或进程列表；一次性脚本用完删除。
- 失败项必须记录复现条件（文件、编码、GOP、平台）。
- 标「人眼」的条目只记录截图/录屏与结论，不由 AI 声称通过。

### 4.2 判定

- 通过标准是“可观察结果”，不是“代码里存在某函数”。
- 资源类验收以进程数、句柄数、纹理数为准，不以“看起来正常”为准。
- 自动项：参数、时长/帧数、可解码、无残留进程、文件非空。
- 人眼项：画面内容、HUD 是否正确、编辑器 UI 是否排除、导出画面。

### 4.3 边界

- 验收导出参数与收尾；不验收导出 UI；不验收直播流；不验收未列出的容器/编码组合。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只做单元测试 | 不跑客户端 | 播放观感、资源回收、光影组合测不到 | 分层验收 + 实机 |
| 只做手工验收 | 全靠人看 | 不可复现、容易漏失败路径 | 探针 + 故障注入 + 实机 |
| 把验收集中在最后 | 全部做完再测 | 失败路径与资源泄漏拖到最后才暴露 | 每篇完成时补本行 |

**本方案的缺点**：

- 媒体验收成本高：需要真实视频、ffmpeg、双客户端、故障注入。
- 光影/跨维度组合的结果受环境与版本影响，需要固定测试矩阵。

## 六、实现结果

状态：J-2 部分已实现（播放/解码/捕获/视频音轨）；J-3 已实现并完成实机验收；J-4 导出未实现。

J-2 结果（保留）：
- 已过：捕获逐位一致 10/10；视频解码/seek/50 次启停探针 40/40（320×180，**无 1080p 吞吐断言**）；实机播放可出画。
- 已过（headless 选帧）：1080p30 30.09fps、4K30 29.98fps；实机由用户验收。导出与预览编码未实现。
- 人眼项：本页标注「人眼」的条目均未验证。

J-3 结果（2026-11-09，Fabric 1.20.1 dev 客户端；ffmpeg 8.1.1 固定路径 `<gameDir>/ffmpeg/`）：
- V1 预览编码：18B 头 + PTS；720p 实机 54.86fps / 1280×720，1080p 50.53fps / 1920×1080，original 2544×1353 约 45–47fps；`ptsMonotonic=true`，关键帧正常，首帧 `firstKey=true`。
- V2 背压：慢端（200ms/帧）单独跑时服务端 `dropped` 223→439/4s（约 54/s）；快端单独 54.86fps vs 双会话并发 54.30fps（差 0.56fps，<1%）。**不自动降档**（用户裁决）。
- V3 暂停/恢复：暂停 0 帧；暂停态 `editor.seek` 补 4 帧且首帧关键帧；恢复 52.64fps 且首帧关键帧。
- A1 音频格式：同源 wav/ogg/mp3 经 `ExternalPcmDecode` 整段解码，长度差 <2%、时长差 <0.2s；实机 `j3_av_test` 在 0/5/10s 分别 `audio-start clip=a_wav/a_ogg/a_mp3`（local≈0.000），无失败日志。
- 视频 seek / AUDIO 边界：同一 AUDIO clip 内 `editor.seek` 后 `audio-start` 不新增（实例复用）；视频解码 ffmpeg 以新 `-ss` 重启（`j2_test.mp4` 进程命令行变化），AUDIO 外部解码为整段内存、不产生常驻进程。
- 回退：移除 `<gameDir>/ffmpeg/ffmpeg.exe` 后重启，预览回退 `type=1` RGBA，尺寸 1280×720（original 封顶），仍出画面。
- 20 次 F9 开关：ffmpeg 进程 0；`IC-WSSender`/`IC-WSReader`/`IC-PreviewEnc-*` 线程 0；仅常驻 `IC-PreviewEnc-closer`。
- 前端：Electron 实跑 WebCodecs 解码/绘制 161 帧，canvas 2544×1352、中心像素非黑、无解码错误；Chrome CDP 探针 317 AU / decoded 317 / displayed 313、PTS 单调、首帧关键帧、平均滞后 0.039ms、最大 17.38ms。
- 探针：协议/AU 切分/队列/PCM 85/85；真实编码器 15/15（含 2560×1392@60，验证 level 5.1）。
