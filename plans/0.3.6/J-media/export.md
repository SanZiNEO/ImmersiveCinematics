# 画面导出（实时录屏，文件 sink）

> 状态：未实现（J-4）
> 范围：复用共用捕获层，把 `hud` 捕获点的实时画面录成视频文件；帧采样、编码、收尾与失败（静音）
> 关联：`capture.md`（共用捕获层）、`preview-stream.md`（同一捕获点的网络 sink）、`degrade.md`、`../Z-editor/README.md` §8.3.1

## 一、摘要

导出不是离线重渲染，而是**实时录屏**：编辑器模式下正常播放脚本时，从共用捕获层按目标帧率取帧，编码写入文件。它与预览通道共用捕获点（`hud`）与编码底座，只是消费者从“本地帧流”换成“文件”。导出入口只在编辑器模式；正常游戏没有导出需求。

## 二、为什么做

### 2.1 问题

- 现在没有导出能力，成片只能靠第三方录屏；录屏受窗口、系统卡顿影响，且无法保证“脚本播放时的画面”。
- 现有预览通道已经是一套逐帧捕获链路，但没有落盘，不能单独出片。
- 若为导出另起一套“离线重渲染”，需要改时间驱动、离屏 FBO、世界 tick 与光影状态，成本远高于实时录屏。

### 2.2 目标

- 编辑器模式下按目标帧率录制成片，画面来自 `hud` 捕获点（世界 + HUD，不含编辑器 UI）；分辨率/帧率由编辑器参数决定，目标可到 4K。
- 支持 MP4/WEBM 两档编码；**导出只做画面，不含音频**（声音交给外部工具 / 后续 addon）。
- **导出期间脚本时间继续**：游戏暂停（单机 ESC）也继续渲染、继续推进脚本，录到脚本结束。
- 录制可取消、有进度；失败不留半成品。
- 复用捕获与编码底座，不新增一套读回/编码代码。

### 2.3 非目标

- v1 不做离线重渲染（逐帧驱动脚本时间）；仅预留模式枚举。
- 不做多机位、立体、球面、4K 离线导出。
- 不保证与实时播放逐像素一致（帧采样会丢帧）。
- 不做剪辑/转码；不做导出 UI（编辑器侧负责参数与进度界面）。
- **不导出音频；导出文件为静音视频**（用户 2026-11-08 裁决）。

## 三、方案

### 3.1 使用者流程

1. 编辑器选择脚本、输出路径、分辨率、帧率、编码档，发导出信号（参数见 §4.2）。
2. 主模组接收信号：按参数创建捕获会话（`hud` 点）与编码进程，锁定输出尺寸，开始播放脚本。
3. 正常播放脚本；捕获层按目标 fps 取帧，HUD 按脚本 `screen_layers` 放行，编码写入。
4. 脚本结束 / 取消：停止采样，关闭编码进程，校验输出，删除半成品（失败时）。
5. 回传结果给编辑器：成功文件路径；失败可定位原因。

### 3.2 帧采样

- 捕获点 `hud`（见 `capture.md` §3.1）：世界 + HUD，不含编辑器 UI；HUD 内容由脚本 `screen_layers` 决定。
- 目标 fps 固定；按脚本局部时间累加 `1/fps` 采样；捕获 PTS（`System.nanoTime()`）到脚本局部时间的映射由导出会话维护。
- 渲染帧率高于目标 fps 时丢中间帧；低于时表现为丢帧，不拉长时长。
- **导出期间脚本时间继续**：游戏暂停（单机 ESC）也继续渲染、继续推进脚本，直到脚本结束；导出会话不继承 `pause_when_game_paused` 的冻结。

### 3.3 编码

- 外部 ffmpeg，rawvideo stdin；尺寸/帧率/像素格式来自导出参数。
- 预设：MP4（libx264 + 码率）、WEBM（libvpx）；具体参数见 §4.3。
- 编码在工作线程；渲染线程只提交帧，不等待管道写入。

### 3.4 音频（不做）

- **2026-11-08 用户裁决：导出不包含音频。** 导出文件是静音视频。
- 原因：游戏输出回环（OpenAL loopback）要换设备、回放、音画同步，成本高；先把画面导出收口，声音交给外部工具或后续 addon。
- 运行时视频音轨仍随视频播放（见 `audio.md`），与导出无关。
- 将来若要做，参考实现都是 OpenAL Soft loopback（`ALC_SOFT_loopback` + `alcRenderSamplesSOFT`）：Flashback、Record-able、ReplayMod Audio Render；另立轮次，不进 J-4。

### 3.5 收尾与失败

- 成功：脚本结束自动停止采样；等待编码进程退出（有超时），校验文件存在且可解码；删除临时文件。
- 失败：停止采样、关闭进程、删除半成品、保留日志。
- 取消：与失败同路径，但标记为“已取消”，不算错误。
- 重复停止幂等。

## 四、技术细节

### 4.1 核心模型

| 对象 | 职责 |
|---|---|
| 导出会话 | 脚本、输出路径、尺寸/帧率/编码档、进度、取消标志 |
| 录制消费者 | 从捕获层取帧、按目标 fps 采样、提交编码 |
| 编码器 | ffmpeg 进程、rawvideo stdin、日志、退出码 |
| 收尾器 | 等进程、校验输出、清理临时文件 |

### 4.2 契约

- **信号入口**：编辑器发导出信号；参数 = 脚本、输出路径、分辨率、帧率、容器、码率。主模组不提供导出 UI。
- **创建**：导出会话独立于正常播放实例；创建自己的捕获会话（`hud` 点）与编码进程。
- **时钟**：导出期间脚本时间继续，不因游戏暂停冻结；录到脚本结束。
- **销毁**：成功/失败/取消走同一收尾；释放捕获会话、进程、临时文件。
- **线程**：捕获在渲染线程；采样/编码在工作线程；收尾在导出线程。
- **背压**：导出不允许随便丢帧；队列满时阻塞采样，等待编码消费。
- **隔离**：导出不改变正常播放实例的状态；取消后恢复原播放。
- **入口**：只在编辑器模式；正常游戏不暴露导出。

### 4.3 编码参数

| 预设 | 参数形态 | 来源 |
|---|---|---|
| MP4 | `-c:v libx264 -b:v <bitrate> -pix_fmt yuv420p` | Replay `RenderSettings.EncodingPreset.MP4_CUSTOM` |
| MP4 快速 | `-preset ultrafast -crf 51` | Replay `MP4_POTATO` |
| WEBM | `-c:v libvpx -b:v <bitrate> -pix_fmt yuv420p` | Replay `WEBM_CUSTOM` |

基础输入：`-y -an -f rawvideo -pix_fmt <格式> -s <W>x<H> -r <FPS> -i -`（`-an` = 不写音轨；两家参考一致）。

### 4.4 数据形态

- 帧：捕获层统一的像素格式与尺寸；行序按编码器要求翻转。
- 输出：单文件（MP4/WEBM）或图像序列目录（可选）。
- 进度：帧号/预计总帧、阶段（准备/录制/编码/收尾）。

### 4.5 边界

- 不改脚本字段；导出参数是工具配置。
- 不碰正常播放实例的时钟与状态；导出会话自己推进脚本时间。
- 不定义离线重渲染；模式枚举预留 `realtime` / `offline`，v1 只实现 `realtime`。
- 不与预览流共用会话队列：预览可丢帧，导出不可随便丢。
- **不导出音频；文件为静音视频。**
- 不做远程传输；导出文件写本地。

## 五、实现步骤（改哪里）

1. **拆捕获层**：把 `WebFrameStreamer` 里的“读回 + 缩放 + 发送”拆成捕获会话 + 消费者；预览先接到捕获会话上，行为不变。
2. **定义录制消费者**：从捕获会话取帧，按目标 fps 采样，提交编码器；队列满时阻塞。
3. **编码进程**：复用现有 ffmpeg 发现/启动逻辑；参数模板化；日志与退出码进入导出会话。
4. **收尾与校验**：等进程（超时）、校验输出、删除半成品；与 `degrade.md` 的错误分类对齐。
5. **入口与进度**：编辑器发导出信号（WebUI / 游戏内附属模组共用同一套语义）；进度与取消由编辑器展示，主模组只回传状态。
6. **验证**：固定脚本录制一次，核对时长/帧数；再验证取消与失败路径。

## 六、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 离线重渲染 | 逐帧驱动脚本时间、离屏 FBO | 改时间驱动、世界 tick、光影状态；成本高 | v1 用实时录屏；离线只预留模式 |
| 另起一套捕获 | 导出自己读回/缩放/队列 | 重复代码，预览与导出帧不一致 | 共用 `capture.md` 的捕获层 |
| 逐帧 PNG 后手动合成 | 导出图片序列 | 体积大、需二次编码 | 直接走视频编码；图像序列作为可选预设 |
| 第三方录屏 | 系统/外部工具 | 含 HUD、窗口缩放、不可控 | 模组内录制，控制捕获源与尺寸 |

**本方案的缺点**：

- 成片帧率受实时性能影响；卡顿表现为丢帧。
- 录制时长等于播放时长，不能后台加速。
- 分辨率为输出配置，不能导出超过渲染能力的尺寸。
- 两次录制结果可能不完全一致（帧采样、光影状态）。

## 七、参考实现调查

### 7.1 本地 BBS（`example/bbs-mod-1.20.1`）

| 事实 | 位置 |
|---|---|
| PBO 双缓冲 + `glGetTexImage(GL_BGR)` 读回 | `VideoRecorder.startRecording` / `recordFrame` |
| 参数模板 `%WIDTH%` / `%HEIGHT%` / `%FPS%` / `%NAME%` / `%FILTERS%` | `VideoRecorder.startRecording` |
| `vflip` 滤镜；运动模糊用 `tblend=all_mode=average,framestep=2` | 同上 |
| 音频先离线混成 WAV，作为独立输入（本方案不采用） | `AudioRenderer.renderAudio` |
| ffmpeg 路径兼容目录/文件名/`.exe`；`-version` 探测 | `FFMpegUtils` |
| 日志重定向；停止等待最长 1 分钟再 destroy | `VideoRecorder` |

BBS 是实时录屏：`recordFrame` 从当前画面纹理读回，不重新渲染。

### 7.2 本地 ReplayMod（`example/ReplayMod-stable`）

| 事实 | 位置 |
|---|---|
| 有界队列 `ArrayBlockingQueue(2)` + `put` 阻塞；线程池 `processors - 2` | `Pipeline.java` |
| 捕获 → 处理 → 消费链；清理顺序固定 | `Pipeline.java` |
| 参数模板 + `TeeOutputStream` 写 `export.log`；关闭等待 30 秒 | `FFmpegWriter.java` |
| 预设 MP4/WEBM/MKV/PNG/EXR；基础 rawvideo bgra | `RenderSettings.EncodingPreset` |
| 导出前预跑约 1 秒，确保实体位置包 | `VideoRenderer.renderVideo` |

Replay 是离线重渲染：`VideoRenderer` 建独立管线、接管时间线、按固定 tick 逐帧渲染。我们 v1 不采用。

### 7.3 外部项目

- [WaterMedia](https://github.com/WaterMediaTeam/watermedia)：MC 内视频播放的正例（LibVLC 路线），证明图层级视频可行；不涉及导出。
- [WaterFrames](https://github.com/SrRapero720/waterframes)：基于 WaterMedia 的游戏内视频框。
- [FFmpegLib](https://www.curseforge.com/minecraft/mc-mods/ffmpeg-lib)：FFmpeg JNI 路线，与本项目的外部进程路线不同。

## 八、已拍板 / 待定

已拍板（用户 2026-11-08）：

- **录制源**：固定 `hud` 捕获点（HUD 后、编辑器 UI 前），与预览一致；不切窗口源、不隐藏 HUD。
- **HUD 内容**：由脚本 `screen_layers` 决定放行哪些层，导出不额外增删。
- **卡顿**：丢帧、保持目标 fps，不拉长时长。
- **音频**：**不做**（2026-11-08 裁决）；导出文件静音，声音交给外部工具/后续 addon。
- **时钟**：导出期间脚本时间继续，游戏暂停也继续，录到脚本结束。
- **进度/取消**：编辑器侧 UI；主模组只回传状态。
- **输出校验**：可解码、时长/帧数匹配、无残留进程、文件非空。

仍待定：

- **光影开启时是否允许录制**：按当前画面录，不单独处理；若出现兼容问题再补限制。
