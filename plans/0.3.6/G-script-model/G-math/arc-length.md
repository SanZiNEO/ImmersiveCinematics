# 弧长参数化

> 状态：实现中（现有三次 Bézier 弧长 LUT；通用算子/多曲线未实现）
> 范围：弧长积分、`u↔s` 映射、解析快路径、数值方法、动态控制点、缓存与退化
> 关联：`expression-contract.md`、`arc-length-lut.md`、`curve-bezier.md`、`example/math/notes/umd_amsc466_numerical_quadrature.pdf`

## 一、摘要

弧长参数化把“曲线参数 `u`”映射成“走过的弧长 `s`”，让匀速的 `s` 变化产生匀速的空间运动。它不是某条曲线的专属成员，而是路径表达式上的通用算子：能解析的类型走快路径，不能解析的类型走数值积分/LUT；反解 `u(s)` 必须单调、端点精确、退化安全。

## 二、为什么做

### 2.1 问题

- 贝塞尔曲线的 `u` 不是弧长；直接按 `u` 匀速会忽快忽慢。
- 现有 `ArcLengthLUT` 只服务三次 Bézier；新增 B-spline/NURBS/Catmull-Rom 后没有通用弧长层。
- 动态控制点（实体跟随/触发器基准）会让 LUT 失效；每帧重建不可接受。
- 零长、尖点、零导处反解可能不单调，必须显式处理。

### 2.2 目标

- 统一 `s(u)` 与 `u(s)` 契约；所有路径表达式都能通过通用算子获得弧长参数化。
- 解析快路径：直线、圆弧、回旋线（以弧长为参数）；数值兜底：Bézier、B-spline、NURBS、Catmull-Rom、Hermite、Fourier。
- 反解单调、端点精确、零长/尖点/零导有明确策略。
- 静态曲线缓存；动态曲线按阈值重建或降级；逐帧零分配。

### 2.3 非目标

- 不要求每条曲线都实现解析弧长；数值兜底是常态。
- 不在表达式层做时间重映射；`s=f(t)` 由播放层负责。
- 不把弧长表写进脚本；表是运行时/算子缓存。

## 三、方案

调用方只做两件事：

- `s = arcLength(u0, u)`：从参数区间起点到 `u` 的弧长（或归一化进度）。
- `u = uFromArcLength(s)`：给定弧长/归一化进度，反解曲线参数。

曲线类型可选“解析快路径”（直线、圆弧）或“数值兜底”（其他）。数值兜底优先用 LUT；动态曲线按“端点/控制点变化阈值”决定重建或降级为每帧固定采样积分。

## 四、技术细节

### 4.1 核心模型

- 弧长 `s(u)=∫_{u0}^{u} |P'(τ)| dτ`；归一化 `s∈[0,1]` 时除以总长 `L`。
- 反解 `u(s)` 是 `s(u)` 的单调逆；要求 `s(u)` 单调递增（除零长/尖点）。
- 解析快路径：直线 `L=|P1-P0|`；圆弧 `L=R·Δθ`；回旋线以弧长为自然参数，`u` 取弧长时 `u(s)` 恒等，取归一化时线性缩放。
- 数值：Gauss-Legendre/自适应 Simpson 积分；LUT 用自适应细分/采样建表。

### 4.2 契约

- 端点：`uFromArcLength(0)=u0`、`uFromArcLength(L)=u1`；浮点误差用 clamp。
- 单调：`s(u)` 非减；零导/尖点处按类型声明（跳过/分段/报错），不静默返回 NaN。
- 零长：总长 0 时 `uFromArcLength` 返回起点，不除零。
- 精度：静态曲线相对误差目标 `≤1e-6`（可调）；LUT 密度按曲率/容差自适应。
- 缓存：键 = 曲线类型 + 控制点 + 权重 + 节点 + 定义域；变化即失效。
- 动态：端点/控制点每帧变化时，标记 `dynamic`，按阈值重建或每帧固定采样积分；不每帧重建整表。
- 零分配：LUT 用预分配数组；反解用二分 + 线性/牛顿精化；逐帧不 new。

### 4.3 数据形态

- 弧长表：`(u_i, s_i)` 单调数组，`s_i` 归一化；查询二分 + 线性插值，必要时牛顿精化。
- 缓存归属调用点/算子实例；曲线定义不持有可变缓存。
- 动态曲线可持有“上次控制点快照 + 表”，变化超过阈值才重建。

### 4.4 边界

- 弧长算子不改变曲线几何；只改变参数映射。
- 弧长算子不负责时间；`s=f(t)` 在播放层。
- 弧长算子不保证跨平台逐位一致；数值方法按类型声明容差。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只做解析弧长 | 每条曲线必须闭式解 | 大多数曲线没有闭式解 | 不可行 |
| 每条曲线各自实现 | 曲线自带 LUT/积分 | 重复代码；行为不一致 | 通用算子统一 |
| 只用 LUT | 所有曲线建表 | 动态曲线重建贵；精度受表密度 | 解析快路径 + 数值兜底 |
| 只用每帧积分 | 每帧数值积分 | 逐帧成本高；结果可能抖动 | 静态缓存/LUT |

**本方案的缺点**：

- 数值反解有误差；容差/表密度要调。
- 动态控制点让缓存策略复杂；极端情况下要降级。
- 尖点/零导的单调性需要类型特定策略，通用算子不能一刀切。
