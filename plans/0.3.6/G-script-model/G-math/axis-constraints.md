# 控制轴约束

> 状态：已实现（几何线性语义）
> 范围：控制点约束、切空间约束、投影三种语义；对 Bézier/B-spline/NURBS/圆弧/回旋线/Fourier 的影响
> 关联：`expression-contract.md`、`curve-bezier.md`、`exact-conics.md`、`arc-length.md`

## 一、摘要

控制轴约束让作者限制路径在某个坐标轴上的弯曲自由度，例如“只在地面平面弯曲、高度线性变化”或“只在垂直平面内弯曲”。它有三种语义：约束控制点分量、约束切空间、把整条曲线投影到子空间；三者结果不同。默认采用“控制点约束”，因为它可预期、端点保持、对现有曲线类型容易施加。

## 二、为什么做

### 2.1 问题

- 作者想“保持高度不变做横移”或“只在一个平面内环绕”，现在只能手工把控制点分量写成同值，容易错。
- 直接投影整条曲线会改变弧长/曲率，运动速度不再均匀。
- 切空间约束可能破坏端点切线，导致段间不连续。
- 轴约束与精确圆组合时，可能把精确圆变成非精确；必须显式说明。

### 2.2 目标

- 提供每轴开关：`x/y/z` 哪些轴参与弯曲；未选轴按线性/常量处理。
- 默认“控制点约束”：保持端点，未选轴的控制点分量按端点线性插值。
- 明确约束后弧长/切线/连续性重新计算；精确性可能丢失，必须标记。
- 与相对控制点兼容：先解析相对点为绝对，再施加约束。

### 2.3 非目标

- 不把投影作为默认语义；投影会改变几何，不推荐。
- 不保证轴约束后仍精确表示圆/椭圆。
- 不自动修复段间连续性；连续性另篇校验。

## 三、方案

作者给路径加轴约束：

- `axis_constraint: {x:true, y:true, z:false}` 表示只允许 x/y 弯曲，z 轴按端点线性/常量。
- 对 Bézier：未选轴的控制点分量设为端点线性插值（三次 Bézier 的 1/3、2/3 点），曲线在该轴退化为线性。
- 对 B-spline：未选轴的控制点分量放在同一直线上；B-spline 基函数能再生线性函数，曲线在该轴为线性。
- 对圆弧/椭圆：约束后一般不再是精确圆/椭圆；标记“非精确”。
- 对 Fourier：未选轴的系数置零或只保留常数项。

> 落地说明：最终实现取**几何线性语义**（求值后替换未选轴分量），而不是逐类型改控制点。
> 对 Bézier / 二次 Bézier / B-spline 两者数学等价（§4.2 有实测）；对 NURBS / 圆锥，
> 控制点约束会破坏权重与精确性，因此统一按几何语义执行，该轴仍严格线性。

## 四、技术细节

### 4.1 核心模型

- 约束是路径表达式算子（求值后替换未选轴），不改曲线控制数据；约束后的曲线仍是路径表达式。
- 每轴开关；未选轴的目标是严格线性，不是“任意”、也不是“常量”。
- 约束后重新计算弧长/切线/连续性；缓存键包含轴约束。

### 4.2 契约

**现行口径（已实现）：算子语义 = 「未选轴严格为端点间线性，已选轴保留原曲线」。**

轴约束不是逐类型改控制点，而是求值后被替换的几何算子：`bind(from, to)` 先按原定义求值，再把未选轴的
位置 / 导数分量换掉——未选轴位置 `from + (to-from)·normalize(u)`、未选轴导数 `(to-from)/span`；
已选轴逐位保留原曲线分量。这样每个曲线类型都拿到同一条契约，且端点精确。

各类型的结果：

- 三次 Bézier：与文档的控制点约束**数学等价**——未选轴 `P1=(2P0+P3)/3`、`P2=(P0+2P3)/3`，
  该轴在 `u` 上线性，与几何替换逐点一致（实测 1.421e-14）。
- 二次 Bézier：与「未选轴 `P1=(P0+P2)/2`」等价（实测 7.105e-15）。实现上二次曲线先升阶为三次，结论不变。
- B-spline：与「未选轴控制点按 **Greville 横坐标**取端点线性值」等价（实测 1.421e-14）；
  按索引等距赋值在非均匀/钳制节点下**不是**严格线性（实测偏差 7.632e-02），这正是本节要提醒的坑。
- NURBS / 圆锥（圆弧、椭圆）：控制点约束会破坏有理权重与精确性（圆不再是圆），因此本实现**不**采用
  控制点语义，改取几何语义——未选轴严格线性、已选轴仍是原来的精确圆锥分量。
- Fourier：未选轴的余弦/正弦系数不再影响该轴（被线性项覆盖）；已选轴系数照旧。
- 弧长 / 切线：几何已变，弧长不能复用原曲线的解析式或 LUT；能力声明收紧（见 4.3），切线按替换后的曲线求。
- 连续性：约束可能破坏段间 G1/G2，必须用 `Continuity.check` 重新校验（`continuity-composition.md`）。

三种语义的取舍不变：默认几何线性（可预期、端点保持、对全部类型一致），切空间约束/投影仍不实现。

### 4.3 数据形态

- 轴约束是路径表达式上的算子：`AxisConstrainedSpec implements PathSpec` 包装原 `PathSpec`，
  `type()` 为原类型加 `"|axis"`；不写进曲线原语的控制点数组。
- 每轴布尔，缺省全 `true`（不约束）；`AxisConstraint.ALL` = 三轴全保留，
  `constrainsAny()` = 至少一轴被约束。`PathSpec.constrain(AxisConstraint)` 叠加包装，不改原定义。
- 绑定：`bind(from, to)` 先委派原定义，再用 `from`/`to` 作未选轴的线性基准。
  `anchor() == FREE` 的曲线（圆弧 / 椭圆 / 周期 Fourier / 回旋线）不消费端点，但线性基准仍取
  `bind` 收到的 `from`/`to`——它们是一段路径的起止位置，不是曲线参数；`anchor() == START` 时
  `to` 只用于未选轴的线性目标。
- 能力：`AxisConstrainedExpression` 只在「内层实现 `AnalyticArcLength` 且三轴全保留」时实现该接口并直接委派；
  有任一轴被约束时弧长已变，表达式不实现接口、`spec.supports(ANALYTIC_ARC_LENGTH)` 也返回 `false`，
  弧长由 `ArcLength` 数值积分重算。`ANALYTIC_SECOND_DERIVATIVE` 等其他能力照旧透传。
- 缓存键：原曲线 + 轴约束（含每轴布尔）。约束后的弧长/曲率与原来不同，不能复用原 LUT。

### 4.4 边界

- 轴约束不改变时间映射；`s=f(t)` 在播放层。
- 轴约束不保证精确圆锥；精确性声明由 `exact-conics.md` 负责。
- 轴约束不自动修复段间连续性；连续性另篇校验。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 几何线性（已实现） | 求值后把未选轴换成端点线性 | 端点保持；该轴严格线性；对全部类型一致 | 默认，作者可预期 |
| 控制点约束 | 未选轴控制点线性插值 | 对 Bézier/B-spline 等价，但会破坏 NURBS 权重与圆锥精确性 | 只作为等价性参照，不作实现 |
| 切空间约束 | 强制一阶导某分量为 0 | 可能破坏端点切线/连续性 | 高级选项，不作为默认 |
| 投影整条曲线 | 三维曲线投影到平面 | 改变弧长/曲率/速度 | 不推荐 |
| 只给作者手填控制点 | 不做约束 | 容易错；无法批量 | 约束是显式能力 |

**本方案的缺点**：

- 几何语义与「控制点约束」在 NURBS/圆锥上结果不同；文档必须写清，否则作者会以为权重仍被保留。
- 约束后弧长/连续性要重算；缓存失效。
- 切空间约束可能无解/破坏端点；只能作为高级选项。

## 六、实现结果

状态：已实现（几何线性语义）。切空间约束与整条投影仍未实现（见五、）。

- `math/path/AxisConstrainedSpec.java`：`bind` 里对未选轴做几何替换（原有行为，补记入 javadoc）；
  新增「三轴全保留时实现 `AnalyticArcLength` 并委派」的表达式变体；
  `supports(ANALYTIC_ARC_LENGTH)` 在任一轴被约束时返回 `false`。
- 未新增作者面类型：轴约束仍是 `PathSpec` 上的算子，不进 `PathCurveRegistry`。
