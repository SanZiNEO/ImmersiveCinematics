# 编辑器播放

> 状态：未实现
> 范围：编辑器播放的实例语义、时钟来源、内容行为参与范围、画面来源、命名与注释修正
> 关联：`../I-script-core/runtime-evaluation.md`（实例/状态所有权）、`../I-script-core/loop-execution.md`（执行身份）、`../Z-editor/server-protocol.md`、`../Z-editor/README.md`

## 一、摘要

编辑器播放不是一种“预览模式”，而是**播放引擎的另一种时钟来源**：游戏保持正常渲染，持续把主画面传输给编辑器，同时播放编辑器当前持有的脚本；播放/暂停/seek 由编辑器播放头控制。画面、HUD、相机、音频、覆盖层全部按脚本执行，与普通播放一致；只有时间的来源不同。

## 二、为什么做

### 2.1 问题

- `PlaybackInstance.isPreview()` 一个布尔同时表达了三件事：时钟来源、内容语义、游戏控制，导致内容语义被一起排除。
- `PlaybackRegistry.instanceBehaviors()` 跳过编辑器实例，注释写着“预览实例不参与（预览通道不套用脚本行为）”；于是脚本的 `hide_hud`、`hud_layers`、`hide_*` 在编辑器里不生效，HUD 表现与普通播放不一致。
- `CameraManager.isPreviewMode()` 的注释把“预览”描述成“玩家移动不由输入驱动”，语义偏向特殊模式，而不是播放。
- `WebPreviewScreen` 的注释接近正确（“把游戏画面编码后发给前端”），但周边命名与门控把它当成例外路径。

### 2.2 目标

- 编辑器里播放脚本，画面与普通播放一致（除时间控制外）。
- 脚本隐藏什么就隐藏什么，显示什么就显示什么；编辑器不额外隐藏或显示任何 HUD。
- 传输源是游戏主画面（含 HUD），不是合成 FBO、不是空白画面。
- 编辑器播放不参与游戏侧控制语义；退出后 HUD、输入、相机恢复原样。

### 2.3 非目标

- 不新增“编辑器专用画面模式”或独立渲染路径。
- 不为编辑器单独做 HUD 过滤。
- 不改变普通播放的语义。

## 三、语义定义

1. **同一播放引擎。** 编辑器播放与普通播放共用解析、采样、合成、HUD、音频；不另起渲染路径。
2. **唯一差异是时钟来源。** 普通播放读游戏时钟；编辑器播放读编辑器播放头（play / pause / seek）。
3. **画面来源是主画面。** 传输的是游戏当前渲染输出（含 HUD、覆盖层、调色）；脚本让它怎么放，游戏就怎么显示。
4. **脚本行为全部生效。** `hide_hud` / `hud_layers` / 相机 / 音频 / 覆盖层按脚本执行，不因“编辑器”而豁免。
5. **游戏控制不生效。** 键鼠屏蔽、暂停联动、播放队列、网络账本、跳过投票属于游戏侧语义，编辑器播放不参与；这一条单独排除，不连带排除内容语义。
6. **退出即恢复。** 停止编辑器播放后，HUD、输入、相机回到进入前的状态。

### 3.2 画面内容与来源

编辑器播放传输的是**游戏主画面**，内容与玩家正常游玩时一致，按层包括：

| 层 | 内容 | 显隐来源 |
|---|---|---|
| 世界渲染 | 地形、实体、粒子、天气、光影 | 游戏状态；编辑器不干预 |
| lane 合成 | 相机轨道产出的画面、多 lane 叠放 | 脚本轨道与合成参数 |
| 覆盖层 | fade / image / subtitle、渐变、遮罩、z 序 | 脚本 OVERLAY / LETTERBOX 字段 |
| 调色 | master 与 lane 级调色、LUT、混合模式 | 脚本调色字段 |
| HUD | 热栏、血量、准星、经验、Boss 条、聊天、计分板、动作栏、标题、字幕、跳过提示 | 脚本 `hide_hud` + `hud_layers` + 各 `hide_*` 字段 |
| 玩家模型 / 手臂 | 第一/第三人称玩家与手臂 | 脚本 `render_player_model` / `hide_arm` |

规则：

- **显隐唯一来源是脚本字段。** 编辑器不额外隐藏、不额外显示任何层；脚本写什么就是什么。
- **未声明的分层字段回落 `hide_hud`**，与普通播放同一套并集逻辑。
- **传输源是主画面**（窗口 framebuffer），含 HUD；不是合成 FBO，也不是空白画面。
- **导出源不同**：成片导出取合成 FBO（不含 HUD），见 `../J-media/export.md`；两者不混用。
- **尺寸按输出配置**，不由现有 720p 原始 RGBA 实现决定。

### 3.3 实例维度拆分

| 维度 | 普通播放 | 编辑器播放 | 处理 |
|---|---|---|---|
| 时钟来源 | 游戏时钟 | 编辑器播放头 | 可以不同 |
| 内容语义（HUD、相机、lane、音频、覆盖层） | 脚本决定 | 脚本决定 | 必须相同 |
| 游戏控制（键鼠、暂停联动、队列、账本、投票） | 参与 | 不参与 | 可以不同 |

`isPreview` 不再承担这三个维度；拆成“时钟来源”与“参与范围”两个声明。

## 四、命名与注释

| 位置 | 统一为 |
|---|---|
| 模式名 | 编辑器播放 / editor-driven playback |
| `isPreview()` | `isEditorDriven()`，或拆 `clockSource` 枚举 |
| 通道名 | 编辑器播放通道 |
| `instanceBehaviors()` | 包含编辑器实例；键鼠屏蔽在并集内单独排除 |
| 相关注释 | 明确“编辑器实例参与内容行为，不参与游戏控制” |

## 五、改动清单

- `PlaybackRegistry.instanceBehaviors()`：包含编辑器实例；注释重写。
- `CinematicController.recomputeUnion`：输入包含编辑器实例；`block_keyboard` / `block_mouse` 对编辑器实例单独置 false。
- `PlaybackInstance.isPreview()` 的命名与注释。
- `CameraManager.isPreviewMode()` 等入口的命名与注释。
- `WebPreviewScreen` 的注释：明确“传输主画面 + 编辑器时钟”，去掉“预览”措辞。
- 画面传输源：确认取主画面（含 HUD），不是合成 FBO。
- 文档与注释中所有“预览模式”措辞统一替换。

## 六、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 编辑器播放做成独立渲染路径 | 单独合成、单独 HUD | 两套画面、两套 HUD，语义继续漂移 | 同一引擎，只换时钟来源 |
| 继续用 `isPreview` 一刀切 | 一个布尔表达全部维度 | 内容语义被连带排除，HUD 不生效 | 拆分维度，分别声明参与范围 |
| 编辑器额外隐藏 HUD | 为了“干净画面” | 看不到脚本对 HUD 的实际影响 | 脚本隐藏什么就显示什么 |

**本方案的缺点**：

- 需要逐处清理“预览”命名与注释，改动面散布在实例、并集、相机门面与 WebUI。
- 键鼠屏蔽单独排除后，行为并集的输入不再等同“所有实例的原始行为”，需要明确分组。
- 画面传输改为含 HUD 的主画面后，编辑器侧需要接受画面尺寸/内容变化。

## 七、验收

- 同一脚本、同一时间点：编辑器播放与普通播放的画面一致（逐帧对照）。
- 脚本 `hide_hud=true`：编辑器里 HUD 同样隐藏；`false`：同样显示。
- `hud_layers` 分层控制生效。
- 编辑器播放时键鼠不被屏蔽；退出后恢复。
- 传输画面含 HUD，不是空白或合成 FBO。
- 停止后 HUD、相机、输入恢复。
