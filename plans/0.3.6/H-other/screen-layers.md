# 画面层（Screen Layers）

> 状态：已实现（2026-11-04，H-5）；2026-11-08 收敛为唯一模式
> 范围：播放期间画面层的可见性控制、15 个规范层名、`screen_layers`、唯一接管模式（强制清除 + 白名单放行）、层注册接口、平台差异
> 关联：`../I-script-core/editor-playback.md`、`docs/SCRIPT_FORMAT.md`、`docs/modules/control.md`、`docs/modules/mixin.md`

## 一、摘要

画面层是播放期间叠加在游戏画面上的原版与第三方呈现内容：HUD、聊天、记分板、字幕、第一人称手臂、视角摇晃、屏幕效果、玩家模型，以及第三方注册或自绘的界面元素。系统决定播放时哪些层出现、哪些不出现；脚本、整合包与模组通过同一套层名接口声明。

**唯一模式：强制清除 + 白名单放行，默认生效。** 只要任一层判隐藏，就取消整帧 HUD 绘制，再按 `screen_layers` 白名单逐层重画；未声明的层不显示。没有模式字段，也没有降级路径。

## 二、为什么做

### 2.1 问题

> 历史背景：下列问题描述的是改造前的状态。相关旧字段（`hide_hud` / `hide_*` / `suppress_*` / `render_player_model` / `hud_layers` / `hard_hide_hud`）已全部移除。

- 现有字段叫 `hide_hud`，但同一套控制还覆盖手臂、视角摇晃、屏幕效果与玩家模型；这些不经过 HUD 管线，名字与实际范围不符。
- 逐层抑制的约束力不足：不走 overlay 注册表、直接在 GUI 前置事件里自绘的第三方界面，逐层路径碰不到。
- 层清单分散在多个字段里（`hide_hud`、旧 `hud_layers`（deprecated）、`hide_arm`、`suppress_bob`、`suppress_distortion`、`render_player_model`），没有统一的名字与配置入口。
- 整合包与模组需要能注册自己的层并参与白名单，目前只有分类注册表，没有面向作者的统一接口。

### 2.2 目标

- 一套层名覆盖 HUD、手臂、摇晃、屏幕效果、玩家模型与第三方界面。
- 唯一模式：先清空整帧画面层，再按白名单放行；只要任一层判隐藏就生效，无需脚本选择模式。
- 脚本、整合包、模组用同一套层名声明；并集语义明确。
- 编辑器播放与普通播放使用同一套画面层规则，编辑器不额外过滤。

### 2.3 非目标

- 不控制世界内容（地形、实体、粒子、天气）；这些由游戏状态决定。
- 不控制脚本自己的覆盖层（黑边、字幕、图片、GIF）；它们由脚本轨道决定，始终按脚本显示。
- 不定义屏幕效果的具体算法与资源格式；本轮只定义显隐。
- 不做“按订阅者白名单”（不枚举 GUI 前置事件监听器）。
- 不为单个模组写针对性 mixin；不补发 overlay 事件。

## 三、方案

### 3.1 层清单

| 层名 | 内容 | 说明 | 空间 |
|---|---|---|---|
| `hud.hotbar` | 快捷栏 | 原版 HUD 元素 | 屏幕 |
| `hud.crosshair` | 准星 | 原版 HUD 元素 | 屏幕 |
| `hud.health` | 血量、护甲、载具生命 | 原版 HUD 元素 | 屏幕 |
| `hud.experience` | 经验条、等级 | 原版 HUD 元素 | 屏幕 |
| `hud.bossbar` | Boss 血条 | 原版 HUD 元素 | 屏幕 |
| `hud.chat` | 聊天记录与输入 | 原版 HUD 元素 | 屏幕 |
| `hud.scoreboard` | 记分板、玩家列表 | 原版 HUD 元素 | 屏幕 |
| `hud.action_bar` | 动作栏 | 原版 HUD 元素 | 屏幕 |
| `hud.title` | 标题 | 原版 HUD 元素 | 屏幕 |
| `hud.subtitle` | 字幕 | 原版 HUD 元素 | 屏幕 |
| `hud.skip_prompt` | 本模组的跳过提示 | 本模组自绘覆盖层 | 屏幕 |
| `viewmodel` | 第一人称手臂 | 世界渲染，仅玩家可见 | 世界（仅玩家可见） |
| `view_bobbing` | 视角摇晃 | 视角变换 | 视角 |
| `screen_effects` | 暗角、传送门、冻结、火焰、扭曲、遮罩 | 屏幕效果与后处理 | 屏幕/后处理 |
| `player_model` | 玩家模型 | 世界渲染 | 世界 |

第三方界面：

- 走 overlay 注册表的层，按注册分类名参与白名单；未注册层以自身资源 ID 作层名。
- 直接在 GUI 前置事件里自绘的界面没有 ID，接管时随整帧一起清空，只能通过注册接口参与白名单。

### 3.2 唯一模式

| 模式 | 行为 | 约束力 |
|---|---|---|
| 强制清除 + 白名单放行（唯一，默认生效） | 接管整帧画面层：先清空，再按白名单逐层重画 | 强 |

- 生效条件：有活跃实例且任一层判隐藏；没有模式字段，也没有降级路径。
- 并集：层按**隐藏方向 OR**——任一实例判隐藏即隐藏；只汇总各实例显式声明的键。
- 每帧只画一次；粒度：整段播放。

### 3.3 白名单接口

- 脚本：`screen_layers` 对象，层名 → boolean；**`true` = 显示（放行）**、`false` = 隐藏。
- 键域：15 个规范层名 + 注册分类名 + 未注册 overlay 的完整资源 ID。
- 整合包/模组：注册层 ID 与分类；白名单按分类或完整 ID 匹配。
- 并集：层集合 = 全部活跃实例 `screen_layers` 的键并集（只取显式声明的键，原样保留）；每层按**隐藏方向 OR**——任一实例判隐藏即隐藏，显示 = 所有实例都放行。
- 未声明的层：不在白名单内 → 不重画（隐藏）。判定顺序 = `screen_layers[规范层名]` → `screen_layers[原始分类键]` → 派生值（15 个 HUD 规范层是否全部显式隐藏）。
- 本模组自己的覆盖层不参与白名单，始终按脚本绘制。

### 3.4 接管与重画

接管整帧画面层。接管条件 = 有活跃实例 **且** 任一层判隐藏（`anyScreenLayerHidden()`）；所有层都放行时不接管（无物可藏，接管会砍掉白名单判为显示的内容）。

1. 判定需要控制时，取消 GUI 前置事件：原版 HUD、注册表 overlay、后续订阅者自绘、后置事件一并跳过。
2. 复位 HUD 布局字段（快捷栏左右高度）。
3. 遍历注册表 overlay，世界效果层豁免；其余按白名单判定，判为显示的逐层重画。判定按**规范层名优先、原始分类键兜底**：`screen_layers[规范层名]` → `screen_layers[原始分类键]` → 派生值（15 个 HUD 规范层是否全部显式隐藏）。
4. 补画本模组覆盖层（黑边、字幕、图片/GIF、跳过提示）。
5. 未接管时走原版路径（Forge 后置事件绘制本模组覆盖层；Fabric 原版 `Gui.render` 照常），保证每帧只画一次。

### 3.5 平台差异

- **Forge**：可取消的整段 HUD 回调（`RenderGuiEvent.Pre`）+ overlay 注册表 → 取消整帧后按注册表逐层重画。
- **Fabric**：`FabricGuiTakeoverMixin` 取消 `Gui.render` 整帧，`FabricHudTakeover` 在重画末尾按白名单调用自定义层表。Fabric 没有 Forge 式 overlay 注册表，第三方参与白名单的方式是注册自定义层（`FabricHudLayerRegistry.register(layerId, category, renderer)`，或跨加载器门面 `HudLayerRegistry.register`），绘制前查询 `FabricHudVisibility.isHidden(layerId)`。

### 3.6 层注册接口（H11）

对外入口是 `common` 的 `api.HudLayerRegistry`（与 `CameraApi` 同包的稳定面，只增不删）。它是第三方注册的**唯一**注册表；平台侧只负责"分类解析优先级 + 平台回调"。

| 成员 | 语义 |
|---|---|
| `install(Platform)` | 安装平台回调；只应在客户端初始化期调用一次，后装者覆盖 |
| `register(ResourceLocation overlayId, String category)` | 把 overlay 归入分类；`overlayId` / `category` 为 null 时忽略整次调用，`category` 为空串 = 未指定（等价于单参重载） |
| `register(ResourceLocation overlayId)` | 分类 = 资源 ID 字符串（把隐式口子写成显式契约） |
| `categoryOf(ResourceLocation overlayId)` | 查询分类；未注册返回 `null`，由平台自行回落 |

平台边界：

- **Forge**：`ForgeHudLayerRegistry.categoryOf` = 内置原版表 → 门面表 → `overlayId.toString()`；接管重画直接读表，门面回调不需要安装——注册写表即生效。
- **Fabric**：`FabricHudLayerRegistry.categoryOf` = 自有表 → 门面表（层名按资源 ID 语法解析后查）→ 原始层 ID；消费点是 `FabricHudVisibility.isHidden`（逐层过滤）与 `FabricHudTakeover`（接管后重画自定义层）。第三方参与白名单须调用三参 `register(layerId, category, renderer)` 登记渲染回调。

注册时机：客户端初始化期完成安装与首次注册（Fabric `ClientModInitializer`；Forge 无安装步骤，注册写表即生效）；注册项进程级存在，不随脚本销毁。加载器不保证模组初始化顺序：若第三方在本模组安装回调之前注册，那条边界日志不会出现，但注册本身仍写入门面表并照常参与判定。

失败隔离：注册表本身没有异常路径——null 参数忽略、未注册查询返回 `null` 而不是抛；平台回调约定不得抛异常（异常会外溢到第三方注册调用）。`screen_layers` 的规范层名优先于注册分类名；注册不会改变 15 个规范层名的判定。

## 四、技术细节

### 4.1 核心模型

| 对象 | 职责 |
|---|---|
| 层注册表 | 层 ID/分类 → 可见性判定；未注册层以完整 ID 为层名 |
| 画面层控制器 | 汇总活跃实例的层声明，计算并集与派生值 |
| 接管器 | 接管整帧画面层，清空后按白名单重画 |

### 4.2 契约

- **创建**：层注册表在客户端初始化时建立；模组/整合包可追加分类。
- **销毁**：不随脚本销毁；注册项进程级存在。
- **状态归谁**：层声明随播放实例的行为快照；并集由控制器持有；接管器无状态，每帧读控制器。
- **接管条件**：有活跃实例且任一层判隐藏；逐帧读控制器，不重启；无实例时复位。
- **重画职责**：接管时由接管器重画；未接管时原版路径照常。

### 4.3 数据形态

- 脚本字段：`screen_layers`（对象，层名 → bool，**`true` = 显示**）。接管恒生效，没有模式字段。
- 层键：15 个规范层名、注册分类名、未注册 overlay 的完整资源 ID。
- 并集：布尔 OR（隐藏方向），只汇总各实例显式声明的键；未声明键回落派生值（15 个 HUD 规范层是否全部显式隐藏）。
- 旧字段已移除：`hide_*` / `suppress_*` / `render_player_model` / `hud_layers` / `hard_hide_hud` / `screen_layer_mode` 都不再可写，出现即解析期「未知字段」报错。
- 不持久化、不走网络包；客户端读已下发的脚本元数据与本地注册表。

### 4.4 边界

- 世界内容不受控：实体、粒子、天气、地形。
- 脚本覆盖层不受控：黑边、字幕、图片、GIF 始终按脚本显示。
- 不替换层注册表与分类机制；只统一命名与接口。
- 不定义 `screen_effects` 的算法与资源格式；扭曲、遮罩作为该层的扩展另行定义。
- 取消只影响排在接管监听器之后的订阅者；同优先级且注册更早的监听器仍会执行，已经画上去的内容不会被清除。
- 依赖 overlay 事件的第三方逻辑在接管时收不到事件。

## 五、现行实现

画面层语义已按本方案落地（H-5，2026-11-04），并于 2026-11-08 收敛为唯一模式。对外入口只有一套：`screen_layers`。旧字段（`hide_*` / `suppress_*` / `render_player_model` / `hud_layers` / `hard_hide_hud` / `screen_layer_mode`）已全部移除，不再可写，出现即解析期「未知字段」报错。

### 5.1 入口与并集

- 脚本级 `screen_layers`（对象，层名 → bool，**`true` = 显示**）；没有模式字段。
- 并集：层按隐藏方向 OR（任一实例判隐藏即隐藏，只汇总显式声明的键）；无实例复位。
- 接管：只要任一层判隐藏即整帧清除 + 白名单重画，默认生效。
- 粒度：整段播放级。

层清单与判定：

| 规范层名 | 空间 | 说明 | 未声明时 |
|---|---|---|---|
| `hud.hotbar` | 屏幕 | 快捷栏 | 派生值 |
| `hud.crosshair` | 屏幕 | 准星 | 派生值 |
| `hud.health` | 屏幕 | 血量、护甲、载具生命 | 派生值 |
| `hud.experience` | 屏幕 | 经验条、等级 | 派生值 |
| `hud.bossbar` | 屏幕 | Boss 血条 | 派生值 |
| `hud.chat` | 屏幕 | 聊天记录与输入 | 派生值 |
| `hud.scoreboard` | 屏幕 | 记分板、玩家列表 | 派生值 |
| `hud.action_bar` | 屏幕 | 动作栏 | 派生值 |
| `hud.title` | 屏幕 | 标题 | 派生值 |
| `hud.subtitle` | 屏幕 | 字幕 | 派生值 |
| `hud.skip_prompt` | 屏幕 | 本模组跳过提示 | 派生值 |
| `viewmodel` | 世界 | 第一人称手臂 | 派生值 |
| `view_bobbing` | 视角 | 视角摇晃 | 派生值 |
| `screen_effects` | 屏幕/后处理 | 暗角、传送门、冻结、火焰、扭曲、遮罩 | 派生值 |
| `player_model` | 世界 | 玩家模型 | 派生值 |

判定顺序：`screen_layers[规范层名]` → `screen_layers[原始分类键]` → 派生值（15 个 HUD 规范层在并集表中是否全部显式判为隐藏）。

### 5.2 接管条件

接管在同时满足时生效：

- 有活跃播放实例；
- 任一层判隐藏（`anyScreenLayerHidden()`）。

任一层都不隐藏时不接管：无物可藏，接管会把白名单判为显示的第三方自绘内容一并砍掉。

### 5.3 接管与重画（Forge / Fabric）

- **Forge**：最高优先级监听 GUI 前置事件，取消整段 HUD 渲染（原版 HUD、注册表 overlay、后续订阅者自绘、后置事件一并跳过）。
- **Fabric**：`FabricGuiTakeoverMixin` 在 `Gui.render` 处取消整帧，`FabricHudTakeover` 在重画末尾调用自定义层表（`FabricHudLayerRegistry.renderCustom`），逐层按 `FabricHudVisibility.isHidden` 判定。
- 复位快捷栏左右高度；遍历注册表 overlay，世界效果层豁免，其余按白名单判定重画——**规范层名优先、原始分类键兜底**。
- 末尾补画本模组覆盖层（黑边、字幕、图片/GIF、跳过提示）。
- 未接管时走原版路径；接管处补画，后置事件早退，保证每帧只画一次。

### 5.4 不补发 overlay 事件

不补发，理由：

- 事件构造器标注内部 API，补发等于依赖不稳定契约；注册表条目不能自建。
- 本仓该事件唯一消费者是我们自己的隐藏判定，效果已由重画过滤复现。
- 补发会逐帧额外派发两轮事件，让第三方前置处理器参与接管。

代价：依赖该事件的第三方逻辑在接管时收不到事件（含 `receiveCanceled=true` 的监听器与读取取消态的模组）。

### 5.5 平台

- **Forge**：`RenderGuiEvent.Pre` 接管 + 白名单重画完整生效。
- **Fabric**：`FabricGuiTakeoverMixin` 取消 `Gui.render` 整帧，`FabricHudTakeover` 在重画末尾按白名单调用 `FabricHudLayerRegistry.renderCustom`。第三方层须注册进自定义层表（三参 `register`）并在绘制前查询 `FabricHudVisibility.isHidden`。

### 5.6 已知偏差与契约边界

- 重画额外豁免世界效果层（暗角、传送门、药水图标等），否则会被误判为隐藏。
- 快捷栏高度复位是防御性操作：正常流程在事件之前已复位，更早的监听器可能改过公开字段。
- 不补发 `RenderGuiOverlayEvent.Pre/Post`：依赖这些事件的第三方逻辑在接管时收不到事件。
- 取消只影响排在接管监听器之后的订阅者；同优先级且注册更早的监听器仍会执行，已经画上去的内容不会被清除。
- 不控制世界内容（实体、粒子、天气、地形）。
- 脚本覆盖层（黑边、字幕、图片、GIF）不参与白名单，始终按脚本绘制。
- 直接 mixin 进 `Gui.render` 或绕过平台入口绘制的 HUD 没有挂点；不做针对性 mixin。
- Fabric 上没有 overlay 注册表：第三方须注册进自定义层表（三参 `register`）才会被重画；未注册的原生 `HudRenderCallback` 绘制在接管时随整帧取消而不显示。
- 15 个规范层是层名的唯一真源（`script/ScreenLayer`）；`health` / `status` / 分类名 / 资源 ID 都是 `screen_layers` 的动态键，不是规范层的别名。

## 六、调查与修正

### 6.1 管线事实

- GUI 前置事件可取消；取消后原版 HUD、注册表 overlay、后置事件与后续订阅者一并跳过。
- 原版 HUD 在部分加载器上不经过 `Gui.render`，逐元素 mixin 的注入点覆盖不同；Forge 上部分元素由 overlay 分类拦截。
- 注册表 overlay 有稳定 ID；前置事件自绘内容没有 ID，无法按模组放行。
- 事件总线没有枚举监听器的 API；监听器没有稳定身份。按订阅者白名单做不到。

### 6.2 补充事实

- 原版 HUD 的隐藏不是单一 mixin：聊天、Boss 血条、玩家列表、字幕各有独立注入点。
- Sodium / Embeddium 只做点状注入，不接管整段 HUD 渲染、不订阅前置事件；兼容风险低。
- 取消只跳过排在接管监听器之后的订阅者；同优先级且注册更早的仍执行。
- Fabric 的 HUD 回调不可取消、无 ID、无注册表（J-1 前的事实）→ 改用 `Gui.render` 整帧取消 + 自定义层表补齐。

## 七、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 继续叫 `hide_hud` | 只改文档不统一层名 | 手臂、摇晃、模型仍散落在各自字段；名字继续误导 | 统一为画面层 |
| 只做逐层抑制 | 不接管整帧 | 前置事件自绘的第三方界面漏网 | 唯一模式直接接管整帧 |
| 按订阅者白名单 | 枚举前置事件监听器，按模组放行 | 事件总线无枚举 API；监听器无稳定身份 | 做不到，且脆弱 |
| 针对性 mixin | 每个第三方模组写一个注入 | 每加一个模组就要维护，版本或混淆变化即失效 | 不可扩展，只留作最后手段 |
| 全屏遮罩 | 在最上层盖不透明层 | 连白名单层与脚本覆盖层一起盖住 | 与“按白名单放行”冲突 |
| 补发 overlay 事件 | 重画时补发前置/后置事件 | 依赖内部 API，逐帧双倍派发 | 不选 |
| 把脚本覆盖层也纳入白名单 | 统一控制所有画面内容 | 黑边/字幕/图片由脚本轨道决定，纳入会重复控制 | 脚本覆盖层不参与 |

**本方案的缺点**：

- 一次性改名涉及脚本字段、schema、编辑器、文档与迁移器。
- 前置事件自绘的第三方界面只能整体清空，无法按模组放行。
- 接管会跳过前置事件订阅者的非绘制副作用（状态准备、缓存刷新）。
- 依赖 overlay 事件的第三方逻辑在接管时收不到事件。
- 同优先级更早注册的监听器仍可能残留绘制。
- 通过 mixin 直接画的界面不受影响。
- 层清单会随原版与第三方变化而增长，注册表需要维护。

## 八、验收

- 唯一模式：前置事件自绘的第三方界面被清空；白名单判为显示的层仍显示；本模组覆盖层正常显示。
- 层接口：`screen_layers` 的规范层名与注册分类/完整 ID 都能参与判定；并集与未声明键的派生回落符合定义。
- 平台：Forge 与 Fabric 都走整帧接管 + 白名单重画。
- 编辑器播放：脚本声明什么就呈现什么；编辑器不额外过滤。
- 真实客户端：需图形环境与对应第三方模组，静态可核不算通过。

## 九、实现结果

状态：**已实现（H-5，2026-11-04）**，2026-11-08 收敛为唯一模式。层清单、`screen_layers`、接管与重画、注册接口与编辑器同规则全部落地。

已实现清单：

- **层清单与 `ScreenLayer` 表**：15 个规范层名（`id` + `space`）是层名唯一真源；没有旧字段别名，也没有逐层回落链。
- **`screen_layers` 解析**：键按原样保存、极性 = 显示（`true` = 显示）；校验与 schema 同步导出一字段。`screen_layer_mode` 与 `ScreenLayerMode` 枚举已删除。
- **旧字段移除**：`hide_hud` / `hide_*` / `suppress_*` / `render_player_model` / `hud_layers` / `hard_hide_hud` 全部从 schema 与解析器删除，出现即「未知字段」报错；代码中不再保留别名、回落表或兼容分支。
- **并集与判定**：并集汇总层（隐藏方向 OR）；键并集只取各实例显式声明的键；单层判定按「规范层名 → 原始分类键 → 派生值（15 个 HUD 层是否全部显式隐藏）」。
- **接管与重画**：接管条件 = 有活跃实例 + 任一层判隐藏；重画按规范层名优先、原始分类键兜底，世界效果层豁免，末尾补画本模组覆盖层。
- **消费点统一走规范层名**：原版 HUD 各元素、聊天、Boss 血条、玩家列表、字幕、手臂、摇晃、玩家模型统一走规范层名判定；不在 15 层内的元素（跳跃条、选中物品名、保存提示）统一走 `status` 键，跳过提示走 `hud.skip_prompt`。
- **编辑器同规则**：编辑器播放与普通播放共用同一并集（`editorDriven` 只影响键鼠屏蔽），画面层不额外过滤。
