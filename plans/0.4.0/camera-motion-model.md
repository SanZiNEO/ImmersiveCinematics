# 0.4.0 长期讨论：相机运动模型与速度控制

**状态**: 🔒 长期讨论中，未定稿，不排入 0.3.5
**最后更新**: 2026-08-21

> 本文是独立长期讨论文档，不与其它计划混写。
> 讨论目标：在“关键帧 + 路程/时间 = 速度”的基础上，如何控制相机运动速度，且不让脚本参数膨胀。

---

## 1. 现状（0.3.5 已定）

- 运动模型唯一：**路程 ÷ 时间 = 速度**
- 默认匀速
- 直线：`from.lerp(to, s)`，`s = t`
- 三次贝塞尔路径：`ArcLengthLUT` 做弧长参数化，保证曲线上匀速
- 没有缓动、没有速度曲线、没有 Catmull-Rom 路径策略

代码位置：
- `KeyframeInterpolator`：`s = t`
- `BezierPathStrategy` / `ArcLengthLUT`：贝塞尔弧长参数化
- `PathStrategy` / `PathStrategies`：路径策略接口

## 2. 核心讨论问题

1. 运动模型是否应该永远只有一个（路程/时间）？
2. 如果需要“先快后慢 / 先慢后快 / 快慢快”等效果，怎么在不引入第二套模型的前提下实现？
3. 缓动到底是“新模型”还是“同一模型上的时间重映射”？
4. 脚本作者怎么用最少的参数描述速度控制？
5. 预设系统生成脚本时，速度控制应该由预设内部处理，还是暴露给作者？

## 3. 数学基础（已确认）

路径参数曲线 `P(u)`，`u∈[0,1]`：

- 总长：
  \[
  L = \int_0^1 \lVert P'(u) \rVert \, du
  \]
- 匀速：
  \[
  s = t,\quad v = L / T
  \]
- 变速（缓动）：
  \[
  s = f(t),\quad f(0)=0,\ f(1)=1,\ f \text{ 单调递增}
  \]
- 瞬时速度：
  \[
  v(t) = \frac{L}{T} \cdot f'(t)
  \]
- 加速度：
  \[
  a(t) = \frac{L}{T} \cdot f''(t)
  \]

关键不变式：
\[
\int_0^1 f'(t)\,dt = 1
\]

含义：**总路程和总时长不变**，缓动只是重新分配“每一瞬间的速度”。某一段慢了，另一段必然快。

---

## 4. 缓动不是新模型

缓动 = 时间重映射：

```
t → ease(t) → s → 弧长 LUT → P(u)
```

- 路径形状（直线/贝塞尔/Catmull-Rom）决定“怎么走”
- 缓动只决定“时间怎么分配给路程”
- 两者解耦，不引入第二套运动模型

### 常用缓动公式

| 名称 | f(t) |
|---|---|
| linear | `t` |
| quadIn | `t²` |
| quadOut | `1 - (1-t)²` |
| quadInOut | `t<0.5 ? 2t² : 1 - (-2t+2)²/2` |
| cubicIn | `t³` |
| cubicOut | `1 - (1-t)³` |
| cubicInOut | `t<0.5 ? 4t³ : 1 - (-2t+2)³/2` |
| smoothstep | `3t² - 2t³` |
| sineInOut | `(1 - cos(πt)) / 2` |

## 5. 速度控制方式选项

### A. 命名缓动（最简单）

```json
"easing": "ease_out"
```

覆盖日常大多数需求：`linear` / `ease_in` / `ease_out` / `ease_in_out`。

### B. 2D 贝塞尔缓动（高级，覆盖怪形状）

```json
"easing": {
  "type": "bezier",
  "x1": 0.1,
  "y1": 0.9,
  "x2": 0.9,
  "y2": 0.1
}
```

- 横轴：时间 `t`
- 纵轴：路程比例 `s`
- 曲线陡 = 快，平 = 慢
- 可表达：先快后慢、先慢后快、慢快慢、快慢快、轻微过冲
- 与 CSS `cubic-bezier(x1,y1,x2,y2)` 同一套数学

### C. 每段给速度值（更直接但更复杂）

```json
"speed": 2.5
```

- `T = L / speed`，时长由速度反推
- 更物理直观，但会改变脚本的总时长语义
- 与“作者显式写 duration”冲突，需要讨论优先级

### D. 每关键帧给速度/加速度（最灵活但最重）

- 每个关键帧带 `speed` 或 `acceleration`
- 需要 Hermite 插值速度曲线
- 脚本参数最多，作者负担最大，暂不建议

---

## 6. 脚本 API 设计草案（待定）

只加一个字段 `easing`，避免参数膨胀：

```json
"easing": "ease_in_out"
```

或高级：

```json
"easing": {
  "type": "bezier",
  "x1": 0.1,
  "y1": 0.9,
  "x2": 0.9,
  "y2": 0.1
}
```

粒度候选：

- **A. clip 级**：整段一种缓动，最简单
- **B. 关键帧级**：每个关键帧指定“到下一个关键帧”的缓动，最灵活
- **C. clip 默认 + 关键帧覆盖**（当前倾向）：平时不用写，特殊时候才写

---

## 7. 与路径形状的关系

- 缓动和路径形状解耦：`ease(t)` 只改 `s`，不碰 `P(u)`
- 未来加 Catmull-Rom 路径时，缓动直接复用同一套 `ease(t) → LUT → P(u)`
- 预设生成时：
  - 预设内部决定路径形状（直线/贝塞尔/未来 Catmull-Rom）
  - 速度由弧长/时长自动决定
  - 是否暴露缓动参数给作者，待定

## 10. 结论（当前倾向，未定稿）

1. 运动模型保持唯一：路程 ÷ 时间 = 速度
2. 缓动 = 时间重映射，不是新模型
3. 脚本只加一个 `easing` 字段
4. 先支持 `linear` / `ease_in` / `ease_out` / `ease_in_out`
5. 高级怪形状用 2D 贝塞尔对象，后续再定是否做 UI
6. 不排入 0.3.5，长期讨论
